## Prerequisites

- Sentry Account: Sign up here if you don't have one.
- Auth Token: Generate a token with the project:releases and org:read scopes from your Sentry dashboard.
- Install the plugin:

```package-install
npm install @hot-updater/sentry-plugin --save-dev
```

## Step 1: Configure Sentry

<Tabs items={['Bare React Native', 'Expo', 'Re.Pack']}>
  <Tab value="Bare React Native">
    

    Configure Metro following the [Sentry documentation](https://docs.sentry.io/platforms/react-native/manual-setup/metro/). Keep your existing Metro customizations and apply `withSentryConfig` last.

    ```js title="metro.config.js"
    const { getDefaultConfig } = require("@react-native/metro-config");
    const { withSentryConfig } = require("@sentry/react-native/metro"); // [!code ++]

    const config = getDefaultConfig(__dirname);
    module.exports = withSentryConfig(config); // [!code ++]
    ```
  </Tab>
  <Tab value="Expo">

    Use Sentry's Expo configuration so Expo's Metro defaults are preserved:

    ```js title="metro.config.js"
    const { getSentryExpoConfig } = require("@sentry/react-native/metro");

    const config = getSentryExpoConfig(__dirname);
    module.exports = config;
    ```

    Preserve your existing customizations. For a custom transformer, use the
    `getDefaultConfig` callback described in the
    [Sentry Metro guide](https://docs.sentry.io/platforms/react-native/manual-setup/metro/#add-a-custom-babel-transformer).
  </Tab>
  <Tab value="Re.Pack">

  Configure Re.Pack:

```package-install
npm install repack-plugin-sentry --save-dev
```

```js title="rspack.config.mjs"
import { SentryDebugIdPlugin } from "repack-plugin-sentry"; // [!code ++]

export default {
  // ... your other config
  plugins: [
    // ... your other plugins
    new SentryDebugIdPlugin(), // [!code ++]
  ],
};
```
  </Tab>
</Tabs>



## Step 2: Wrap your build adapter

Use `withSentry()` to wrap any compatible build adapter such as bare.

<Tabs items={['Bare', 'Expo', 'Rock']}>
  <Tab value="Bare">

```ts title="hot-updater.config.ts (excerpt)"
import { existsSync } from "node:fs";
import { bare } from "@hot-updater/bare";
import { withSentry } from "@hot-updater/sentry-plugin"; // [!code ++]
import { defineConfig } from "hot-updater";

if (existsSync(".env.hotupdater")) {
  process.loadEnvFile(".env.hotupdater");
}

export default defineConfig({
  build: withSentry( // [!code ++]
    bare({
      enableHermes: false,
      // Required for sourcemap upload
      sourcemap: true, // [!code ++]
    }),
    { // [!code ++]
      // Your Sentry organization slug
      org: "your-org-slug", // [!code ++]
      // Your Sentry project slug
      project: "your-project", // [!code ++]
      authToken: process.env.SENTRY_AUTH_TOKEN!, // [!code ++]
    }, // [!code ++]
  ), // [!code ++]
  // ... storage, database, plugins, and updateStrategy
});
```
</Tab>

With a [managed provider](/docs/get-started/choose-provider#set-up-a-provider-preset),
`hot-updater init` keeps this wrapped build when it updates the storage,
database, and plugins in `hot-updater.config.ts`.

<Callout title="Automatic Upload">
`withSentry()` uploads one bundle and its sourcemap during `hot-updater deploy`,
using the Hermes sourcemap when available. Additional bundles or chunk maps,
such as split Re.Pack output, require separate uploads through Sentry's tooling.
</Callout>

## Step 3: Deploy

Deploy the update to build the bundle and upload its sourcemaps to Sentry.

```package-install
npx hot-updater deploy -i
```

## Verify symbolication

Install a release build, deploy a small JavaScript change with sourcemaps
enabled, and trigger a controlled test error from the updated code. In your
monitoring dashboard, confirm the stack points to the original source file
and line in that update. A successful upload alone does not prove the app and
uploaded map use the same identity.
