## What a storage plugin does

A storage plugin keeps the files that `hot-updater deploy` uploads, such as
manifests, assets, archives, and patches, and resolves the URLs devices
download them from. It is one object: a `name`, the URI `protocol` it owns,
and the operations its consumers call. The CLI, the Console, and the server
use the same object, so the operations take plain inputs and Web streams. The
factory that creates the plugin captures SDK clients, bindings, and
credentials.

Each consumer checks the operations it needs, and fails with
`Storage plugin "<name>" does not implement <operation>.` when one is missing:

| Consumer                        | Operations                                             |
| ------------------------------- | ------------------------------------------------------ |
| `hot-updater deploy`            | `put`, `get`, `exists`, `delete`                       |
| `hot-updater patch`             | `get`, `put`, `delete`                                 |
| `hot-updater bundle promote`    | None; it reuses the stored artifact                    |
| `hot-updater storage prune`     | `get`, `listObjects`, and `deleteObjects` with `--yes` |
| Console                         | `get`, `put`, `exists`, `delete`                       |
| `createHotUpdater({ storage })` | `get`, `getDownloadUrl`                                |

A plugin for general use implements `put`, `get`, `getDownloadUrl`, `exists`,
and `delete`. `listObjects` and `deleteObjects` add
[storage cleanup](#support-storage-cleanup).

## Install

```package-install
npm install @hot-updater/plugin-core
```

`@hot-updater/plugin-core` exports `createStoragePlugin`, the storage types,
and the URI and download helpers used below. A plugin you publish lists it in
`peerDependencies`; see [Test and publish a plugin](/docs/plugins/publish).

## Write the plugin

This plugin stores objects through a `BucketClient`, the calls it needs from
your provider's SDK. Replace it with your SDK's client:

```ts title="src/myStorage.ts"
import {
  createStorageDownloadUrl,
  createStorageKeyBuilder,
  createStoragePlugin,
  createStorageUri,
  parseStorageUri,
} from "@hot-updater/plugin-core";

/** The calls the plugin makes to your provider's SDK. */
export interface BucketClient {
  upload(
    key: string,
    body: ReadableStream<Uint8Array>,
    options: { contentType: string; contentLength?: number },
  ): Promise<void>;
  download(key: string): Promise<{
    body: ReadableStream<Uint8Array>;
    contentType: string;
    size: number;
  } | null>;
  exists(key: string): Promise<boolean>;
  remove(key: string): Promise<void>;
}

export interface MyStorageOptions {
  client: BucketClient;
  bucket: string;
  /** A folder inside the bucket for Hot Updater's objects. */
  basePath?: string;
  /** Signs download URLs that the Hot Updater server answers itself. */
  downloadUrlSigningKey?: string;
}

const PROTOCOL = "my-storage";

export const myStorage = ({
  client,
  bucket,
  basePath,
  downloadUrlSigningKey,
}: MyStorageOptions) => {
  const objectKey = createStorageKeyBuilder(basePath);
  const keyOf = (storageUri: string) => {
    const parsed = parseStorageUri(storageUri, PROTOCOL);
    if (parsed.bucket !== bucket) {
      throw new Error(`Expected bucket "${bucket}", got "${parsed.bucket}".`);
    }
    return parsed.key;
  };

  return createStoragePlugin({
    name: "myStorage",
    protocol: PROTOCOL,

    async put({ key, body, contentLength, contentType }) {
      const storedKey = objectKey(key);
      await client.upload(storedKey, body, { contentType, contentLength });
      return {
        storageUri: createStorageUri({
          protocol: PROTOCOL,
          bucket,
          key: storedKey,
        }),
      };
    },

    async get({ storageUri }) {
      const object = await client.download(keyOf(storageUri));
      if (object === null) return { response: null };
      return {
        response: new Response(object.body, {
          headers: {
            "content-type": object.contentType,
            "content-length": String(object.size),
          },
        }),
      };
    },

    async exists({ storageUri }) {
      return { exists: await client.exists(keyOf(storageUri)) };
    },

    async delete({ storageUri }) {
      await client.remove(keyOf(storageUri));
      return { deleted: true };
    },

    ...(downloadUrlSigningKey === undefined
      ? {}
      : { getDownloadUrl: createStorageDownloadUrl(downloadUrlSigningKey) }),
  });
};
```

- `protocol` is the scheme of every URI the plugin stores, such as `s3` or
  `r2`. The database keeps those URIs, so the protocol cannot change once
  Bundles use it, and a server registers one plugin per protocol. Choose one
  that names your provider.
- `put` receives a key relative to the plugin's base path, such as
  `bundles/<bundle-id>/manifest.json` or `assets/sha256/ab/<hash>.png`, and a
  one-shot `ReadableStream`. Consume or cancel the stream before the promise
  settles. `contentLength` is set when the consumer knows the size.
- `put` returns the URI of that key below the base path, from
  `createStorageUri`. Deploy and the server derive the URIs of related objects
  from it, such as the archive next to a manifest and the shared `assets/`
  folder, and pass them to `get` and `exists`, so a plugin must store every
  key at the same place relative to its base path.
- `get` returns a `Response` whose body streams the object, or `null` when it
  does not exist. Consumers pipe the body without buffering it.
- `exists` tells deploy whether it can reuse an object. Return `true` only
  when a device could download it.
- `delete` removes exactly one object and returns `{ deleted: true }`, also
  when the object is already gone, so a retried cleanup succeeds.
- `createStorageKeyBuilder(basePath)` joins the base path and a key, and
  rejects `.`, `..`, and `\` segments.
- `parseStorageUri(uri, protocol)` checks the scheme and decodes the key.
  Check the bucket too, so a plugin never reads another bucket's URI.

Each operation receives one input object and returns one result object, so the
contract can add fields without changing positions.

## Serve downloads

`getDownloadUrl({ storageUri })` returns the URL a device downloads an object
from. The server calls it for every artifact in an update response. Return one
of these:

- **A URL your provider serves.** A public or CDN URL, or one your provider
  signs, such as an S3 presigned URL. It must be `http` or `https`.
- **A download path the server answers.** `createStorageDownloadUrl(signingKey)`
  returns a `getDownloadUrl` that signs the URI with HMAC-SHA256 and returns
  `/storage/<uri>/<signature>`. The server's client handler checks the
  signature and streams the object through `get`. Use it for a private bucket
  your provider cannot sign URLs for. The app resolves the path against its
  `baseURL`. The signature does not expire and the route skips client
  authentication: like a public URL, it only keeps other objects' paths from
  being guessed.

Only the server needs `getDownloadUrl`, and with it the signing key. Keep the
key in the server's environment, and use the same key on every server instance.

## Register the plugin

The CLI takes one storage plugin as `storage`. This excerpt shows only that
field of a complete `hot-updater.config.ts`:

```ts title="hot-updater.config.ts (storage excerpt)"
import { createBucketClient } from "./src/bucketClient";
import { myStorage } from "./src/myStorage";

const storage = myStorage({
  client: createBucketClient(process.env.BUCKET_TOKEN!),
  bucket: "bundles",
  basePath: "ota",
});
```

Assign this value to `storage` next to the configuration's `build`,
`database`, and `updateStrategy`.

The server takes a list, so it can read Bundles that different plugins stored.
Configure the same bucket and base path as the CLI:

```ts title="src/hotUpdater.ts (excerpt)"
export const hotUpdater = createHotUpdater({
  database, // Your provider's database.
  storage: [
    myStorage({
      client: createBucketClient(process.env.BUCKET_TOKEN!),
      bucket: "bundles",
      basePath: "ota",
      downloadUrlSigningKey: process.env.STORAGE_DOWNLOAD_URL_SIGNING_KEY!,
    }),
  ],
  plugins: [insights(), apiKeys()],
});
```

`createHotUpdater` rejects a plugin without `get` or `getDownloadUrl`, and two
plugins with one protocol. To answer a URI, Hot Updater:

1. uses the registered plugin whose `protocol` matches the URI's scheme;
2. uses an `http` or `https` URI directly when no plugin owns its scheme;
3. otherwise reports the scheme as unsupported.

A plugin that owns `http` or `https` takes precedence, so a provider can apply
authorization to those URIs as well.

## Provide runtime-specific entries

A provider can create the same plugin in different ways for different
runtimes, and export each from its own entry. `@hot-updater/cloudflare`
exports `r2Storage` over S3-compatible credentials for the CLI, and
`@hot-updater/cloudflare/worker` exports an `r2Storage` over a Worker's R2
binding. Both use the `r2` protocol and the same key layout, so each reads
the URIs the other stores:

```json title="package.json (excerpt)"
{
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
    "./worker": {
      "types": "./dist/worker.d.ts",
      "import": "./dist/worker.js"
    }
  }
}
```

## Support storage cleanup

[`hot-updater storage prune`](/docs/guides/storage-cleanup) removes objects
that no Bundle references. It needs two more operations:

- `listObjects(prefix?)` lists the objects below an optional prefix, relative
  to the base path. Each `StorageObject` has `key`, `storageUri`, `size`, and
  an optional `lastModifiedAt`. Pruning keeps objects without a modification
  time.
- `deleteObjects(keys)` deletes exactly the keys it receives, relative to the
  base path.

Without them, `storage prune` reports that the plugin does not support it.
Prefix or bucket deletion is outside the contract.

## Test the plugin

Test the plugin against a fake of your SDK's client, and against a real bucket
before you publish it. This Vitest spec keeps objects in memory:

```ts title="src/myStorage.spec.ts"
import { describe, expect, it } from "vitest";

import { type BucketClient, myStorage } from "./myStorage";

/** Keeps objects in memory in place of the provider. */
const memoryBucket = (): BucketClient => {
  const objects = new Map<
    string,
    { bytes: ArrayBuffer; contentType: string }
  >();
  return {
    async upload(key, body, { contentType }) {
      const bytes = await new Response(body).arrayBuffer();
      objects.set(key, { bytes, contentType });
    },
    async download(key) {
      const object = objects.get(key);
      if (object === undefined) return null;
      return {
        body: new Blob([object.bytes]).stream(),
        contentType: object.contentType,
        size: object.bytes.byteLength,
      };
    },
    async exists(key) {
      return objects.has(key);
    },
    async remove(key) {
      objects.delete(key);
    },
  };
};

describe("myStorage", () => {
  const storage = myStorage({
    client: memoryBucket(),
    bucket: "bundles",
    basePath: "ota",
    downloadUrlSigningKey: "test-signing-key",
  });

  it("stores an object under a canonical URI and reads it back", async () => {
    const { storageUri } = await storage.put({
      key: "releases/1.0.0/bundle ios#1.zip",
      body: new Blob(["hello"]).stream(),
      contentLength: 5,
      contentType: "application/zip",
    });
    expect(storageUri).toBe(
      "my-storage://bundles/ota/releases/1.0.0/bundle%20ios%231.zip",
    );
    await expect(storage.exists({ storageUri })).resolves.toEqual({
      exists: true,
    });
    const { response } = await storage.get({ storageUri });
    await expect(response?.text()).resolves.toBe("hello");
    const { url } = await storage.getDownloadUrl!({ storageUri });
    expect(url.startsWith("/storage/")).toBe(true);
  });

  it("deletes exactly one object, and deleting it again succeeds", async () => {
    const { storageUri } = await storage.put({
      key: "a.txt",
      body: new Blob(["a"]).stream(),
      contentType: "text/plain",
    });
    await expect(storage.delete({ storageUri })).resolves.toEqual({
      deleted: true,
    });
    await expect(storage.delete({ storageUri })).resolves.toEqual({
      deleted: true,
    });
    await expect(storage.exists({ storageUri })).resolves.toEqual({
      exists: false,
    });
    await expect(storage.get({ storageUri })).resolves.toEqual({
      response: null,
    });
  });

  it("refuses a URI of another bucket", async () => {
    await expect(
      storage.get({ storageUri: "my-storage://other/ota/a.txt" }),
    ).rejects.toThrow('Expected bucket "bundles"');
  });
});
```

Then deploy through it: point a test app's `hot-updater.config.ts` at the
plugin, run `hot-updater deploy`, and [test an OTA update](/docs/get-started/test-ota)
against a server that registers the same plugin.

## Storage contract

```ts
interface StoragePlugin {
  readonly name: string;
  readonly protocol: string;

  readonly put?: (input: {
    readonly key: string;
    readonly body: ReadableStream<Uint8Array>;
    readonly contentLength?: number;
    readonly contentType: string;
  }) => Promise<{ readonly storageUri: string }>;

  readonly get?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly response: Response | null }>;

  readonly getDownloadUrl?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly url: string }>;

  readonly exists?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly exists: boolean }>;

  readonly delete?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly deleted: true }>;

  readonly listObjects?: (prefix?: string) => Promise<StorageObject[]>;
  readonly deleteObjects?: (keys: readonly string[]) => Promise<void>;
}
```

`createStoragePlugin` returns the object it receives, typed with the
operations it has. `StoragePluginWith<"get" | "put">` names a plugin that has
those operations.

### Storage URI format

A stored location is a hierarchical URI:

```text
protocol://bucket/encoded/slash/key
```

The bucket is the URI host. Each key segment is encoded on its own, so `/`
separates segments while spaces, Unicode, `#`, `?`, and `%` round-trip. Create
and parse URIs with the helpers instead of joining strings:

```ts
const storageUri = createStorageUri({
  protocol: "my-storage",
  bucket: "bundles",
  key: "releases/1.0.0/bundle ios#1.zip",
});
// my-storage://bundles/releases/1.0.0/bundle%20ios%231.zip

const parsed = parseStorageUri(storageUri, "my-storage");
// { protocol: "my-storage", bucket: "bundles",
//   key: "releases/1.0.0/bundle ios#1.zip" }
```

A protocol starts with a lowercase letter and uses lowercase letters, digits,
`+`, `.`, and `-`. Empty, `.`, and `..` key segments, query strings, and
fragments are not valid locations; the helpers reject them instead of
normalizing to another object.

### File-system consumers

The contract carries Web streams and responses, not paths. The CLI opens a
local file as a stream, passes its size as `contentLength`, and hands the
stream to `put` without reading the file into memory. Keep file-system
operations out of a plugin.
