## Installation

```package-install
npm install @hot-updater/cloudflare
```

## Setup

Set up the backend with an [AI agent or the interactive
CLI](/docs/managed/cloudflare#step-2-configure-cloudflare), then use the
configuration below.

Create R2 S3-compatible credentials from the Cloudflare R2 API token page or
follow the [Cloudflare R2 API token guide](https://developers.cloudflare.com/r2/api/tokens/).

## Configuration

```typescript
interface R2S3StorageConfig {
  accountId: string;
  bucketName: string;
  credentials: {
    accessKeyId: string;
    secretAccessKey: string;
  };
  basePath?: string;
  downloadUrlSigningKey?: string;
}
```

`r2Storage` requires S3-compatible credentials. The Wrangler object-storage
fallback is removed.

## Usage

```typescript
import { r2Storage } from "@hot-updater/cloudflare";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID,
    bucketName: "my-r2-bucket",
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
    },
  }),
  // ... other config
});
```

## Runtime Usage

The root `r2Storage` plugin implements upload, read, existence-check, and
exact-delete operations. When the same plugin is passed to a self-hosted
`createHotUpdater` server, also provide `downloadUrlSigningKey`; it enables
the signed download location required by the server while `get` reads the
stored object.

## Protocol

`r2://bucket/encoded/key`

For example, `r2://updates/releases/1.0.0/bundle%20ios.zip` is stored in the
`storageUri` field. Keys retain their slash hierarchy and encode each segment.
