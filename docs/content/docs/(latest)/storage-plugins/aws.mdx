## Installation

```package-install
npm install @hot-updater/aws --save-dev
```

## Setup

For a complete provider deployment, follow the [AWS setup](/docs/managed/aws#step-2-configure-aws).
For an existing bucket or a custom server, use the storage configuration below;
you do not need to provision the provider's database and server to use this plugin.

## Configuration

```typescript
interface S3StorageConfig {
  region: string; // AWS region or 'auto' for R2
  bucketName: string; // S3 bucket name
  basePath?: string; // Optional base path within bucket
  endpoint?: string; // Custom endpoint for S3-compatible services
  credentials?: {
    accessKeyId: string;
    secretAccessKey: string;
  };
  downloadUrlSigningKey?: string;
  getDownloadUrl?: (input: { storageUri: string }) => Promise<{ url: string }>;
}
```

If `credentials` is omitted, the AWS SDK default credential chain is used. This
lets you rely on local AWS CLI sessions, `AWS_PROFILE`, shared config files, or
other standard AWS credential sources.

## Usage

### AWS S3

```typescript title="hot-updater.config.ts"
import { s3Storage } from "@hot-updater/aws"; // [!code ++]
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: s3Storage({ // [!code ++]
    region: "us-east-1", // [!code ++]
    credentials: { // [!code ++]
      accessKeyId: process.env.AWS_ACCESS_KEY_ID, // [!code ++]
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY, // [!code ++]
    }, // [!code ++]
    bucketName: "my-hot-updater-bucket", // [!code ++]
  }), // [!code ++]
  // ... other config
});
```

### Cloudflare R2

```typescript title="hot-updater.config.ts"
export default defineConfig({
  storage: s3Storage({
    region: "auto", // [!code ++]
    endpoint: `https://${process.env.CLOUDFLARE_ACCOUNT_ID}.r2.cloudflarestorage.com`, // [!code ++]
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID, // [!code ++]
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY, // [!code ++]
    },
    bucketName: "my-r2-bucket", // [!code ++]
  }),
  // ... other config
});
```

## Protocol

`s3://bucket/encoded/key`

For example, `s3://my-bucket/releases/1.0.0/bundle%20ios.zip` is stored in the
`storageUri` field. Keys retain their slash hierarchy and encode each segment.

## Capabilities

`s3Storage` implements streaming upload, streaming Web-response reads,
existence checks, and exact deletion. Download URL generation requires either
`downloadUrlSigningKey` or a `getDownloadUrl` implementation; the plugin does
not implicitly generate S3 presigned URLs. CLI-only storage does not need this
capability. For a self-hosted server, set `downloadUrlSigningKey` so the plugin
returns a signed URL handled by the same server.

For CloudFront delivery, pass `cloudFrontDownloadUrl(...)` as `getDownloadUrl`:

```typescript title="hot-updater.config.ts"
import { cloudFrontDownloadUrl, s3Storage } from "@hot-updater/aws"; // [!code ++]

const storage = s3Storage({
  region: process.env.AWS_REGION!,
  bucketName: process.env.AWS_S3_BUNDLES_BUCKET!,
  getDownloadUrl: cloudFrontDownloadUrl({ // [!code ++]
    publicBaseUrl: "https://updates.example.com", // [!code ++]
    keyPairId: process.env.CLOUDFRONT_KEY_PAIR_ID!, // [!code ++]
    ssmRegion: process.env.AWS_REGION!, // [!code ++]
    ssmParameterName: process.env.CLOUDFRONT_PRIVATE_KEY_PARAMETER!, // [!code ++]
  }), // [!code ++]
});
```

Use the CloudFront distribution's artifact domain and public key ID. The SSM
parameter stores JSON containing `privateKey`; grant the server role permission
to read and decrypt it. These settings and the private key remain on the
server. If your secret store is elsewhere, provide
`getPrivateKey: async () => privateKeyPem` instead of the two SSM options.
Managed AWS initialization configures its CloudFront delivery path for you.

## Maintenance

`s3Storage` provides the object listing and exact deletion capabilities used by
`hot-updater storage prune`. Follow the [Storage Cleanup](/docs/guides/storage-cleanup)
guide to remove unreferenced bundle objects and shared assets safely.

Use a separate `basePath` for every database or environment that shares a
bucket. Pruning assumes that the configured database owns every object below
its storage prefix.

## Custom Server Usage

Use `s3Storage` with `createHotUpdater` for self-hosted servers:

```typescript title="src/hotUpdater.ts"
import { s3Storage } from "@hot-updater/aws"; // [!code ++]
import { createHotUpdater } from "@hot-updater/server";

const hotUpdater = createHotUpdater({
  database,
  clientAccess: { type: "api-key" },
  storage: [ // [!code ++]
    s3Storage({ // [!code ++]
      region: process.env.AWS_REGION!, // [!code ++]
      credentials: { // [!code ++]
        accessKeyId: process.env.AWS_ACCESS_KEY_ID!, // [!code ++]
        secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY!, // [!code ++]
      }, // [!code ++]
      bucketName: process.env.AWS_S3_BUNDLES_BUCKET!, // [!code ++]
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!, // [!code ++]
    }), // [!code ++]
  ], // [!code ++]
  // ... other options
});
```
