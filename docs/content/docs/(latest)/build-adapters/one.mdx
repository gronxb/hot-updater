[One](https://onestack.dev) builds its native bundle through
`react-native bundle`, which One's `react-native.config.cjs` routes to its own
bundler, and generates `ios/` and `android/` with `one prebuild`. The One
adapter bundles the same way, and `hotUpdaterPatches` sets up the projects
prebuild generates.

## Installation

The One adapter needs One 2.15 or later.

```package-install
npm install @hot-updater/one --save-dev
```

## Configuration

```typescript
interface OneAdapterConfig {
  outDir?: string; // Output directory (default: "node_modules/.hot-updater/build")
  sourcemap?: boolean; // Generate sourcemaps (default: false)
  resetCache?: boolean; // Reset One's transform cache before bundling (default: true)
}
```

The bundle is always compiled with Hermes, which One apps use. The default
`outDir` stays out of `dist/`, where One writes its web build and files of its
native bundle step.

## Usage

```typescript title="hot-updater.config.ts"
import { one } from "@hot-updater/one"; // [!code ++]
import { defineConfig } from "hot-updater";

export default defineConfig({
  build: one(), // [!code ++]
  // ... other config
});
```

## One configuration

`one prebuild` deletes and regenerates `ios/` and `android/`, so it applies Hot
Updater's native changes itself, through `native.app.patches`. Add
`hotUpdaterPatches` in `vite.config.ts`:

```ts title="vite.config.ts"
import { hotUpdaterPatches } from "@hot-updater/one/patches"; // [!code ++]
import { one } from "one/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    one({
      native: {
        app: {
          name: "MyApp",
          ios: { bundleId: "com.example.myapp" },
          android: { applicationId: "com.example.myapp" },
          patches: hotUpdaterPatches({ channel: "production" }), // [!code ++]
        },
      },
    }),
  ],
});
```

The patches make `AppDelegate.swift` and `MainApplication.kt` load Hot
Updater's bundle, and write the channel and the signing public key into
`Info.plist` and `AndroidManifest.xml`. Keep your own patches beside them with
`patches: [...hotUpdaterPatches(), ...yourPatches]`.

`hotUpdaterPatches` accepts these options:

| Option          | Purpose                                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| `channel`       | Native update channel. Defaults to `production`.                                                                |
| `publicKeyPath` | Optional path to the signing public key, relative to the project root. Required when bundle signing is enabled. |

Run prebuild to apply the changes:

```package-install
npx one prebuild
```

<Callout type="warn">
  Leave `native.app.updates` unset. It replaces the bundle URL with One's own
  update launcher, and the Hot Updater patch then stops the prebuild.
</Callout>

## Initialize the client

`HotUpdater.init` runs on iOS and Android only. Put it in a `.native.ts` module
and export a stub from the web file of the same name:

```ts title="features/hotUpdater/hotUpdater.native.ts"
import { HotUpdater } from "@hot-updater/react-native";

export const hotUpdater = HotUpdater.init({
  baseURL: "https://your-update-server-url",
});
```

```ts title="features/hotUpdater/hotUpdater.ts"
export const hotUpdater = null;
```

## Key features

- Bundles with `react-native bundle`, through One's bundler
- Always compiles with Hermes
- Runs `one prebuild` before native builds
- Reads `hotUpdaterPatches`' options from `vite.config.ts` for signing and
  fingerprints
- Counts the app's own Swift packages and Kotlin files, which One compiles
  into the app, in the [fingerprint](/docs/guides/update-strategies/fingerprint)
