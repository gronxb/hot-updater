## Overview

A preview build is a Release native build that testers install once and
point at any pull request's bundle without rebuilding:

1. Build a native app with a shared default channel, such as `preview`, and
   register it.
2. Deploy each pull request's bundle to its own channel, such as `pr-12`.
3. In the Console's **Preview** page, a tester installs the build, by QR code
   on Android or with `xcrun simctl` on the iOS Simulator, then scans the
   pull request's channel link.
4. The app opens the link with
   [`hotUpdater.openChannelLink()`](/docs/react-native-api/openChannelLink),
   which switches to the channel with
   [runtime channel switching](/docs/guides/runtime-channel-switch).
5. When the pull request closes, `hot-updater channel delete pr-12` deletes
   its channel and bundles.

Only builds whose default channel you list open channel links. A production
build, with another default channel, ignores them, even when it runs the same
JavaScript.

## Build and register a preview build

Set the shared default channel, then build and register a Release build:

```package-install
npx hot-updater channel set preview
```

```package-install
npx hot-updater build:android --scheme release --register
```

Register the iOS build for the Simulator with a `nativeBuild.ios` scheme that
sets `simulator: true`. See [Native Build](/docs/guides/native-build#register-a-build)
for the schemes and what registering uploads.

Every pull request reuses this build while its native code doesn't change.
Keep pull request channels for bundles only: a channel a native build embeds
as its default channel can't be deleted.

## Open channel links in the app

A channel link is `<prefix>hot-updater/channel/<channel>`. The prefix is your
app's URL scheme, such as `myapp://`, or a universal link's prefix, such as
`https://example.com/`. Register the scheme in the native project as the
[React Native linking guide](https://reactnative.dev/docs/linking) describes,
then pass every URL the app opens to `openChannelLink`:

```tsx title="src/channelLinks.ts"
import { Linking } from "react-native";

import { hotUpdater } from "./hotUpdater";

const openLink = async (url: string | null) => {
  if (url === null) return;
  const result = await hotUpdater.openChannelLink(url, {
    updateStrategy: "fingerprint",
    // Builds whose default channel is "preview" open channel links.
    defaultChannels: ["preview"],
  });
  if (result.status === "NOT_CHANNEL_LINK") {
    // Route the URL as the app routes its other links.
  }
};

void Linking.getInitialURL().then(openLink);
Linking.addEventListener("url", ({ url }) => void openLink(url));
```

`openChannelLink` checks the channel with `checkForUpdate({ channel })`,
installs its bundle with `updateBundle()`, and reloads the app. When the app
already runs another pull request's channel, it calls `resetChannel()` first.
A link to the build's default channel leaves the pull request's channel.

<Callout type="info">
  `checkForUpdate` returns no update in a Debug build, which loads JavaScript
  from Metro, so test channel links in a Release build.
</Callout>

## Show channel links in the Console

Set `console.channelLinkPrefix` to the prefix the app opens:

```ts title="hot-updater.config.ts"
import { defineConfig } from "hot-updater";

export default defineConfig({
  console: {
    channelLinkPrefix: "myapp://", // [!code ++]
  },
  build: ...,
  storage: ...,
  database: ...,
});
```

A [deployed Console](/docs/guides/console-deployment) takes the same option
under `console` in its configuration.

The Console's **Preview** page then has two cards:

- **Native builds** lists the registered builds, newest first. **Install**
  opens a build: an APK shows a QR code that downloads it, a Simulator app
  shows its `xcrun simctl install` command, and every build has a download.
  AAB and IPA builds install through Google Play and your iOS distribution.
- **Channel link** shows the QR code of the channel you choose, a link that
  opens it on the device that shows the page, and the `adb` and
  `xcrun simctl openurl` commands that open it on an emulator or simulator.

`/preview?build=<build id>` opens a build's install dialog, and
`/preview?channel=<channel>` shows a channel's link, so a pull request
comment can link to either. A bundle's detail sheet links to its channel's
link too.

A download goes through `/api/native-builds/<build id>/download`, which
redirects to the storage's download URL each time, so the Console link never
expires. The APK QR code holds the storage's download URL itself, so a phone
downloads it without signing in to the Console; the open dialog reads a new
URL every five minutes, before one expires. A storage with no download URL
serves the artifact through the Console, and the QR code holds the Console's
download link.

## Deploy a pull request's bundle

Deploy each pull request to its own channel:

```package-install
npx hot-updater deploy -p android -c pr-12
```

## Clean up a closed pull request

```package-install
npx hot-updater channel delete pr-12 --yes
```

The command disables and deletes each bundle in the channel, on both
platforms, then deletes the channel. A bundle also promoted to another
channel keeps its files there. The deleted bundles' files stay in storage
until [`hot-updater storage prune`](/docs/guides/storage-cleanup) deletes
them.

A missing channel deletes nothing, and the command succeeds, so a cleanup job
can run again. When a native build embeds the channel as its default channel,
the command deletes the bundles, keeps the channel and its native builds, and
exits with status 1.

Add `--json` to print the result, with the IDs of the deleted bundles.
