## Overview

Configure Hot Updater at module scope, then let your app decide when to check,
download and restart. You can check after login, when the app returns to the
foreground, or from a button.

The [app setup example](/docs/get-started/app-setup) checks and applies an update
with one button. Use this guide to download in the background, show progress or
wait for the user to accept a restart.

## Initialize and prepare updates

Import this module from your app entry point. Call `HotUpdater.init` at the top
level, outside React components and effects. The SDK handles native startup
verification internally.

```ts title="updates.ts"
import { HotUpdater } from "@hot-updater/react-native";

function reportUpdateError(error: unknown) {
  console.error("Hot Updater:", error);
}

HotUpdater.init({
  baseURL: "https://your-update-server-url",
  requestHeaders: {
    "x-api-key": "<your-client-api-key>",
  },
  onError: reportUpdateError,
});

export async function runUpdateFlow() {
  try {
    const update = await HotUpdater.checkForUpdate({
      updateStrategy: "appVersion",
    });

    if (!update) {
      return;
    }

    const downloaded = await update.updateBundle();

    if (!downloaded) {
      throw new Error("Could not prepare the update");
    }

    if (update.shouldForceUpdate) {
      await HotUpdater.reload();
    }
  } catch (error) {
    reportUpdateError(error);
  }
}
```

Use the URL and client key from [App setup](/docs/get-started/app-setup). Calling
`init` configures the client; call `runUpdateFlow()` when your app should check.
It downloads a selected update and restarts immediately for required updates.
Other downloaded updates take effect on the next app restart.

The returned `update.updateBundle()` helper resolves the artifact and preserves
the selected transition, including rollback. Use this helper for update checks;
the result's `fileUrl` and `fileHash` fields are `null`.

## Restart on user confirmation

To let users finish their work first, replace the automatic reload with your
app's restart prompt. Show the prompt only after `update.updateBundle()` returns
`true`. Its confirmation button can call this handler in the same module:

```ts
async function restartToApply() {
  try {
    await HotUpdater.reload();
  } catch (error) {
    reportUpdateError(error);
  }
}
```

`shouldForceUpdate` tells your app that the selected update is required. A
custom flow owns the restart decision, so make sure its UI enforces your
required-update policy. See [`reload`](/docs/react-native-api/reload) for native
and custom reload behavior.

## Show update progress

Use the SDK store to show download progress without maintaining a second copy
of it in component state. Render this component while a download is running:

```tsx title="UpdateProgress.tsx"
import { useHotUpdaterStore } from "@hot-updater/react-native";
import { Text } from "react-native";

export function UpdateProgress() {
  const progress = useHotUpdaterStore((state) => state.progress);

  return <Text>Downloading: {Math.round(progress * 100)}%</Text>;
}
```

See [`useHotUpdaterStore`](/docs/react-native-api/useHotUpdaterStore) for other
state fields, or [`addListener`](/docs/react-native-api/addListener) for event
listeners outside React.

## Handle errors

Use `init.onError` as the shared error reporter for lifecycle reporting and update
checks. Use `try/catch` for rejected operations, including downloads and restarts.
A download that returns `false` has not prepared the update; keep the current
app running and report the failure.

Accept `unknown` in a shared reporter because caught values are not guaranteed
to be `Error` objects. The reporter should log the failure or update your UI
without throwing it again.

A check can return `null` when there is no update, or after reporting a failure
to `onError`. Stop the flow in either case; `null` alone is not proof that the
app is up to date. A per-check `onError` is an optional
[override](/docs/react-native-api/checkForUpdate#parameters) when a particular
check needs different reporting.

## Choose a different channel

For a beta opt-in or channel picker, follow
[Runtime channel switching](/docs/guides/runtime-channel-switch). A switch is
persisted after the selected update is applied. Use `resetChannel()` to return
to the channel embedded in the native build.
