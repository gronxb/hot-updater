**The console provides the following features:**

- Release delivery-policy management
- Release disable and force-update controls
- Immutable Bundle artifact inspection
- Quick access to git history for updates

## Configuration (Optional)

Console configuration does not change Release policy or Bundle artifacts.

You can configure additional console settings in the `hot-updater.config.ts` file.

The `storage` and `database` plugins must be exist.

| Option           | Description                                              | Default |
| ---------------- | -------------------------------------------------------- | ------- |
| `console.gitUrl` | Enables commit shortcuts by linking to git commit hashes | -       |
| `console.port`   | Sets the console server port                             | `1422`  |

```ts title="hot-updater.config.ts"
import { defineConfig } from "hot-updater";

export default defineConfig({
  console: { // [!code hl]
    port: 3000, // [!code hl]
  }, // [!code hl]
  build: ...,
  storage: ...,
  database: ...,
});

```

## Usage

Execute the following command:

```package-install
npx hot-updater console
```

## Security model

The CLI Console binds to loopback and loads the configured database and storage
plugins on its server. With a direct database plugin, it does not call the Hot
Updater HTTP handlers at all.

When the configured database is `standaloneRepository`, point its `baseUrl` at
the exact admin root (for example, `https://example.com/hot-updater/admin`) and
put the admin bearer token in server-side `commonHeaders`. Never expose that
token to Console browser code or a React Native app.

A deployed Console has two independent boundaries: its Console auth adapter
authenticates browser users, while the framework middleware in front of
`handlers.admin` authenticates Console-to-server requests. The Console's own
`/api/*` routes belong to the Console application and are not the Hot Updater
admin API. The standalone repository does not currently proxy Insights or API
key models, so those Console views require a direct database
plugin.

Use the Release CLI for delivery-policy automation and CI scripts:

```package-install
npx hot-updater release list --platform ios
npx hot-updater release list --bundle-id <bundle-id>
npx hot-updater release show <release-id>
npx hot-updater release disable <release-id> -y
npx hot-updater release enable <release-id> -y
npx hot-updater release update <release-id> --force-update true -y
npx hot-updater release update <release-id> --rollout-cohort-count 500 -y
npx hot-updater release update <release-id> --target-cohorts qa,dogfood -y
```

Add `--json` to `release list`, `release show`, or `release update` when
another tool needs to read Release policy. Bundle commands remain available
for immutable artifact inspection and reference-safe deletion:

```package-install
npx hot-updater bundle list --platform ios
npx hot-updater bundle show <bundle-id>
```

After deleting bundle records, use the [Storage Cleanup](/docs/guides/storage-cleanup)
workflow to preview and reclaim bundle objects and shared assets that are no
longer referenced.

## Rollback

Disabling a Release removes it from delivery selection. Affected installations
move to the previous compatible enabled Release or to the app's built-in
Bundle when no compatible Release remains. The result can vary by app version,
fingerprint, and cohort, so verify the scope shown by the Console before
confirming.

## Force Update

Setting a Release's `shouldForceUpdate` policy to `true` tells eligible
installations to apply that Release immediately when it is selected. The flag
belongs to the Release, not to its Bundle artifact.

## Promote

Promotion creates a new Release in the target channel while reusing the source
Release's Bundle:

```package-install
npx hot-updater release promote <source-release-id> --target <channel>
```

No Storage object is uploaded or copied. The target Release has a new Release
ID and rollout seed, is enabled, starts at a 100% numeric rollout, and has no
target cohorts. The command previews those defaults before confirmation. A
`--action move` promotion also disables the source Release atomically.

## Git URL

You can set the git URL in the `hot-updater.config.ts` file.

```ts title="hot-updater.config.ts"
import { defineConfig } from "hot-updater";

export default defineConfig({
  console: {
    gitUrl: "<your-repo>", // e.g. https://github.com/gronxb/hot-updater // [!code hl]
  },
});
```

When you set the git URL, the commit hash will be clickable and redirect you to the corresponding commit in your repository.
