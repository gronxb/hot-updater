**The console provides the following features:**

- Bundle rollout and targeting management
- Bundle disable and force-update controls
- Advanced immutable artifact inspection
- Quick access to git history for updates

## Configuration (Optional)

Console configuration does not change bundle delivery settings or artifacts.

You can configure additional console settings in the `hot-updater.config.ts` file.

The `storage` and `database` plugins must be exist.

| Option           | Description                                              | Default |
| ---------------- | -------------------------------------------------------- | ------- |
| `console.gitUrl` | Enables commit shortcuts by linking to git commit hashes | -       |
| `console.port`   | Sets the console server port                             | `1422`  |

```ts title="hot-updater.config.ts"
import { defineConfig } from "hot-updater";

export default defineConfig({
  console: { // [!code hl]
    port: 3000, // [!code hl]
  }, // [!code hl]
  build: ...,
  storage: ...,
  database: ...,
});

```

## Usage

The Bundles list and its detail sheet show an **ID** that matches
[`HotUpdater.getBundleId()`](/docs/react-native-api/getBundleId) on the device.
Promoted updates have their own IDs even when they reuse the same files.

Execute the following command:

```package-install
npx hot-updater console
```

## Security model

The CLI Console binds to loopback and loads the configured database and storage
plugins on its server. With a direct database plugin, it does not call the Hot
Updater HTTP handlers at all.

When the configured database is `standaloneRepository`, point its `baseUrl` at
the exact admin root (for example, `https://example.com/hot-updater/admin`) and
put the admin bearer token in server-side `commonHeaders`. Never expose that
token to Console browser code or a React Native app.

A deployed Console has two independent boundaries: its Console auth adapter
authenticates browser users, while the framework middleware in front of
`handlers.admin` authenticates Console-to-server requests. The Console's own
`/api/*` routes belong to the Console application and are not the Hot Updater
admin API. The standalone repository does not currently proxy Insights or API
key models, so those Console views require a direct database
plugin.

Use the same Bundle commands as v0 for automation and CI scripts:

```package-install
npx hot-updater bundle list --platform ios
npx hot-updater bundle show <id>
npx hot-updater bundle disable <id> -y
npx hot-updater bundle enable <id> -y
npx hot-updater bundle update <id> --force-update true -y
npx hot-updater bundle update <id> --rollout-cohort-count 500 -y
npx hot-updater bundle update <id> --target-cohorts qa,dogfood -y
```

Add `--json` to `bundle list`, `bundle show`, or `bundle update` when
another tool needs raw internal row data. Its field names follow the v1 database
schema rather than the human-readable Bundle terminology.

### Advanced artifact diagnostics

Artifact operations use the **Artifact ID** from Advanced diagnostics. They are
kept outside the normal bundle workflow:

```package-install
npx hot-updater bundle artifact delete <artifact-id> --yes
```

The command refuses to delete an artifact while any bundle ID references it and
reports those IDs. After deleting unreferenced artifact records, use the
[Storage Cleanup](/docs/guides/storage-cleanup) workflow to preview and reclaim
stored objects and shared assets.

## Rollback

Disabling a bundle removes it from delivery selection. Affected installations
move to the previous compatible enabled bundle or to the app's built-in bundle
when no compatible bundle remains. The result can vary by app version,
fingerprint, and cohort, so verify the scope shown by the Console before
confirming.

## Force Update

Setting a bundle's `shouldForceUpdate` value to `true` tells eligible
installations to apply that bundle immediately when it is selected.

## Promote

Promotion creates a new bundle ID in the target channel while reusing the same
uploaded artifact:

```package-install
npx hot-updater bundle promote <source-id> --target <channel>
```

No Storage object is uploaded or copied. The promoted update has a new ID
and rollout seed, is enabled, starts at a 100% numeric rollout, and has no
target cohorts. The command previews those defaults before confirmation. A
`--action move` promotion also disables the source bundle atomically.

## Git URL

You can set the git URL in the `hot-updater.config.ts` file.

```ts title="hot-updater.config.ts"
import { defineConfig } from "hot-updater";

export default defineConfig({
  console: {
    gitUrl: "<your-repo>", // e.g. https://github.com/gronxb/hot-updater // [!code hl]
  },
});
```

When you set the git URL, the commit hash will be clickable and redirect you to the corresponding commit in your repository.
