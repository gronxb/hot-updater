## Attach the Skill

Agent skills are packaged capabilities that give AI coding agents structured
instructions for a production workflow. Attach the Hot Updater skill from its
GitHub location:

- [`skills/hot-updater/SKILL.md`](https://github.com/hot-updater/skills/blob/main/skills/hot-updater/SKILL.md)

You can also install it with `npx skills`:

```sh
npx skills add hot-updater/skills
```

## Ask With `$hot-updater`

After attaching the skill, ask your agent in natural language:

```txt
$hot-updater Set up infrastructure on Cloudflare for this project.
$hot-updater deploy using the current app version
$hot-updater deploy the current iOS app version to production
$hot-updater list iOS Bundles on the production channel
$hot-updater inspect a Bundle, then disable that exact Bundle
$hot-updater show which Bundles reference this artifact
$hot-updater run doctor with server URL https://updates.example.com
$hot-updater fix local doctor issues that do not require server credentials
```

The skill uses the project's installed CLI help to discover supported commands.
For infrastructure setup, the agent asks for missing project details or access,
generates templates with `hot-updater agent infra setup`, and applies them using
available provider tools. It verifies each step and resumes unfinished work
after inspecting remote state. The installed CLI must support the agent commands;
attaching the skill does not add commands to an older CLI.

## Safety Rules

- For agent-led infrastructure setup or upgrades, ask the agent to use
  `npx hot-updater agent infra setup` or `npx hot-updater agent infra upgrade`.
  These commands generate instructions and deployment templates for the agent
  to apply using its available provider tools. See
  [Agent Infrastructure](/docs/guides/agent-infrastructure).
- `npx hot-updater init` remains the interactive terminal workflow.
- The agent should ask for the update server URL before running a
  server/infrastructure doctor check unless you already provided it or it is
  obvious from local configuration.
- When iterating on doctor failures, the agent should prefer
  `npx hot-updater doctor --json`. It should repair issues marked
  `fixability: "auto"`, run listed commands for `fixability: "command"`, and
  stop on `fixability: "blocked"`.
- The agent should edit provider credentials only as part of a requested setup
  or credential change. Credentials are commonly stored in `.env.hotupdater`,
  but projects may use a different environment-loading setup.
- Server infrastructure failures remain blocked until the agent has the
  required provider access and authorization. It can generate upgrade
  instructions locally, then apply them when that access is available.
- If an OTA deploy fails, the agent should not keep trying fixes or mutate project
  setup automatically. It should summarize the failed command, the likely
  cause, and the next checks for you to decide.
- For state-changing operations such as deploy, bundle enable/disable, or
  database migration, the agent should identify the console ID and affected
  scope first and verify the result afterward. Operational rollback uses
  `bundle disable <id>`; Artifact IDs are used only for Advanced operations and
  native crash diagnostics.
