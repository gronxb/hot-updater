Deploy builds and uploads one immutable Bundle per platform, creates a Release
that owns its delivery policy, and atomically recompiles the affected Release
Catalog. Bundle IDs identify bytes; Release IDs identify delivery chronology,
rollout, compatibility, enabled state, force update, and message policy.

## Checklist

1. Ensure `hot-updater.config.ts` is properly configured.
2. Wrap your components using `HotUpdater.wrap`.
3. Include the native code.

If you haven't completed these steps, refer to the [Supabase Provider](/docs/managed/supabase) guide.

## Options

```
Options:
  -p, --platform <platform>                    specify the platform (choices: "ios", "android")
  -t, --target-app-version <targetAppVersion>  specify the target app version (semver format e.g. 1.0.0, 1.x.x)
  -d, --disabled                               create the Release disabled (default: false)
  -f, --force-update                           force update the app (default: false)
  -o, --bundle-output-path <bundleOutputPath>  the directory where bundle archives will be generated
  -r, --rollout <percentage>                   specify the rollout percentage for the new Release (0-100) (default: 100)
  -i, --interactive                            interactive mode (default: false)
  -c, --channel <channel>                      specify the channel to deploy (default: "production")
  -m, --message <message>                      Specify a custom message for this deployment. If not provided, the latest git commit message will be used as the deployment message
  -h, --help                                   display help for command
```

## Usage

### Default Mode

When you omit `-p` and `-i`, Hot Updater deploys **iOS first, then Android**
sequentially. If the iOS deploy fails, Android is not attempted.

Run the following command:

```package-install
npx hot-updater deploy
```

- This is the default mode for CI/CD pipelines when both platforms should move
  together.
- Local bundle archives are written under platform-specific directories such as
  `<bundle-output-path>/ios/bundle/` and `<bundle-output-path>/android/bundle/`.

### Deployment Result

After the database commit succeeds, deploy prints the identity of each
platform result:

- Release ID
- Bundle ID
- authority ID
- Release Catalog scope key
- Catalog generation

Use the Release ID with `release show`, `release update`, `release disable`, or
`release promote`. Use the Bundle ID with artifact commands such as
`bundle show`, `patch`, and `bundle delete`.

### Bundle Diffing

New deployments automatically include the artifacts needed for bundle diffing
alongside the archive bundle. When the app runtime supports manifest-based
diffing, unchanged files can be reused locally and only changed files are
downloaded. No deploy flag is required for this behavior.

Hermes binary patch generation is enabled by default (`patch.enabled: true`).
Deploy therefore also tries to prepare compatible `bsdiff` patches. Set
`patch.enabled: false` only when you want to disable this optimization. Patch
generation is best-effort; a skipped patch does not fail the deployment because
the normal archive update remains available.

See [Bundle Diffing](/docs/guides/bundle-diffing) for the runtime behavior and
fallback rules.

### Interactive Mode

Interactive mode guides you through the deployment steps via keyboard inputs.

Execute the following command:

```package-install
npx hot-updater deploy -i
```

The `-i` (or `--interactive`) flag enables interactive keyboard input.

- This mode allows you to proceed through deployment steps interactively.

### For Continuous Deployment (CD) Pipelines

Use this mode when a pipeline should deploy only one platform.

Run the following command:

```package-install
npx hot-updater deploy -p <"ios" | "android">
```

- Use `-p` to scope the deploy to exactly one platform.

### Force Update

Create a Release whose selected update is applied immediately.

Run the following command:

```package-install
npx hot-updater deploy -p <"ios" | "android"> -f
```

The `-f` (or `--force-update`) flag sets policy on the new Release. It does not
mutate the immutable Bundle.

### Channel

The `-c` (or `--channel`) flag specifies the release channel.

Run the following command:

```package-install
npx hot-updater deploy -p <"ios" | "android"> -c "<channel>"
```

The `-c` (or `--channel`) flag specifies the release channel. The default value is `production`.

For more details about default channels, refer to
[Default Channel Setup](/docs/guides/channel-management).

### Rollout

The `-r` (or `--rollout`) flag sets the rollout percentage for the new Release.

Run the following command:

```package-install
npx hot-updater deploy -p <"ios" | "android"> -r 25
```

Use `1` to `99` for gradual rollout, `100` for a full rollout, and `0` when
you want to create the Release without exposing it to numeric rollout until you
edit the same Release later.

Hot Updater maps rollout percentages to `1..1000` numeric cohorts internally.
For example, `-r 25` means 250 of 1000 numeric cohorts are eligible for that
Release. Numeric cohort selection is seeded by Release ID and remains stable
when that Release's rollout policy changes.

If you omit `-r`, the default value is `100`, so the new Release is eligible for
the entire numeric audience immediately.

For more on gradual rollout, current device cohorts, and cohort targeting from
the console, see [Rollout & Cohorts](/docs/guides/rollout-cohorts).

### Message

The `-m` (or `--message`) flag specifies the new Release's public message.

Run the following command:

```package-install
npx hot-updater deploy -p <"ios" | "android"> -m "<message>"
```

If you omit `-p`, the same message is applied to both sequential platform
deploys.

## Force Update Flag Difference

| Update Type  | When Applied                                                                                 | How to Enable                             |
| ------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Default      | Downloads the update bundle in the background and applies it when the user restarts the app. | Default setting                           |
| Force Update | Downloads the selected Release's Bundle and applies it immediately.                           | Use the `--force-update` flag or console. |
