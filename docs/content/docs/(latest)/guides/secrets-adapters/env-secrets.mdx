## Read secrets from the environment

`envSecrets()` from `hot-updater` is the default `secrets` adapter: a config
without `secrets` uses it. It reads each name the config uses from an
environment variable, in the environment or the project's `.env.hotupdater`,
and a variable in the environment wins.

```ts title="hot-updater.config.ts (partial)"
import { defineConfig, envSecrets } from "hot-updater";

export default defineConfig({
  secrets: envSecrets(),
  nativeBuild: {
    ios: {
      release: {
        bundleIdentifier: "com.example.app",
        scheme: "ExampleApp",
        // Reads HOT_UPDATER_ASC_API_KEY.
        signing: { ascApiKey: "secret:asc-api-key" },
      },
    },
  },
  // build, storage, database and plugins stay as they are
});
```

A name that is a variable name, such as `CLOUDFLARE_API_TOKEN` in
`secretEnv`, is that variable. Any other name is `HOT_UPDATER_` and the name
upper-cased, with `_` for every character but letters and digits:

| Reference                             | Variable                           |
| ------------------------------------- | ---------------------------------- |
| `secret:asc-api-key`                  | `HOT_UPDATER_ASC_API_KEY`          |
| `secret:release-keystore`             | `HOT_UPDATER_RELEASE_KEYSTORE`     |
| `play-service-account` (the default)  | `HOT_UPDATER_PLAY_SERVICE_ACCOUNT` |
| `secret:bundle-signing-key`           | `HOT_UPDATER_BUNDLE_SIGNING_KEY`   |
| `secretEnv(["CLOUDFLARE_API_TOKEN"])` | `CLOUDFLARE_API_TOKEN`             |

## Set a credential

A build credential's variable holds its
[JSON value](/docs/concepts/secrets#sign-native-builds-with-secrets). In
`.env.hotupdater`, put the JSON in single quotes, which keep the `\n` of a
key's line breaks as JSON reads them:

```bash title=".env.hotupdater"
HOT_UPDATER_ASC_API_KEY='{"keyId":"ABC123","issuerId":"00000000-0000-0000-0000-000000000000","p8":"-----BEGIN PRIVATE KEY-----\nMIGT…\n-----END PRIVATE KEY-----"}'
```

Each credential also has variables of its own, one per field, such as
`HOT_UPDATER_ASC_KEY_PATH`, `HOT_UPDATER_ASC_KEY_ID`, and
`HOT_UPDATER_ASC_ISSUER_ID` for a `.p8` file on disk. The CLI reads them
before any adapter: when one of a credential's variables is set, the build
reads the credential from them.
[Provide signing credentials](/docs/guides/native-build#provide-signing-credentials)
lists them.

Keep `.env.hotupdater` out of version control. It configures only the CLI,
not the app.

## Store an issued key

`envSecrets()` reads and never writes. `secrets put` given key files names the
variable to set instead of storing them. An Apple or Google sign-in, with
`secrets issue` or in a build, still issues the key: the CLI writes it to `<cacheDir>/issued/<name>.json`, a file
only your user can read, prints the variables to store it in, and, when the
project has a GitHub remote and you have a GitHub token, offers once to store
it as a GitHub Actions secret with
[`githubActions()`](/docs/guides/secrets-adapters/github-actions).
[Where an issued key goes](/docs/guides/native-build#where-an-issued-key-goes)
describes the file. Store the key, then delete the file.

## Grant least privilege

`envSecrets()` has no permissions of its own: whoever can read the environment or
the file can read the secrets. In CI, give each secret only to the job, and
the step, that needs it, and keep release credentials in a protected
[environment](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)
with required reviewers, away from pull request workflows that run untrusted
code.

## Read secrets in GitHub Actions

Add each value as a repository or environment secret, under its variable
name, and map it into the step that builds:

```yaml title=".github/workflows/native-release.yml (partial)"
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  env:
    HOT_UPDATER_ASC_API_KEY: ${{ secrets.HOT_UPDATER_ASC_API_KEY }}
  with:
    platform: ios
    scheme: release
    upload: testflight
```

[Build and upload from CI](/docs/guides/ci-native-build#environment-variables)
has the complete workflow for both platforms.
