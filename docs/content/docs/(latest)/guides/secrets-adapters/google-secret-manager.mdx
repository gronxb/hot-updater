## Read secrets from Google Secret Manager

`googleSecretManager()` from `hot-updater/secrets` reads the secrets
`hot-updater.config.ts` names from Secret Manager, and stores the keys
`secrets put` stores and `secrets issue` and builds issue after an Apple or
Google sign-in, as new versions.

```ts title="hot-updater.config.ts (partial)"
import { defineConfig } from "hot-updater";
import { googleSecretManager } from "hot-updater/secrets"; // [!code ++]

export default defineConfig({
  // [!code ++:4]
  secrets: googleSecretManager({
    project: "my-project",
    prefix: "hot-updater-",
  }),
  // build, storage, database and plugins stay as they are
});
```

| Option    | Description                                                                                   |
| --------- | --------------------------------------------------------------------------------------------- |
| `project` | The Google Cloud project ID or number that holds the secrets, such as your Firebase project's |
| `prefix`  | Put before each name to make its secret ID. Letters, digits, `-`, and `_`. Defaults to none   |

Each name is the secret ID with the prefix before it: with the config above,
`secret:asc-api-key` reads the secret `hot-updater-asc-api-key`, and
`secretEnv(["CLOUDFLARE_API_TOKEN"])` reads `hot-updater-CLOUDFLARE_API_TOKEN`.
Secret IDs take letters, digits, `-`, and `_`, so a name with a `.` is
refused. A credential is one JSON value per secret, as
[Secrets](/docs/concepts/secrets#sign-native-builds-with-secrets)
describes; each read is the secret's `latest` version.

## Provide Google credentials

The adapter takes a Google access token from the first of these:

1. `CLOUDSDK_AUTH_ACCESS_TOKEN` or `GOOGLE_OAUTH_ACCESS_TOKEN`, an access
   token as it is.
2. A Workload Identity Federation file in `GOOGLE_APPLICATION_CREDENTIALS`,
   as `google-github-actions/auth` writes it. The adapter exchanges the job's
   OIDC token for a Google token itself, so CI needs no package and no key.
3. Application Default Credentials through the optional `google-auth-library`
   package: `gcloud auth application-default login` on your machine, a
   service account key file in `GOOGLE_APPLICATION_CREDENTIALS`, or the
   service account attached to a Google Cloud runner.

For 3, install the package next to `hot-updater`:

```package-install
npm install google-auth-library --save-dev
```

```bash
gcloud auth application-default login
```

Every request goes to `https://secretmanager.googleapis.com` and refuses
redirects. The adapter keeps nothing on disk, and every token and value is
masked in the CLI's output.

## Grant least privilege

Give each identity only what it does:

| Who                                                     | Role                                                                                                                                      |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| A CI job that builds or deploys                         | `roles/secretmanager.secretAccessor` on each secret it reads                                                                              |
| The developer who runs `secrets put` or `secrets issue` | `roles/secretmanager.editor` and `roles/secretmanager.secretAccessor` on the project, or a custom role with exactly the permissions below |

```bash
gcloud iam roles create hotUpdaterSecretsWriter --project=my-project \
  --title="Hot Updater secrets writer" \
  --permissions=secretmanager.secrets.create,secretmanager.secrets.get,secretmanager.secrets.update,secretmanager.versions.add,secretmanager.versions.destroy,secretmanager.versions.access
```

`set` checks the permissions it needs on the secret before it writes, and
names any that are missing.

## Versions after set

Each `set` adds the value as the secret's newest version, creating the secret
when it is missing, and waits up to about 30 seconds for the `latest` alias,
which is eventually consistent, to resolve to it. It then destroys the older
versions it added, which the secret's `hot-updater-versions` annotation lists,
so a secret keeps one version from Hot Updater. Versions you add in the Cloud
Console or with `gcloud` are never destroyed. The annotation is updated against
the secret's etag, so two runs that store the same secret at once both stay
listed. When `latest` has not caught up in time, `set` keeps the older versions
for the next `set` and reports the version it stored. A secret with
[delayed destruction](https://cloud.google.com/secret-manager/docs/delay-destruction-of-secret-versions)
keeps the destroyed version disabled until its scheduled time.

Secret Manager's [free tier](https://cloud.google.com/secret-manager/pricing)
covers six active versions, and disabled versions count as active until they
are destroyed. One secret per credential kind keeps a project at three.

## Read secrets in GitHub Actions

Create a Workload Identity pool and a provider for your repository, and let
the CI service account read the build's secrets:

```bash
gcloud iam workload-identity-pools create github --project=my-project \
  --location=global
gcloud iam workload-identity-pools providers create-oidc my-app \
  --project=my-project --location=global --workload-identity-pool=github \
  --issuer-uri=https://token.actions.githubusercontent.com \
  --attribute-mapping=google.subject=assertion.sub,attribute.repository=assertion.repository \
  --attribute-condition="assertion.repository == 'my-org/my-app'"
gcloud iam service-accounts create hot-updater-ci --project=my-project
gcloud iam service-accounts add-iam-policy-binding \
  hot-updater-ci@my-project.iam.gserviceaccount.com \
  --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/github/attribute.repository/my-org/my-app"
for secret in hot-updater-release-keystore hot-updater-play-service-account; do
  gcloud secrets add-iam-policy-binding "$secret" --project=my-project \
    --role=roles/secretmanager.secretAccessor \
    --member=serviceAccount:hot-updater-ci@my-project.iam.gserviceaccount.com
done
```

The job asks GitHub for an OIDC token (`id-token: write`), and
`google-github-actions/auth` writes the federation file the adapter reads:

```yaml title=".github/workflows/native-release.yml (partial)"
permissions:
  contents: read
  id-token: write

# ...in the job, after npm ci:
- uses: google-github-actions/auth@7c6bc770dae815cd3e89ee6cdf493a5fab2cc093 # v3
  with:
    workload_identity_provider: projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/github/providers/my-app
    service_account: hot-updater-ci@my-project.iam.gserviceaccount.com
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  with:
    platform: android
    scheme: release
    upload: play-internal
```

[Build and upload from CI](/docs/guides/ci-native-build#google-secret-manager)
has the complete workflow.

Without `service_account`, the job uses its federated identity directly:
grant `roles/secretmanager.secretAccessor` to the `principalSet://…` member
instead of a service account. A job that already has an access token, such as
from the action's `token_format: access_token` output, can set
`GOOGLE_OAUTH_ACCESS_TOKEN` to it instead.

## Troubleshoot

| Error                                                 | Fix                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `found no Google credentials`                         | Run `gcloud auth application-default login`, or authenticate the CI job as above                       |
| `through the optional google-auth-library package`    | Install `google-auth-library`, or provide a token or a federation file, which need no package          |
| `403 PERMISSION_DENIED`                               | Grant the role [Grant least privilege](#grant-least-privilege) names for the identity in the message                     |
| `Enable the Secret Manager API`                       | `gcloud services enable secretmanager.googleapis.com --project=my-project`                             |
| `lacks ... on it`                                     | `set` found missing permissions before it wrote anything: grant the writer role                        |
