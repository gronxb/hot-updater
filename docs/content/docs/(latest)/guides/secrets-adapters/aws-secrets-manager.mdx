## Read secrets from AWS Secrets Manager

`awsSecretsManager()` from `hot-updater/secrets` reads each secret the config
names from [AWS Secrets Manager](https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html):
the secret `<prefix><name>`. It signs its requests itself, so CI needs no AWS
SDK, and its `set` stores the keys `secrets put` stores and the keys
`secrets issue` or a build issues after a sign-in.

```ts title="hot-updater.config.ts (partial)"
import { defineConfig } from "hot-updater";
import { awsSecretsManager } from "hot-updater/secrets";

export default defineConfig({
  secrets: awsSecretsManager({
    region: "ap-northeast-2",
    prefix: "hot-updater/",
  }),
  nativeBuild: {
    ios: {
      release: {
        bundleIdentifier: "com.example.app",
        scheme: "ExampleApp",
        // Reads the secret hot-updater/asc-api-key.
        signing: { ascApiKey: "secret:asc-api-key" },
      },
    },
  },
  // build, storage, database and plugins stay as they are
});
```

| Option        | Description                                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `region`      | The region the secrets are in. Required.                                                                                                                 |
| `prefix`      | Put before every name, such as `hot-updater/`, so one IAM resource, `secret:hot-updater/*`, covers every secret. Defaults to none.                       |
| `credentials` | `{ accessKeyId, secretAccessKey, sessionToken? }`, or a function that returns them. Without it, the adapter finds credentials as described below.        |
| `endpoint`    | An HTTPS endpoint, such as a VPC endpoint. Defaults to `https://secretsmanager.<region>.amazonaws.com`.                                                  |

Each secret holds one value: a credential is one JSON value, such as
`{"keyId": "…", "issuerId": "…", "p8": "…"}`, as
[Secrets](/docs/concepts/secrets#sign-native-builds-with-secrets) lists.
A secret stored as binary is read as base64. A secret that does not exist reads
as missing; a missing permission, expired credentials, or a secret scheduled for
deletion fails the command.

## Provide AWS credentials

Without `credentials`, the adapter uses, in order:

1. `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN` from
   the environment, which `aws-actions/configure-aws-credentials` sets in
   GitHub Actions.
2. The AWS SDK's default chain, for a profile, AWS SSO, or an instance role,
   from the optional `@aws-sdk/credential-providers` package. Install it where
   you sign in with a profile:

```package-install
npm install @aws-sdk/credential-providers --save-dev
```

```bash
aws sso login --profile release
AWS_PROFILE=release npx hot-updater build:ios --scheme release
```

The adapter masks the credentials it signs with in the CLI's output, as it does
every secret it reads.

## Grant least privilege

CI only reads. Give its role `secretsmanager:GetSecretValue` on the prefix:

```json title="IAM policy: read"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:ap-northeast-2:123456789012:secret:hot-updater/*"
    }
  ]
}
```

Whoever stores secrets, with `secrets put`, `secrets issue`, or a build that
issues a key, also
needs `secretsmanager:PutSecretValue`, and `secretsmanager:CreateSecret` for a
secret that does not exist yet. `GetSecretValue` stays: a sign-in reads the key
back after storing it.

```json title="IAM policy: store"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "secretsmanager:GetSecretValue",
        "secretsmanager:PutSecretValue",
        "secretsmanager:CreateSecret"
      ],
      "Resource": "arn:aws:secretsmanager:ap-northeast-2:123456789012:secret:hot-updater/*"
    }
  ]
}
```

- The adapter reads each secret with its own `GetSecretValue` call, in
  parallel. It never calls `BatchGetSecretValue`, which would need its own
  permission on every resource.
- A secret the adapter creates has the description "Stored by Hot Updater." and
  no tags, so no `secretsmanager:TagResource` is needed.
- Secrets encrypted with a customer managed KMS key also need `kms:Decrypt` on
  that key to read, and `kms:GenerateDataKey` and `kms:Decrypt` to store. To use
  such a key, create the secret with it first; `set` then puts new values on it.
- AWS appends six random characters to a secret's ARN, such as
  `hot-updater/asc-api-key-a1b2c3`. Avoid a name that ends in a hyphen and six
  characters, which a partial ARN can confuse.

## Versions after set

`set` puts a new version of the secret. AWS moves the label `AWSCURRENT` to it
and `AWSPREVIOUS` to the version before; the adapter reads `AWSCURRENT`. AWS
keeps the 100 most recent versions, and every version from the last 24 hours,
and removes older ones itself. Secrets Manager has no call that deletes one
version, so the adapter deletes nothing. AWS bills per secret, not per version,
but [advises](https://docs.aws.amazon.com/secretsmanager/latest/apireference/API_PutSecretValue.html)
storing one secret no more often than once every 10 minutes.

## Read secrets in GitHub Actions

[GitHub Actions OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws)
exchanges the workflow's identity for short-lived credentials of a role, so the
repository stores no AWS key. Trust the role only from the expected repository
and environment:

```json title="IAM role trust policy"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:example/app:environment:production"
        }
      }
    }
  ]
}
```

Attach the read policy to the role, and let the workflow request an ID token:

```yaml title=".github/workflows/native-release.yml (partial)"
permissions:
  contents: read
  id-token: write

# ...in the job, after npm ci:
- uses: aws-actions/configure-aws-credentials@e6de054238d6b7531b4efff3b6587d9aade6a06c # v6
  with:
    role-to-assume: arn:aws:iam::123456789012:role/hot-updater-ci
    aws-region: ap-northeast-2
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  with:
    platform: ios
    scheme: release
    upload: testflight
```

The steps after `configure-aws-credentials` read the secrets with the role's
credentials from the environment; the optional package is not needed in CI.
Keep the role away from pull request workflows that run untrusted code.
[Build and upload from CI](/docs/guides/ci-native-build#aws-secrets-manager)
has the complete workflow.
