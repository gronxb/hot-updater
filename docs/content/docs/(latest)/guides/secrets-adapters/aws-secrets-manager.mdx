## Add the adapter

Hot Updater ships no AWS Secrets Manager adapter: paste this file into your
project. It implements [`SecretsAdapter`](/docs/concepts/secrets#write-a-secrets-adapter)
with the official AWS SDK, keeping each name as the secret `<prefix><name>`.

```package-install
npm install @aws-sdk/client-secrets-manager --save-dev
```

```ts title="secrets/aws-secrets-manager.ts"
import {
  CreateSecretCommand,
  GetSecretValueCommand,
  PutSecretValueCommand,
  ResourceNotFoundException,
  SecretsManagerClient,
} from "@aws-sdk/client-secrets-manager";
import type { SecretsAdapter } from "hot-updater";

export const awsSecretsManager = ({
  region,
  prefix = "hot-updater/",
}: {
  region: string;
  prefix?: string;
}): SecretsAdapter => {
  // Credentials come from the AWS SDK's default chain: the environment
  // (GitHub Actions OIDC), a profile, or AWS SSO.
  const client = new SecretsManagerClient({ region });
  const secretId = (name: string) => `${prefix}${name}`;

  const read = async (name: string) => {
    try {
      const secret = await client.send(
        new GetSecretValueCommand({ SecretId: secretId(name) }),
      );
      return secret.SecretString;
    } catch (error) {
      if (error instanceof ResourceNotFoundException) return undefined;
      throw error;
    }
  };

  return {
    name: "awsSecretsManager",
    get: async (names) =>
      Object.fromEntries(
        await Promise.all(names.map(async (name) => [name, await read(name)])),
      ),
    set: async (name, value) => {
      try {
        await client.send(
          new PutSecretValueCommand({
            SecretId: secretId(name),
            SecretString: value,
          }),
        );
      } catch (error) {
        if (!(error instanceof ResourceNotFoundException)) throw error;
        await client.send(
          new CreateSecretCommand({
            Name: secretId(name),
            SecretString: value,
          }),
        );
      }
    },
    describe: (name) =>
      `AWS Secrets Manager secret ${secretId(name)} in ${region}`,
  };
};
```

```ts title="hot-updater.config.ts (partial)"
import { defineConfig } from "hot-updater";

import { awsSecretsManager } from "./secrets/aws-secrets-manager";

export default defineConfig({
  secrets: awsSecretsManager({ region: "ap-northeast-2" }),
  // build, storage, database and plugins stay as they are
});
```

With the default prefix, `secret:asc-api-key` reads the secret
`hot-updater/asc-api-key`. Each secret holds one value: a credential is one
[JSON value](/docs/concepts/secrets#sign-native-builds-with-secrets). A
secret that does not exist reads as missing; a missing permission or expired
credentials fail the command.

The AWS SDK finds credentials itself: `AWS_ACCESS_KEY_ID` and its siblings,
which `aws-actions/configure-aws-credentials` sets in GitHub Actions, a
profile, or AWS SSO:

```bash
aws sso login --profile release
AWS_PROFILE=release npx hot-updater apple login
```

## Grant least privilege

CI only reads. Give its role `secretsmanager:GetSecretValue` on the prefix:

```json title="IAM policy: read"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:ap-northeast-2:123456789012:secret:hot-updater/*"
    }
  ]
}
```

Whoever stores secrets, with `secrets put` or a sign-in that issues a key,
also needs `secretsmanager:PutSecretValue`, and `secretsmanager:CreateSecret`
for a secret that does not exist yet. `GetSecretValue` stays: a sign-in
reads the key back after storing it. Secrets encrypted with a customer
managed KMS key also need `kms:Decrypt` on that key to read, and
`kms:GenerateDataKey` to store.

Each `set` puts a new version: AWS moves `AWSCURRENT` to it, keeps the
previous one as `AWSPREVIOUS`, and removes old versions itself.

## Read secrets in GitHub Actions

[GitHub Actions OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws)
exchanges the workflow's identity for short-lived credentials of a role, so
the repository stores no AWS key. Trust the role only from the expected
repository and environment:

```json title="IAM role trust policy"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:example/app:environment:production"
        }
      }
    }
  ]
}
```

Attach the read policy to the role, and let the workflow request an ID token:

```yaml title=".github/workflows/native-release.yml (partial)"
permissions:
  contents: read
  id-token: write

# ...in the job, after npm ci:
- uses: aws-actions/configure-aws-credentials@e6de054238d6b7531b4efff3b6587d9aade6a06c # v6
  with:
    role-to-assume: arn:aws:iam::123456789012:role/hot-updater-ci
    aws-region: ap-northeast-2
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  with:
    platform: ios
    scheme: release
    upload: testflight
```

Keep the role away from pull request workflows that run untrusted code.
[Build and upload from CI](/docs/guides/ci-native-build#read-secrets-from-a-secrets-store)
has the complete workflow.
