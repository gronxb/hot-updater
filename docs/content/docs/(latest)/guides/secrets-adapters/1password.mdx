## Add the adapter

Hot Updater ships no 1Password adapter: paste this file into your project.
It implements [`SecretsAdapter`](/docs/concepts/secrets#write-a-secrets-adapter)
with 1Password's official SDK, keeping each name as a **Password** item of
that title in one vault.

```package-install
npm install @1password/sdk --save-dev
```

```ts title="secrets/1password.ts"
import {
  type Client,
  createClient,
  ItemCategory,
  ItemFieldType,
} from "@1password/sdk";
import type { SecretsAdapter } from "hot-updater";

export const onePassword = ({
  vaultId,
}: {
  /** The vault's ID, as `op vault list` prints it. */
  vaultId: string;
}): SecretsAdapter => {
  let connected: Promise<Client> | undefined;
  // A service account token, OP_SERVICE_ACCOUNT_TOKEN, here and in CI.
  const client = () =>
    (connected ??= createClient({
      auth: process.env.OP_SERVICE_ACCOUNT_TOKEN ?? "",
      integrationName: "hot-updater",
      integrationVersion: "1",
    }));

  // Each name is a Password item of that title in the vault.
  const read = async (names: readonly string[]) => {
    const op = await client();
    const items = await op.items.list(vaultId);
    return Promise.all(
      names.map(async (name) => {
        const overview = items.find((item) => item.title === name);
        return overview && op.items.get(vaultId, overview.id);
      }),
    );
  };

  return {
    name: "onePassword",
    get: async (names) => {
      const items = await read(names);
      return Object.fromEntries(
        names.map((name, index) => {
          const fields = items[index]?.fields ?? [];
          return [name, fields.find(({ id }) => id === "password")?.value];
        }),
      );
    },
    set: async (name, value) => {
      const op = await client();
      const [item] = await read([name]);
      if (!item) {
        await op.items.create({
          vaultId,
          title: name,
          category: ItemCategory.Password,
          fields: [
            {
              id: "password",
              title: "password",
              fieldType: ItemFieldType.Concealed,
              value,
            },
          ],
        });
        return;
      }
      await op.items.put({
        ...item,
        fields: item.fields.map((field) =>
          field.id === "password" ? { ...field, value } : field,
        ),
      });
    },
    describe: (name) =>
      `the Password item "${name}" in 1Password vault ${vaultId}`,
  };
};
```

```ts title="hot-updater.config.ts (partial)"
import { defineConfig } from "hot-updater";

import { onePassword } from "./secrets/1password";

export default defineConfig({
  secrets: onePassword({ vaultId: "abcdefghijklmnopqrstuvwxyz" }),
  // build, storage, database and plugins stay as they are
});
```

`secret:asc-api-key` reads the item `asc-api-key`'s password field. A
credential is one [JSON value](/docs/concepts/secrets#sign-native-builds-with-secrets).

## Grant least privilege

The SDK signs in with a
[service account](https://developer.1password.com/docs/service-accounts/)
token in `OP_SERVICE_ACCOUNT_TOKEN`. A service account reaches only the
vaults it was created for:

| Who                                              | Vault access    |
| ------------------------------------------------ | --------------- |
| CI, which builds and deploys                     | Read items      |
| The developer who runs `secrets put` or signs in | Read and write items |

Create two service accounts for the vault, one per row, and keep the
writable token on the machines that store keys.

## Read secrets in CI

Store the read-only token as the CI secret `OP_SERVICE_ACCOUNT_TOKEN` and set
it on the build step:

```yaml title=".github/workflows/native-release.yml (partial)"
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  env:
    OP_SERVICE_ACCOUNT_TOKEN: ${{ secrets.OP_SERVICE_ACCOUNT_TOKEN }}
  with:
    platform: ios
    scheme: release
    upload: testflight
```

[Build and upload from CI](/docs/guides/ci-native-build#read-secrets-from-a-secrets-store)
has the complete workflow.
