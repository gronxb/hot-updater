## Add the adapter

Hot Updater ships no Infisical adapter: paste this file into your project.
It implements [`SecretsAdapter`](/docs/concepts/secrets#write-a-secrets-adapter)
with Infisical's official SDK, keeping each name as one secret in a project,
environment, and folder.

```package-install
npm install @infisical/sdk --save-dev
```

```ts title="secrets/infisical.ts"
import { InfisicalSDK } from "@infisical/sdk";
import type { SecretsAdapter } from "hot-updater";

export const infisical = ({
  projectId,
  environment,
  secretPath = "/",
  siteUrl = "https://app.infisical.com",
}: {
  projectId: string;
  environment: string;
  secretPath?: string;
  siteUrl?: string;
}): SecretsAdapter => {
  const where = { projectId, environment, secretPath };
  let signedIn: Promise<InfisicalSDK> | undefined;
  // INFISICAL_TOKEN on your machine (`infisical login`), a machine
  // identity's Universal Auth in CI.
  const client = () =>
    (signedIn ??= (async () => {
      const sdk = new InfisicalSDK({ siteUrl });
      const token = process.env.INFISICAL_TOKEN;
      if (token) return sdk.auth().accessToken(token);
      return sdk.auth().universalAuth.login({
        clientId: process.env.INFISICAL_UNIVERSAL_AUTH_CLIENT_ID ?? "",
        clientSecret: process.env.INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET ?? "",
      });
    })());

  const list = async () => {
    const { secrets } = await (await client()).secrets().listSecrets({
      ...where,
      viewSecretValue: true,
      expandSecretReferences: false,
    });
    return new Map(secrets.map((secret) => [secret.secretKey, secret]));
  };

  return {
    name: "infisical",
    // One request for the folder: a name it does not hold is missing.
    get: async (names) => {
      const held = await list();
      return Object.fromEntries(
        names.map((name) => [name, held.get(name)?.secretValue] as const),
      );
    },
    set: async (name, value) => {
      const secrets = (await client()).secrets();
      if ((await list()).has(name)) {
        await secrets.updateSecret(name, { ...where, secretValue: value });
      } else {
        await secrets.createSecret(name, { ...where, secretValue: value });
      }
    },
    describe: (name) =>
      `${name} in Infisical project ${projectId}, ${environment}:${secretPath}`,
  };
};
```

```ts title="hot-updater.config.ts (partial)"
import { defineConfig } from "hot-updater";

import { infisical } from "./secrets/infisical";

export default defineConfig({
  secrets: infisical({
    projectId: "6f4a…",
    environment: "prod",
    secretPath: "/hot-updater",
  }),
  // build, storage, database and plugins stay as they are
});
```

`secret:asc-api-key` reads the secret `asc-api-key` in that folder. A
credential is one [JSON value](/docs/concepts/secrets#sign-native-builds-with-secrets).
`get` lists the folder once, so a name it does not hold is missing, and a
wrong `projectId`, `environment`, or `secretPath` fails with Infisical's
reason. For a self-hosted instance, pass its URL as `siteUrl`.

## Sign in

| Where        | Set                                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| Your machine | `INFISICAL_TOKEN`, after `infisical login`: `export INFISICAL_TOKEN="$(infisical user get token --plain)"` |
| CI           | `INFISICAL_UNIVERSAL_AUTH_CLIENT_ID` and `INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET`, a machine identity's     |

Your user needs a project role that can create and edit secrets in the
environment, such as **Member**, to store a secret.

## Read secrets in CI

1. In your organization's **Access Control** > **Machine Identities**,
   create an identity with **Universal Auth**, and add a client secret.
2. In the project's **Access Control** > **Machine Identities**, add the
   identity with the **Viewer** role, which reads secrets and their values
   but can't create, edit, or delete them.
3. Store the client ID and secret as the CI secrets
   `INFISICAL_UNIVERSAL_AUTH_CLIENT_ID` and
   `INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET`, and set them on the build step:

```yaml title=".github/workflows/native-release.yml (partial)"
- uses: gronxb/hot-updater/actions/native-build@v1.2.0
  env:
    INFISICAL_UNIVERSAL_AUTH_CLIENT_ID: ${{ secrets.INFISICAL_UNIVERSAL_AUTH_CLIENT_ID }}
    INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET: ${{ secrets.INFISICAL_UNIVERSAL_AUTH_CLIENT_SECRET }}
  with:
    platform: android
    scheme: release
    upload: play-internal
```

[Build and upload from CI](/docs/guides/ci-native-build#read-secrets-from-a-secrets-store)
has the complete workflow.
