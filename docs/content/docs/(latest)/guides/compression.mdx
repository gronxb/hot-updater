---
title: "Artifact Compression"
description: "How Hot Updater transfers changed files and complete bundles."
icon: FileArchive
---

Hot Updater distributes OTA updates using a verified manifest, individual files,
and a `tar.br` archive for updates where a single download is more economical.
The client chooses the transport automatically after checking which local files
it can reuse. ZIP and `tar.gz` OTA archives are not supported.

Deploy automatically compresses eligible individual files with Brotli. The
manifest records the logical installed-file hash and, when the served bytes are
compressed, the download hash and byte size. Native clients decompress and
verify each file before staging the update.

There is no compression or archive/diff setting. Deploy also creates
`bundle.tar.br` containing the target files and records its hash and sizes in the
manifest. This adds compression work and one complete compressed object to each
Bundle's storage.

```bash
npx hot-updater deploy -p ios
npx hot-updater deploy -p android
```

Per-file transfer skips files already present in the current OTA, completed
staging, or built-in app. With at least two files left to download, the client
compares `tar.br` against the expected individual transfer bytes, including
smaller offered patches. If every target file needs downloading and no patch is
offered, it also allows the archive's TAR framing and padding overhead. This
avoids many requests for a complete bundle whose files do not compress well.
Updates that reuse files or offer patches keep the strict byte comparison.
Missing or invalid sizes keep the per-file route. Selection bounds the permitted
extra payload; it does not predict every network's latency.

Both routes verify the same target file set and hashes before activating the
update. If the archive fails, the client discards its extraction scratch and
tries the original per-file plan once. This recovery can transfer additional
bytes. A failed patch falls back only to that file's original.
