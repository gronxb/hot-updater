---
title: "Secrets"
description: "Where the CLI reads deploy, signing, and native build credentials from. Hot Updater stores none of them."
icon: KeyRound
---

Hot Updater stores no secrets. Your CLI, CI, and signing service keep them,
and the CLI reads each one when a command needs it:

| Credential                                     | Where the CLI reads it                                                                                                                       |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider credentials for `storage` and `database` | The environment and `.env.hotupdater`, which `hot-updater.config.ts` reads                                                                  |
| Bundle signing key                             | The `signing` adapter: a local PEM file, or a key that stays in [AWS KMS](/docs/guides/signing/aws-kms), [Google Cloud KMS](/docs/guides/signing/google-cloud-kms), or a [remote signer](/docs/guides/signing/remote) |
| Native build signing and store upload keys     | The `HOT_UPDATER_*` environment variables in [Provide signing credentials](/docs/guides/native-build#provide-signing-credentials)             |

Keep these values out of version control and out of the app. In CI, set them
from your CI provider's secret storage. [Security](/docs/policy/security)
lists which values belong where.
