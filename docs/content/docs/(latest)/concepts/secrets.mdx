---
title: "Secrets"
description: "Where the CLI reads deploy, signing, and native build credentials from. Hot Updater stores none of them."
icon: KeyRound
---

Hot Updater stores no secrets. Your secrets store, CI, and signing service
keep them, and the CLI reads each one when a command needs it:

| Credential                                        | Where the CLI reads it                                                                                                                                                                                      |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider credentials for `storage` and `database` | The config's [`secrets` adapter](/docs/guides/secrets) through [`secretEnv`](/docs/guides/secrets#deploy-credentials-with-secretenv), or the environment the config reads                                  |
| Native build signing and store upload keys        | The `secrets` adapter through `secret:<name>`, or the environment variables in [Provide signing credentials](/docs/guides/native-build#provide-signing-credentials)                                          |
| Bundle signing key                                | The `signing` adapter: a key that stays in [AWS KMS](/docs/guides/signing/aws-kms), [Google Cloud KMS](/docs/guides/signing/google-cloud-kms), or a [remote signer](/docs/guides/signing/remote), or a [local PEM](/docs/guides/signing/local) from the `secrets` adapter as `secret:<name>` or from a file |

The default `secrets` adapter, `env()`, reads the environment and
`.env.hotupdater`. Keep these values out of version control and out of the
app. In CI, set them from your CI provider's secret storage.
[Security](/docs/policy/security) lists which values belong where.
