## Provider Setup

Before configuring the build plugin, you need to set up a provider to handle updates. Hot-updater supports multiple managed providers that handle storage and update distribution.

### Step 1: Install hot-updater

First, install the hot-updater package:

```package-install
npm install hot-updater --save-dev
```

### Step 2: Initialize Your Provider

Run the initialization command to set up your provider interactively:

```package-install
npx hot-updater init
```

This interactive CLI will guide you through:

1. **Build Plugin Selection**: Choose your build system (Bare/React Native CLI, Rock, or Expo)
2. **Provider Selection**: Select from available providers:
   - [Supabase](/docs/managed/supabase)
   - [Firebase](/docs/managed/firebase)
   - [Cloudflare](/docs/managed/cloudflare)
   - [AWS](/docs/managed/aws)

3. **Provider Configuration**: Follow provider-specific prompts for authentication and resource setup.

### Step 3: Generated Configuration

After initialization, two files will be generated:

**`.env.hotupdater`** - Contains provider credentials and configuration:

```
# Example for Supabase
HOT_UPDATER_SUPABASE_URL=https://your-project.supabase.co
HOT_UPDATER_SUPABASE_PROJECT_ID=your-project-id
HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY=your-service-role-or-secret-key
HOT_UPDATER_SUPABASE_BUCKET_NAME=your-bucket-name
```

**`hot-updater.config.ts`** - Contains provider integration settings:

The example below uses the Bare (React Native CLI) build plugin. If you selected Rock or Expo, only the `build` field changes as shown in the build configuration section below.

```ts title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { supabaseStorage, supabaseDatabase } from "@hot-updater/supabase";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

export default defineConfig({
  authorityId: "your-project-id",
  build: bare({ enableHermes: true }),
  updateStrategy: "appVersion",
  storage: supabaseStorage({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey: process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
    bucketName: process.env.HOT_UPDATER_SUPABASE_BUCKET_NAME!,
  }),
  database: supabaseDatabase({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey: process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
  }),
});
```

<Callout type="info">
  For detailed provider-specific setup instructions, see the [Self-Hosting
  (Managed)](/docs/managed/supabase) documentation.
</Callout>

<Callout type="warn">
  The environment variables in `.env.hotupdater` are used only during
  deployment, not in your app bundle. However, if you're using
  `react-native-dotenv`, review the [Security
  guidelines](/docs/policy/security#plugin-token-protection).
</Callout>

### Step 4: Wrap Your Application

Add the HotUpdater wrapper to your main application component:

```tsx title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";
import { Text, View } from "react-native";

function App() {
  return (
    <View>
      <Text>Hello World</Text>
    </View>
  );
}

export default HotUpdater.wrap({
  baseURL: "https://your-update-server-url", // [!code ++]
  authorityId: "your-project-id", // [!code ++]
  updateStrategy: "appVersion", // or "fingerprint" // [!code ++]
  requestHeaders: {
    // Optional: Add custom headers if needed
  },
  fallbackComponent: ({ progress, status }) => (
    <View
      style={{
        flex: 1,
        padding: 20,
        borderRadius: 10,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "rgba(0, 0, 0, 0.5)",
      }}
    >
      <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
        {status === "UPDATING" ? "Updating..." : "Checking for Update..."}
      </Text>
      {progress > 0 ? (
        <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
          {Math.round(progress * 100)}%
        </Text>
      ) : null}
    </View>
  ),
})(App);
```

<Callout type="info">
  The update server URL will be provided after running `npx hot-updater init`.
  Check your terminal output or provider console for the correct URL.
</Callout>

<Callout type="info">
  In v1, keep this `authorityId` identical to the value generated in
  `hot-updater.config.ts`. The default resolver requests a Release Catalog with
  the authority ID, platform, base64url-encoded channel key, and the selected
  strategy value (app version or fingerprint).
</Callout>

## Build Configuration

Hot Updater configures bundling through the `build` field in
`hot-updater.config.ts`. The snippets below are build-field excerpts: keep the
complete provider configuration generated by `init`, including `authorityId`,
`updateStrategy`, `storage`, and `database`.

<Tabs items={['Bare (React Native CLI)', 'Rock', 'Expo']}>
  <Tab value="Bare (React Native CLI)">

Use the Bare build plugin for standard React Native CLI projects:

```ts title="hot-updater.config.ts (build excerpt)"
import { bare } from "@hot-updater/bare";
import { defineConfig } from "hot-updater";

export default defineConfig({
  build: bare({
    enableHermes: true,
  }),
  // ... storage and database
});
```

No additional Babel plugin setup is required.

  </Tab>
  <Tab value="Rock">

Use the Rock build plugin for Rock projects:

```ts title="hot-updater.config.ts (build excerpt)"
import { rock } from "@hot-updater/rock";
import { defineConfig } from "hot-updater";

export default defineConfig({
  build: rock(),
  // ... storage and database
});
```

No additional Babel plugin setup is required.

  </Tab>
  <Tab value="Expo">

Use the Expo build plugin in `hot-updater.config.ts`:

```ts title="hot-updater.config.ts (build excerpt)"
import { expo } from "@hot-updater/expo";
import { defineConfig } from "hot-updater";

export default defineConfig({
  build: expo(),
  // ... storage and database
});
```

Then add the config plugin to your `app.json`:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "@hot-updater/react-native",
        {
          "channel": "production"
        }
      ]
    ]
  }
}
```

Run prebuild to apply the native changes:

```package-install
npx expo prebuild
```

<Callout>
  For Expo projects, the config plugin automatically generates the native code
  configuration described in the next section.
</Callout>

<Callout type="info">
  If you use Expo DOM components (`use dom`), see [Expo DOM Components (`use
  dom`)](/docs/build-plugins/expo#expo-dom-components-use-dom) for the
  additional Babel plugin setup.
</Callout>

  </Tab>
</Tabs>

## Native Code Setup

Expo projects using the config plugin can skip this section after running
`expo prebuild`. For Bare and Rock projects, start from the
`MainApplication` and `AppDelegate` generated by your installed React Native
version and add only the highlighted integration points below. Do not replace a
newer template with an older full-file example.

### Android

Keep Metro as the bundle source in debug builds. Hot Updater should select the
downloaded or embedded release bundle only when `BuildConfig.DEBUG` is
`false`.

<Tabs items={['Kotlin (RN 0.82+)', 'Kotlin (RN <=0.81)', 'Java (RN <=0.81)']}>
  <Tab value="Kotlin (RN 0.82+)">

React Native 0.82 introduced the `ReactHost`-only template. Add the import and
the `jsBundleFilePath` argument to the generated `getDefaultReactHost` call:

```kt title="android/app/src/main/java/com/<your-app-name>/MainApplication.kt (excerpt)"
import com.hotupdater.HotUpdater // [!code ++]

// Keep the other arguments generated by your React Native version.
override val reactHost: ReactHost by lazy {
  getDefaultReactHost(
    context = applicationContext,
    packageList = PackageList(this).packages,
    jsBundleFilePath = // [!code ++]
      if (BuildConfig.DEBUG) { // [!code ++]
        null // Keep Metro in debug builds. // [!code ++]
      } else { // [!code ++]
        HotUpdater.getJSBundleFile(applicationContext) // [!code ++]
      }, // [!code ++]
  )
}
```

  </Tab>
  <Tab value="Kotlin (RN <=0.81)">

For templates that still define `DefaultReactNativeHost`, preserve the
generated startup code for your version. In particular, do not copy
`SoLoader.init` between the React Native 0.75 and earlier, 0.76-0.80, and 0.81
templates. Add only this import and override:

```kt title="android/app/src/main/java/com/<your-app-name>/MainApplication.kt (excerpt)"
import com.hotupdater.HotUpdater // [!code ++]

override val reactNativeHost: ReactNativeHost =
  object : DefaultReactNativeHost(this) {
    // Keep the methods generated by your React Native version.

    override fun getJSBundleFile(): String? = // [!code ++]
      if (BuildConfig.DEBUG) { // [!code ++]
        null // Keep Metro in debug builds. // [!code ++]
      } else { // [!code ++]
        HotUpdater.getJSBundleFile(applicationContext) // [!code ++]
      } // [!code ++]
  }
```

  </Tab>
  <Tab value="Java (RN <=0.81)">

For Java applications using `DefaultReactNativeHost`, add the import and
override without replacing the surrounding generated class:

```java title="android/app/src/main/java/com/<your-app-name>/MainApplication.java (excerpt)"
import com.hotupdater.HotUpdater; // [!code ++]

private final ReactNativeHost mReactNativeHost =
    new DefaultReactNativeHost(this) {
      // Keep the methods generated by your React Native version.

      @Override // [!code ++]
      protected String getJSBundleFile() { // [!code ++]
        return BuildConfig.DEBUG // [!code ++]
            ? null // Keep Metro in debug builds. // [!code ++]
            : HotUpdater.Companion.getJSBundleFile( // [!code ++]
                MainApplication.this.getApplicationContext() // [!code ++]
              ); // [!code ++]
      } // [!code ++]
    };
```

  </Tab>
</Tabs>

### iOS

Keep the generated debug branch that uses `RCTBundleURLProvider`, and replace
only the release bundle URL.

<Tabs items={['Swift (RN 0.79+)', 'Swift (RN <=0.78)', 'Objective-C']}>
  <Tab value="Swift (RN 0.79+)">

React Native 0.79 moved bundle selection to
`ReactNativeDelegate.bundleURL()`:

```swift title="ios/<your-app-name>/AppDelegate.swift (excerpt)"
import HotUpdater // [!code ++]

class ReactNativeDelegate: RCTDefaultReactNativeFactoryDelegate {
  override func sourceURL(for bridge: RCTBridge) -> URL? {
    self.bundleURL()
  }

  override func bundleURL() -> URL? {
#if DEBUG
    RCTBundleURLProvider.sharedSettings().jsBundleURL(forBundleRoot: "index")
#else
    HotUpdater.bundleURL() // [!code ++]
#endif
  }
}
```

  </Tab>
  <Tab value="Swift (RN <=0.78)">

React Native 0.78 and earlier Swift templates use
`RCTAppDelegate.bundleURL()`:

```swift title="ios/<your-app-name>/AppDelegate.swift (excerpt)"
import HotUpdater // [!code ++]

@main
class AppDelegate: RCTAppDelegate {
  override func sourceURL(for bridge: RCTBridge) -> URL? {
    self.bundleURL()
  }

  override func bundleURL() -> URL? {
#if DEBUG
    RCTBundleURLProvider.sharedSettings().jsBundleURL(forBundleRoot: "index")
#else
    HotUpdater.bundleURL() // [!code ++]
#endif
  }
}
```

  </Tab>
  <Tab value="Objective-C">

For Objective-C app delegates, keep the existing debug URL and replace the
release URL:

```objc title="ios/<your-app-name>/AppDelegate.mm (excerpt)"
#import <HotUpdater/HotUpdater.h> // [!code ++]

- (NSURL *)bundleURL
{
#if DEBUG
  return [[RCTBundleURLProvider sharedSettings] jsBundleURLForBundleRoot:@"index"];
#else
  return [HotUpdater bundleURL]; // [!code ++]
#endif
}
```

  </Tab>
</Tabs>

<Callout type="info">
  For brownfield apps where the JavaScript bundle is embedded in an XCFramework,
  pass its `Bundle` to `HotUpdater.bundleURL(bundle: xcframeworkBundle)` in
  Swift or `[HotUpdater bundleURLWithBundle:xcframeworkBundle]` in Objective-C.
</Callout>

## Next Steps

Now that you've completed the setup, you can start deploying updates:

### Deploy Your First Update

Build and publish an update to your users:

```package-install
npx hot-updater deploy
```

This default command deploys iOS first and Android second. Use `-p ios` or
`-p android` when you want to target only one platform.

Use the interactive mode for guided deployment:

```package-install
npx hot-updater deploy -i
```

For emergency updates with forced reload:

```package-install
npx hot-updater deploy -i -f
```

For staged rollouts, set the initial audience percentage explicitly:

```package-install
npx hot-updater deploy -p ios -r 25
```

### Monitor and Manage Updates

Open the console to track deployments, manage versions, and perform rollbacks:

```package-install
npx hot-updater console
```
