## Complete the setup

This path uses your terminal and provider tools. For an agent to complete the
same workflow, use [Set up with an agent](/docs/guides/ai-agents).
Existing installations should first read
[Move from v0 to v1](/docs/guides/upgrade-to-v1).

The result is a deployed update server, an integrated native app and a verified
OTA update on a dedicated test channel. Follow these steps from the app's
workspace directory.

## Provider Setup

### Step 1: Install hot-updater

Follow [Install packages](/docs/get-started/installation) to install the
`@hot-updater/react-native` SDK, `hot-updater` CLI, your selected build
plugin and provider package. Complete all four package choices before init.

### Step 2: Initialize Your Provider

Run the interactive initializer after installation:

```package-install
npx hot-updater init
```

Select your app's build system and provider. [Choose infrastructure](/docs/get-started/choose-provider)
compares the available paths. The provider guide explains access,
resources, deployment and the exact update server URL:

- [Cloudflare](/docs/managed/cloudflare)
- [Supabase](/docs/managed/supabase)
- [AWS](/docs/managed/aws)
- [Firebase](/docs/managed/firebase)

If you are assembling your own server, use
[Custom server quick start](/docs/custom/quick-start). To deploy packaged server
files through your own tooling, use
[Infrastructure Templates](/docs/guides/infrastructure-templates).

### Step 3: Generated Configuration

Review the setup result:

| Output | What to verify |
| --- | --- |
| `hot-updater.config.ts` | Selected build, storage, database and update strategy |
| `.env.hotupdater` | Local provider settings and registered `HOT_UPDATER_API_KEY`, kept private and ignored |
| Update server base URL | The actual deployed endpoint, including a provider base path when required |
| Remote resources | The selected account/project, database and storage match the local config |

The server URL and **client** API key connect the app to the server.
`.env.hotupdater` is not automatically loaded into the mobile app. Provider,
service-role and admin credentials remain in the CLI/server environment.

Re-running `init` with another provider preserves unrelated config, prior
provider variables and existing infrastructure. Keep old resources until
installed binaries no longer depend on them.

### Step 4: Wrap Your Application

Continue to [Connect your app](/docs/get-started/app-setup). It configures the
client URL/key, app and OTA build variables, build plugin, native loading,
compatibility and test channel.

## Build Configuration

The [build configuration](/docs/get-started/app-setup#build-configuration)
section covers Bare, Rock and Expo. Keep its build setting alongside your
provider's storage and database settings.

## Native Code Setup

Native integration is required before the first Release build. Expo applies the
native changes through its config plugin during prebuild; bare and Rock apps
configure native bundle loading directly.

### Android

Follow the [Android native setup](/docs/get-started/app-setup#android) for your
React Native version and Kotlin or Java project.

### iOS

Follow the [iOS native setup](/docs/get-started/app-setup#ios) for Swift or
Objective-C.

## Next Steps

### Deploy Your First Update

Complete [Test an OTA update](/docs/guides/simulator-test). Use a native Release
build on a dedicated test channel, change visible JavaScript and an asset,
deploy to the matching platform/compatibility target and verify the change on
the device. A successful upload alone does not complete onboarding.

### Monitor and Manage Updates

Open the [Console](/docs/guides/console) and verify received
[Insights](/docs/guides/insights) reports. Insights is enabled by default in the
SDK; its guide explains reporting and opt-out.

### Explore Advanced Features

After the first verified OTA:

- [Deploy updates](/docs/guides/deploy) to the intended production scope.
- [Roll out gradually](/docs/guides/rollout-cohorts) and target QA cohorts.
- [Bundle Signing](/docs/guides/bundle-signing) verifies authorized artifact content.
- [Doctor](/docs/guides/doctor) diagnoses setup and server version issues.
