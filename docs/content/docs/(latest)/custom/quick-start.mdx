## Installation

Install all required dependencies at once.

```package-install
npm install @hot-updater/server @hot-updater/aws hono @hono/node-server kysely better-sqlite3 dotenv
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater @types/better-sqlite3 tsx
```

## Database Setup

Create the database connection file.

```bash
mkdir -p data
```

```typescript title="src/kysely.ts"
import { Kysely, SqliteDialect } from "kysely";
import Database from "better-sqlite3";

export const db = new Kysely({
  dialect: new SqliteDialect({
    database: new Database("./data/database.db"),
  }),
});
```

## Hot Updater Configuration

Create the Hot Updater instance with your database adapter and storage plugin (see [Storage Plugins](./overview#storage-plugins)).

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { kyselyAdapter } from "@hot-updater/server/adapters/kysely";
import { s3Storage } from "@hot-updater/aws";
import { config } from "dotenv";
import { db } from "./kysely";

config({ path: ".env.hotupdater" });

export const hotUpdater = createHotUpdater({
  database: kyselyAdapter({ db, provider: "sqlite" }),
  clientAccess: { type: "api-key" },
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

`createHotUpdater` mounts update-check routes and `/version`. This example uses
the recommended `api-key` policy for update checks and Analytics ingestion.
Admin routes used by the CLI `standaloneRepository` live on a separate handler;
mount that handler only behind framework authentication.

Server Analytics routes are always available. React Native clients decide
whether to send lifecycle events with `HotUpdater.init({ analytics })`.
`clientAccess` is required so the client authentication policy is never
selected implicitly.

## Server Setup

Create the server entry point.

```typescript title="src/index.ts"
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { bearerAuth } from "hono/bearer-auth"; // [!code ++]
import { hotUpdater } from "./hotUpdater"; // [!code ++]

const app = new Hono();

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN; // [!code ++]
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required"); // [!code ++]
} // [!code ++]

app.use(
  "/hot-updater/admin/*", // [!code ++]
  bearerAuth({ token: adminToken }), // [!code ++]
); // [!code ++]
app.mount("/hot-updater/admin", hotUpdater.handlers.admin); // [!code ++]
app.mount("/hot-updater", hotUpdater.handlers.client); // [!code ++]

serve({ fetch: app.fetch, port: 3000 }, (info) => {
  console.log(`Server running at http://localhost:${info.port}`);
});
```

## Security Settings

The recommended self-hosted policy requires an API key for update-check and
Analytics ingestion routes. Always protect admin routes separately before
mounting `handlers.admin`.

Update-check routes are usually exposed for React Native clients, but that is a
deployment choice:

- `/hot-updater/release-catalogs/*`
- `/hot-updater/artifacts/*`

The admin routes under `/hot-updater/admin/*` are used by the CLI. They exist
only where `handlers.admin` is explicitly mounted, and your framework
middleware must protect every request before that mount. The server example
above uses Bearer authentication for `/hot-updater/admin/*`.
Create `.env.hotupdater` with the storage credentials, download URL signing
key, and admin token used by this example:

```bash
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=your-access-key-id
R2_SECRET_ACCESS_KEY=your-secret-access-key
R2_BUCKET_NAME=your-bucket-name
HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY=your-download-url-signing-key
HOT_UPDATER_ADMIN_TOKEN=your-secret-auth-token
```

## Bootstrap the Schema and API Key

Generate and apply the database schema first:

```bash
npx hot-updater db generate src/hotUpdater.ts --yes
npx hot-updater db migrate src/hotUpdater.ts
```

Then create the API key for your mobile app from the same direct
`createHotUpdater` configuration:

```bash
npx hot-updater api-key create src/hotUpdater.ts --name "Mobile app"
```

Copy the plaintext API key from the command output now. Hot Updater persists
only its hash and cannot show the plaintext again.

## Run Server

Start your server.

```bash
npx tsx src/index.ts
```

Your Hot Updater server is now running at `http://localhost:3000/hot-updater`!

## CLI Configuration

Configure your Hot Updater CLI to connect to this self-hosted server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match one entry in the server's
  `createHotUpdater({storage})` array. Both use `s3Storage` here.
</Callout>

## React Native Setup

Configure your React Native app to connect to this server. Use the API key
printed by the bootstrap command above.

```typescript title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "http://localhost:3000/hot-updater", // [!code ++]
  requestHeaders: {
    "x-api-key": "<API key printed by api-key create>", // [!code ++]
  },
  analytics: true,
});
```

The React Native `baseURL` always points to the client root. Never put the
admin bearer token in the app. The API key is scoped to client update and
Analytics ingestion routes and is sent using `x-api-key`.

`HotUpdater.init` initializes the client but does not start an update check.
Call `HotUpdater.checkForUpdate()` when your app is ready; see the
[Custom Update guide](/docs/guides/custom-update) for the complete manual flow.
For automatic HOC-managed checks, pass the same `baseURL` and `requestHeaders`
to `HotUpdater.wrap` together with an `updateStrategy`.

## Unauthenticated Alternative

If you intentionally want client update and Analytics ingestion routes to be
unauthenticated, set `clientAccess: { type: "public" }` and omit `x-api-key`
from React Native `requestHeaders`. This does not make the admin handler public;
its framework authentication remains required.
