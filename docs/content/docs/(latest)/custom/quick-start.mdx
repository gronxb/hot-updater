## What you will build

This guide builds a server with Hono, SQLite and R2 storage,
then connects a React Native app. For an existing backend, use the
[adapter and framework recipes](/docs/custom/overview).

## Before you start

Use separate server and React Native project directories. Install a supported
Node.js version from [Install packages](/docs/get-started/installation), and
prepare an R2 bucket with S3-compatible credentials through your existing
Cloudflare tooling. An agent can discover or create these resources within
your setup request. Keep credentials in ignored local configuration.

The examples use Bare for the React Native build. For Expo or Rock, install
and use the [matching build plugin](/docs/get-started/installation) in that
project before running Hot Updater commands.

## Installation

Install the server dependencies in your server project.

```package-install
npm install @hot-updater/server @hot-updater/aws hono @hono/node-server kysely better-sqlite3 dotenv
```

```package-install
npm install --save-dev hot-updater @types/better-sqlite3 tsx
```

In your React Native project, install the client and CLI dependencies:

```package-install
npm install @hot-updater/react-native
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/aws @hot-updater/standalone hot-updater dotenv
```

## Database setup

Create the database connection file.

```bash
mkdir -p data
```

```typescript title="src/kysely.ts"
import { Kysely, SqliteDialect } from "kysely";
import Database from "better-sqlite3";

export const db = new Kysely({
  dialect: new SqliteDialect({
    database: new Database("./data/database.db"),
  }),
});
```

## Hot Updater configuration

Create the Hot Updater instance with your database adapter and storage plugin (see [Storage Plugins](/docs/custom/overview#storage-plugins)).

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { kyselyAdapter } from "@hot-updater/server/adapters/kysely";
import { s3Storage } from "@hot-updater/aws";
import { config } from "dotenv";
import { db } from "./kysely";

config({ path: ".env.hotupdater" });

export const hotUpdater = createHotUpdater({
  database: kyselyAdapter({ db, provider: "sqlite" }),
  clientAccess: { type: "api-key" },
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

`createHotUpdater` mounts update-check routes and `/version`. This example uses
the recommended `api-key` policy for update checks and Insights ingestion.
Admin routes used by the CLI `standaloneRepository` live on a separate handler;
mount that handler only behind framework authentication.

Server Insights routes are always available. React Native clients send
lifecycle events by default and can opt out with
`HotUpdater.init({ insights: false })`.
`clientAccess` is required so the client authentication policy is never
selected implicitly.

## Server setup

Create the server entry point.

```typescript title="src/index.ts"
import { Hono } from "hono";
import { serve } from "@hono/node-server";
import { bearerAuth } from "hono/bearer-auth"; // [!code ++]
import { hotUpdater } from "./hotUpdater"; // [!code ++]

const app = new Hono();

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

app.use( // [!code ++]
  "/hot-updater/admin/*", // [!code ++]
  bearerAuth({ token: adminToken }), // [!code ++]
); // [!code ++]
app.mount("/hot-updater/admin", hotUpdater.handlers.admin); // [!code ++]
app.mount("/hot-updater", hotUpdater.handlers.client); // [!code ++]

serve({ fetch: app.fetch, port: 3000 }, (info) => {
  console.log(`Server running at http://localhost:${info.port}`);
});
```

## Security settings

The recommended self-hosted policy requires an API key for update-check and
Insights ingestion routes. Always protect admin routes separately before
mounting `handlers.admin`.

Update-check routes are usually exposed for React Native clients, but that is a
deployment choice:

- `/hot-updater/release-catalogs/*`
- `/hot-updater/artifacts/*`

The admin routes under `/hot-updater/admin/*` are used by the CLI. They exist
only where `handlers.admin` is explicitly mounted, and your framework
middleware must protect every request before that mount. The server example
above uses Bearer authentication for `/hot-updater/admin/*`.
Create `.env.hotupdater` with the storage credentials, download URL signing
key, and admin token used by this example. Add this file to `.gitignore`:

```bash
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=your-access-key-id
R2_SECRET_ACCESS_KEY=your-secret-access-key
R2_BUCKET_NAME=your-bucket-name
HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY=your-download-url-signing-key
HOT_UPDATER_ADMIN_TOKEN=your-secret-auth-token
```

## Bootstrap the schema and API key

Generate and apply the database schema first:

```bash
npx hot-updater db generate src/hotUpdater.ts --yes
npx hot-updater db migrate src/hotUpdater.ts
```

Then create the API key for your mobile app from the same direct
`createHotUpdater` configuration:

```bash
npx hot-updater api-key create src/hotUpdater.ts --name "Mobile app"
```

Copy the plaintext API key from the command output now. Hot Updater persists
only its hash and cannot show the plaintext again. Store the key in your
existing React Native build-time configuration, do not commit it to source,
and do not reuse it as an admin credential. The server's `.env.hotupdater` file
is not loaded into the React Native app automatically.

## Run server

Start your server.

```bash
npx tsx src/index.ts
```

The server runs at `http://localhost:3000/hot-updater`.

## CLI configuration

Configure your Hot Updater CLI to connect to this self-hosted server.

Create this configuration in the React Native project. Its `.env.hotupdater`
must contain the same `R2_*` storage values and `HOT_UPDATER_ADMIN_TOKEN` as the
server, and must also be excluded from Git.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match one entry in the server's
  `createHotUpdater({storage})` array. Both use `s3Storage` here.
</Callout>

## React Native setup

Before a release-build OTA test, expose the server through a reachable HTTPS
endpoint using your existing deployment or HTTPS development endpoint. The
local HTTP URL above is suitable for server and CLI smoke checks; do not assume
a mobile release binary permits cleartext HTTP.

Then follow [Set up your app](/docs/get-started/app-setup) to configure the SDK
and native bundle loaders with these values:

| Setting | Value |
| --- | --- |
| Client base URL | Your reachable HTTPS endpoint ending in `/hot-updater` |
| Client header | `x-api-key` |
| Client API key | The key created by `api-key create` above |
| CLI/admin URL | `http://localhost:3000/hot-updater/admin`; keep its bearer token out of the app |

For local connectivity checks, the Android Emulator reaches the host at
`10.0.2.2` and the iOS Simulator on the same Mac can use `localhost`. This only
changes host routing; the release-build OTA test uses the HTTPS endpoint.
The server's `.env.hotupdater` is not loaded into the mobile app automatically.

## Unauthenticated alternative

If you intentionally want client update and Insights ingestion routes to be
unauthenticated, set `clientAccess: { type: "public" }` and omit `x-api-key`
from React Native `requestHeaders`. This does not make the admin handler public;
its framework authentication remains required.

## Verify and deploy

1. [Verify the CLI connection](/docs/custom/cli-configuration#verify-the-connection)
   to the protected admin handler.
2. Deploy with your existing process or the [Docker](/docs/custom/hosting/docker)
   or [Vercel](/docs/custom/hosting/vercel) recipe, or expose your existing HTTPS
   development endpoint. Update the CLI and mobile app to their respective
   verified admin and client URLs.
3. [Test an OTA update](/docs/get-started/test-ota) in a native release build
   against that HTTPS endpoint, including application and restart of the changed code.
