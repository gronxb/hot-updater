## Overview

Your CLI configuration (`hot-updater.config.ts`) connects your React Native project to your self-hosted Hot Updater server. This file defines how bundles are built, stored, and tracked.

## Basic configuration

Install the CLI dependencies in your React Native project:

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/aws @hot-updater/standalone hot-updater dotenv
```

Create `.env.hotupdater` in that project with the server's `R2_*` storage values
and `HOT_UPDATER_ADMIN_TOKEN`, and add it to `.gitignore`. Then create
`hot-updater.config.ts` in the same project root:

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone"; // [!code ++]
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({ // [!code ++]
    baseUrl: "http://localhost:3000/hot-updater/admin", // [!code ++]
    commonHeaders: { // [!code ++]
      Authorization: `Bearer ${adminToken}`, // [!code ++]
    }, // [!code ++]
  }), // [!code ++]
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
The CLI `storage` plugin must match one entry in the server's
`createHotUpdater({ storage })` array.

If the CLI uses `s3Storage`, the server must also use `s3Storage`.

Both sides need the same plugin type and URI configuration to encode and decode
the hierarchical `protocol://bucket/encoded/slash/key` storage URIs correctly.

</Callout>

## Standalone Repository configuration

`baseUrl` is the exact root where the server mounts `handlers.admin`.
`commonHeaders` must match the authentication middleware on that mount. Keep
these values in the CLI's environment; the mobile app connects to the client
root with its own API key.

See the [Standalone Repository reference](/docs/database-plugins/standalone#configuration)
for all options, alternate authentication headers and custom Bundle route
mapping. Release, Release Catalog, commit and Channel paths are fixed.

## API endpoints

The [repository server contract](/docs/database-plugins/standalone#server-contract)
is the canonical request and response reference. `createHotUpdater` implements
it through `handlers.admin`; no handwritten endpoint implementation is needed
when using that server. Protect the admin mount with framework middleware.

## Verify the connection

Run a read-only command from the React Native project:

```bash
npx hot-updater bundle list
```

A successful list, including an empty list for a new installation, verifies
the configured admin URL and credentials. A `401` means the CLI header and
server middleware do not agree. It does not verify the mobile client path.

Then [set up your app](/docs/get-started/app-setup) with the client URL and API
key, and [test an OTA update](/docs/get-started/test-ota) in a release build.
