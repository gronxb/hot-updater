## Overview

Your CLI configuration (`hot-updater.config.ts`) connects your React Native project to your self-hosted Hot Updater server. This file defines how bundles are built, stored, and tracked.

## Basic Configuration

Create a `hot-updater.config.ts` file in your React Native project root:

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { r2Storage } from "@hot-updater/cloudflare";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater",
    commonHeaders: {
      Authorization: `Bearer ${managementToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
**Critical: Storage Plugin Must Match**

The CLI `storage` plugin must match one entry in the server's
`createHotUpdater({ storage })` array.

**CLI uses `r2Storage` → Server must use `r2Storage`**

Both sides need the same plugin type and URI configuration to encode and decode
the hierarchical `protocol://bucket/encoded/slash/key` storage URIs correctly.

</Callout>

## Standalone Repository Configuration

The `standaloneRepository` HTTP repository connects your CLI to your
self-hosted server:

```typescript
interface StandaloneRepositoryConfig {
  baseUrl: string; // Your server URL
  commonHeaders?: Record<string, string>; // Optional headers (e.g., authentication)
  routes?: Routes; // Optional legacy Bundle-route mapping
}
```

`routes` can remap only the five legacy-compatible Bundle create, update, list,
retrieve, and delete requests. Release, Release Catalog, database commit, and
Channel requests use the fixed canonical paths summarized below.

### Basic Example

```typescript
database: standaloneRepository({
  baseUrl: "http://localhost:3000/hot-updater",
});
```

### With Authentication

```typescript
const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

database: standaloneRepository({
  baseUrl: process.env.HOT_UPDATER_SERVER_URL!,
  commonHeaders: {
    Authorization: `Bearer ${managementToken}`,
  },
});
```

### With Custom Bundle Routes

```typescript
database: standaloneRepository({
  baseUrl: "https://api.example.com",
  routes: {
    create: () => ({
      path: "/v1/hot-updater/api/bundles",
      headers: { "X-Custom-Header": "value" },
    }),
    update: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
      headers: { "X-Custom-Header": "value" },
    }),
    list: () => ({
      path: "/v1/hot-updater/api/bundles",
    }),
    retrieve: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
    delete: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
  },
});
```

## API Endpoints

With `features: { updateCheck: true, bundles: true }`,
`@hot-updater/server` mounts the management contract used by
`standaloneRepository`:

| Method | Default endpoint                              | Mapping    | Purpose                              |
| ------ | --------------------------------------------- | ---------- | ------------------------------------ |
| POST   | `/hot-updater/api/bundles`                    | remappable | Create Bundles                       |
| PATCH  | `/hot-updater/api/bundles/:id`                | remappable | Update a Bundle                      |
| GET    | `/hot-updater/api/bundles`                    | remappable | List Bundles                         |
| GET    | `/hot-updater/api/bundles/:id`                | remappable | Retrieve a Bundle                    |
| DELETE | `/hot-updater/api/bundles/:id`                | remappable | Delete a Bundle                      |
| GET    | `/hot-updater/api/releases/:id`               | fixed      | Retrieve a Release                   |
| GET    | `/hot-updater/api/releases`                   | fixed      | List Releases                        |
| GET    | `/hot-updater/api/release-catalogs/:scopeKey` | fixed      | Retrieve a Release Catalog row       |
| GET    | `/hot-updater/api/release-catalogs`           | fixed      | List Release Catalog rows            |
| POST   | `/hot-updater/api/database/commit`            | fixed      | Commit database mutations atomically |
| GET    | `/hot-updater/api/channels`                   | fixed      | List Channels                        |
| POST   | `/hot-updater/api/channels`                   | fixed      | Insert or resolve a Channel          |
| DELETE | `/hot-updater/api/channels/:id`               | fixed      | Delete an unreferenced Channel       |

A Channel referenced by a Release is not empty and cannot be deleted. For the
complete query encoding, request bodies, response envelopes, conflict results,
and fixed Release/Catalog semantics, use the canonical
[Standalone Repository server contract](../database-plugins/standalone#server-contract).
The management routes do not authenticate themselves; protect
`/hot-updater/api/*` before mounting the handler.
