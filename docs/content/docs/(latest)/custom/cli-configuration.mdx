## Overview

Your CLI configuration (`hot-updater.config.ts`) connects your React Native project to your self-hosted Hot Updater server. This file defines how bundles are built, stored, and tracked.

## Basic Configuration

Create a `hot-updater.config.ts` file in your React Native project root:

```typescript title="hot-updater.config.ts"
import { defineConfig } from "@hot-updater/core";
import { bare } from "@hot-updater/bare";
import { r2Storage } from "@hot-updater/cloudflare";
import { standaloneRepository } from "@hot-updater/standalone";

export default defineConfig({
  build: bare(),
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater",
  }),
});
```

<Callout type="warn">
**Critical: Storage Plugin Must Match**

The CLI `storage` plugin must match one entry in the server's
`createHotUpdater({ storage })` array.

**CLI uses `r2Storage` → Server must use `r2Storage`**

Both sides need the same plugin type and URI configuration to encode and decode
the hierarchical `protocol://bucket/encoded/slash/key` storage URIs correctly.

</Callout>

## Standalone Repository Configuration

The `standaloneRepository` HTTP repository connects your CLI to your
self-hosted server:

```typescript
interface StandaloneRepositoryConfig {
  baseUrl: string; // Your server URL
  commonHeaders?: Record<string, string>; // Optional headers (e.g., authentication)
  routes?: Routes; // Optional custom route configuration
}
```

### Basic Example

```typescript
database: standaloneRepository({
  baseUrl: "http://localhost:3000/hot-updater",
});
```

### With Authentication

```typescript
database: standaloneRepository({
  baseUrl: process.env.HOT_UPDATER_SERVER_URL!,
  commonHeaders: {
    Authorization: `Bearer ${process.env.API_TOKEN}`,
  },
});
```

### With Custom Routes

```typescript
database: standaloneRepository({
  baseUrl: "https://api.example.com",
  routes: {
    create: () => ({
      path: "/v1/hot-updater/api/bundles",
      headers: { "X-Custom-Header": "value" },
    }),
    update: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
      headers: { "X-Custom-Header": "value" },
    }),
    list: () => ({
      path: "/v1/hot-updater/api/bundles",
    }),
    retrieve: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
    delete: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
  },
});
```

## API Endpoints

Your server must implement these endpoints (when using default routes):

| Method | Endpoint                        | Description                                                         |
| ------ | ------------------------------- | ------------------------------------------------------------------- |
| POST   | `/hot-updater/api/bundles`      | Create bundles                                                      |
| PATCH  | `/hot-updater/api/bundles/:id`  | Update a bundle                                                     |
| GET    | `/hot-updater/api/bundles`      | List bundles (query: channel, platform, limit, page, after, before) |
| GET    | `/hot-updater/api/bundles/:id`  | Get bundle by ID                                                    |
| DELETE | `/hot-updater/api/bundles/:id`  | Delete bundle                                                       |
| GET    | `/hot-updater/api/channels`     | List all channels                                                   |
| POST   | `/hot-updater/api/channels`     | Insert or resolve a channel                                         |
| DELETE | `/hot-updater/api/channels/:id` | Delete an empty channel                                             |

These endpoints are automatically created when you use `@hot-updater/server` with database adapters.

`GET /hot-updater/api/bundles` should return a `Paginated<Bundle[]>` body
consumed by `standaloneRepository`:

Cursor pagination is the official contract. `page` is an optional positive
integer that keeps page numbers stable for console and standalone repository
requests.

```json
{
  "data": [{ "id": "bundle-id", "channel": "production" }],
  "pagination": {
    "total": 1,
    "hasNextPage": false,
    "hasPreviousPage": false,
    "currentPage": 1,
    "totalPages": 1
  }
}
```

`GET /hot-updater/api/channels` should return normalized Channel rows:

```json
{
  "data": {
    "channels": [
      { "id": "channel-production", "name": "production" },
      { "id": "channel-staging", "name": "staging" }
    ]
  }
}
```

`POST /hot-updater/api/channels` accepts
`{ "row": { "id", "name" }, "onConflict": "returnExisting" }` and returns
`{ "data": { "row": ChannelRow, "inserted": boolean } }`. A name conflict
returns the canonical stored row.

`DELETE /hot-updater/api/channels/:id` returns `204 No Content` on success. A
missing Channel returns `404` with reason `not_found`; a Channel still
referenced by a bundle returns `409` with reason `not_empty`.
