## Overview

`hot-updater.config.ts` holds your React Native project's deploy settings, such
as the build adapter, the update strategy, and signing, and `server`, which
tells the CLI where the server's database, storage, and plugins are. The CLI
never lists them itself:

- `server: "./src/hotUpdater.ts"` points at the
  [server definition](/docs/custom/quick-start#define-the-server), the module
  that exports `hotUpdater` from
  `createHotUpdater({ database, storage, plugins })`. The CLI opens the same
  database, uploads to the first storage, and adds the plugins' commands. Use it
  when the React Native project can import that module, such as in a monorepo.
- `server: standaloneRepository({ baseUrl, commonHeaders, storage })` reaches
  a self-hosted server through its admin API. Use it when the server's code
  lives elsewhere.

A `database`, `storage`, or `plugins` key in `hot-updater.config.ts` stops the
CLI with a message that asks you to move it into the server definition.

## Point at the server definition

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { defineConfig } from "hot-updater";

export default defineConfig({
  build: bare({ enableHermes: true }),
  updateStrategy: "appVersion",
  server: "./src/hotUpdater.ts", // [!code ++]
});
```

- The path is relative to `hot-updater.config.ts`. The module exports
  `hotUpdater`, or a default export, and can export `closeDatabase`, which the
  CLI calls when a command finishes, such as to end a connection pool.
- The CLI loads the module only for the commands that need the server:
  `deploy`, `patch`, the `bundle` commands, `db`, `storage prune`, `console`,
  the plugins' commands, and `doctor`.
- Load the server's environment before the definition reads it, such as with
  `process.loadEnvFile(".env.hotupdater")` at the top of
  `hot-updater.config.ts`.

## Reach a self-hosted server

Install the CLI dependencies in your React Native project:

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/aws @hot-updater/standalone hot-updater
```

Create `.env.hotupdater` in that project with the server's `R2_*` storage values
and `HOT_UPDATER_ADMIN_TOKEN`, and add it to `.gitignore`. Then create
`hot-updater.config.ts` in the same project root:

```typescript title="hot-updater.config.ts"
import { existsSync } from "node:fs";

import { s3Storage } from "@hot-updater/aws";
import { bare } from "@hot-updater/bare";
import { standaloneRepository } from "@hot-updater/standalone"; // [!code ++]
import { defineConfig } from "hot-updater";

if (existsSync(".env.hotupdater")) {
  process.loadEnvFile(".env.hotupdater");
}

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  updateStrategy: "appVersion",
  server: standaloneRepository({ // [!code ++]
    baseUrl: "http://localhost:3000/hot-updater/admin", // [!code ++]
    commonHeaders: { // [!code ++]
      Authorization: `Bearer ${adminToken}`, // [!code ++]
    }, // [!code ++]
    storage: [ // [!code ++]
      s3Storage({ // [!code ++]
        region: "auto", // [!code ++]
        endpoint: process.env.R2_ENDPOINT, // [!code ++]
        credentials: { // [!code ++]
          accessKeyId: process.env.R2_ACCESS_KEY_ID!, // [!code ++]
          secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!, // [!code ++]
        }, // [!code ++]
        bucketName: process.env.R2_BUCKET_NAME!, // [!code ++]
      }), // [!code ++]
    ], // [!code ++]
  }), // [!code ++]
});
```

<Callout type="warn">
`storage` must match the server's `createHotUpdater({ storage })`: the same
adapter, configured with the same bucket and URI settings, so both sides encode
and decode the hierarchical `protocol://bucket/encoded/slash/key` storage URIs
the same way. The CLI uploads to the first adapter.

</Callout>

## Standalone Repository configuration

`baseUrl` is the exact root where the server mounts `handlers.admin`.
`commonHeaders` must match the authentication middleware on that mount. Keep
these values in the CLI's environment; the mobile app connects to the client
root with its own API key. `storage` lists the adapters of the server's bundle
storage: the CLI uploads to the first, and the Console reads and deletes a
bundle's files with the adapter of their protocol.

The routes are the server's admin API, so they cannot be remapped. See the
[Standalone Repository reference](/docs/database-adapters/standalone#configuration)
for alternate authentication headers.

## Server plugins

With `standaloneRepository`, the [server plugins](/docs/custom/server-plugins)
run only on the server, and the CLI and the Console read which ones from the
admin `/version` route; nothing lists them again. The Console reads the server's
Insights overview, events, and installations from its admin handler; App usage,
bundle activity, and API key management need the server definition. A plugin's
commands, such as `hot-updater api-key`, also need the definition: run them in
the server project, or name its path as the command's last argument, as in
[Manage API keys](/docs/custom/api-key-authentication#manage-api-keys).

## API endpoints

The [repository server contract](/docs/database-adapters/standalone#server-contract)
is the canonical request and response reference. `createHotUpdater` implements
it through `handlers.admin`; no handwritten endpoint implementation is needed
when using that server. Protect the admin mount with framework middleware.

## Verify the connection

Run a read-only command from the React Native project:

```bash
npx hot-updater bundle list
```

A successful list, including an empty list for a new installation, verifies
the configured server. With `standaloneRepository`, a `401` means the CLI header
and server middleware do not agree. A `503` means the server's database is not
ready; if it needs migrations, run `hot-updater db migrate` where the server
definition is. A message to upgrade `@hot-updater/server` means the server does
not speak the admin API protocol this CLI needs. A successful list does not
verify the mobile client path.

Then [set up your app](/docs/get-started/app-setup) with the client URL and API
key, and [test an OTA update](/docs/get-started/test-ota) in a release build.
