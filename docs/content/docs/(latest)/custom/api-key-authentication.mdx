description: Protect OTA reads and Analytics writes with the built-in API key domain.

---

API key authentication is built into `createHotUpdater` and uses the official
`database.models.apiKeys` domain. No authentication package or server plugin is
required.

## Terminology

| Surface                                      | Canonical name        |
| -------------------------------------------- | --------------------- |
| User-facing credential and database domain   | API key / `apiKeys`   |
| CLI namespace and `clientAccess` policy type | `api-key`             |
| Default HTTP request header                  | `x-api-key`           |
| Managed AWS environment variable             | `HOT_UPDATER_API_KEY` |

`clientAccess` remains the server setting because it selects how client routes
are accessed. The credential selected by its `api-key` policy is always called
an API key.

```ts
import { createHotUpdater } from "@hot-updater/server";

export const hotUpdater = createHotUpdater({
  database,
  clientAccess: { type: "api-key" },
});
```

The `api-key` policy requires `x-api-key` for update-check routes and
`POST /events`. `/version` stays public. API keys do not grant access to
Analytics queries, admin routes, or API key management.

To use a different header, set it explicitly and send the same header from the
client:

```ts
clientAccess: {
  type: "api-key",
  headerName: "x-hot-updater-key",
}
```

Release Catalog responses include the selected header in `Vary`, so shared
caches keep authenticated responses partitioned by the configured credential
header.

## Bootstrap a self-hosted client

After configuring `createHotUpdater` with the `api-key` policy, apply its schema
and create an API key from the same direct configuration:

```bash
npx hot-updater db migrate src/hotUpdater.ts
npx hot-updater api-key create src/hotUpdater.ts --name "Mobile app"
```

The command prints the plaintext API key exactly once. Store it in your client
configuration and send it using `x-api-key`. Persistence receives only its
SHA-256 hash and non-secret metadata, including its prefix, name, creation time,
and revocation time.

```ts
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "https://example.com/hot-updater",
  requestHeaders: {
    "x-api-key": "<API key printed by api-key create>",
  },
});
```

## Manage API keys

List metadata and revoke a key by ID with:

```bash
npx hot-updater api-key list src/hotUpdater.ts
npx hot-updater api-key revoke <api-key-id> src/hotUpdater.ts
```

The Console uses the same official domain to create, list, and revoke API keys.
`standaloneRepository` proxies Bundle, Release, Release Catalog, Channel, and
commit operations, but it does not proxy API key management.

`createHotUpdater` exposes the same local management API used by the CLI:

```ts
const { apiKey, record } = await hotUpdater.apiKeys.create({
  name: "Mobile app",
});

const records = await hotUpdater.apiKeys.list();
await hotUpdater.apiKeys.revoke({ id: record.id });
```

This is an in-process API backed by the configured direct database plugin. It
does not add API key management routes to `handlers.client` or
`handlers.admin`.

Managed init uses this same API key domain. For example, AWS init registers an
existing `HOT_UPDATER_API_KEY` or creates one, then stores the plaintext only in
the local environment file.

## Rotate an API key

Create a replacement, ship clients configured with the replacement, verify the
rollout, and then revoke the old API key. Revocation takes effect immediately at
the origin; a shared Release Catalog cache can retain an authenticated response
for its configured short TTL.

## Security boundary

An API key embedded in a mobile binary can be extracted. Treat this feature as
an abuse-control boundary for OTA reads and Analytics writes, not as an admin
credential. Protect `handlers.admin`, Console access, and API key management
with your application or framework authentication.

Missing, malformed, unknown, and revoked API keys return `401`. A database
failure during credential lookup returns `503` and does not fall back to public
access.

Client update and Analytics ingestion routes are always available on
`handlers.client`, while Analytics queries live on `handlers.admin`.
`clientAccess` is required and applies its policy to update checks and
Analytics ingestion. It does not authenticate the admin handler.

## Unauthenticated alternative

If you intentionally want client update and Analytics ingestion routes to be
public, use `clientAccess: { type: "public" }` and omit `x-api-key` from the
React Native request headers. Admin handler authentication remains a separate,
required framework boundary.
