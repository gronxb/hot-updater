## Installation

Install Elysia and its bearer token plugin.

```package-install
npm install elysia @elysiajs/bearer
```

## Setup and Security

Set up a [database adapter](../database/drizzle), generate its Hot Updater
schema, and apply the schema before starting the server.

The recommended self-hosted client policy uses built-in API key authentication
for update-check and Analytics ingestion routes. Always protect admin routes with
framework middleware scoped to the admin handler. Update-check
routes are usually exposed for React Native clients, but that is a deployment
choice:

- Client OTA: `/hot-updater/release-catalogs/*`, `/hot-updater/artifacts/*`
- Optional public diagnostics: `/hot-updater/version`
- Protected admin API: `/hot-updater/admin/*`

Mounting `handlers.admin` opts the server into the admin API;
`handlers.client` never serves those routes. This example requires a nonempty
token and scopes the authentication hook to an admin sub-app:

```typescript
import { Elysia } from "elysia";
import { bearer } from "@elysiajs/bearer"; // [!code ++]
import { hotUpdater } from "./hotUpdater"; // [!code ++]

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

const adminApp = new Elysia()
  .use(bearer()) // [!code ++]
  .onBeforeHandle(({ bearer }) => {
    if (bearer !== adminToken) {
      // [!code ++]
      return new Response("Unauthorized", { status: 401 }); // [!code ++]
    } // [!code ++]
  }) // [!code ++]
  .mount("/", hotUpdater.handlers.admin); // [!code ++]

new Elysia()
  .mount("/hot-updater/admin", adminApp) // [!code ++]
  .mount("/hot-updater", hotUpdater.handlers.client) // [!code ++]
  .listen(3000);
```

Set your auth token in environment variables:

```bash
HOT_UPDATER_ADMIN_TOKEN=your-secret-auth-token
```

Configure the CLI to include the auth token when deploying bundles:

```typescript title="hot-updater.config.ts (excerpt)"
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  // ...
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
});
```

## Handler Boundaries

The handlers own these complete route groups. Optional groups exist only when
their feature or storage provider is configured:

| Handler | External route group                      | Purpose                                          |
| ------- | ----------------------------------------- | ------------------------------------------------ |
| Client  | `GET /hot-updater/version`                | Server diagnostics                               |
| Client  | `GET /hot-updater/release-catalogs/*`     | App-version and fingerprint catalogs             |
| Client  | `GET /hot-updater/artifacts/*`            | Artifact resolution                              |
| Client  | `GET /hot-updater/storage/*`              | Optional proxied storage download                |
| Client  | `POST /hot-updater/events`                | Optional Analytics ingestion                     |
| Admin   | `/hot-updater/admin/bundles/*`            | Bundle management and optional Analytics queries |
| Admin   | `/hot-updater/admin/releases/*`           | Release management and preflight                 |
| Admin   | `/hot-updater/admin/release-catalogs/*`   | Catalog rows and rebuilds                        |
| Admin   | `/hot-updater/admin/channels/*`           | Channel management                               |
| Admin   | `POST /hot-updater/admin/database/commit` | Atomic database commit                           |
| Admin   | `GET /hot-updater/admin/installations/*`  | Optional Analytics queries                       |

Admin route groups exist only where `handlers.admin` is explicitly mounted.
See the [Standalone Repository server contract](../../database-plugins/standalone#server-contract)
for the exact admin request and response shapes.

## React Native Setup

Configure your React Native app to connect to this server.

```typescript title="App.tsx"
import { HotUpdater } from '@hot-updater/react-native';

export default HotUpdater.wrap({
  baseURL: 'http://localhost:3000/hot-updater', // [!code ++]
  updateStrategy: 'appVersion', // or "fingerprint" // [!code ++]
  fallbackComponent: ({ progress, status }) => (
    // ... Custom loading UI
  ),
  onError: error => {
    // ... Error handling
  },
})(App);
```
