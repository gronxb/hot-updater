## Installation

Install Prisma and initialize your project.

```package-install
npm install @hot-updater/server @hot-updater/aws @prisma/client@6.19.3
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater prisma@6.19.3
```

Initialize Prisma:

```bash
npx prisma@6.19.3 init --datasource-provider sqlite --generator-provider prisma-client-js
npx prisma generate
```

Generate the initial client before creating `src/prisma.ts`; the Hot Updater
schema command loads that module while preparing the managed models.

For other databases, see [Prisma's database documentation](https://www.prisma.io/docs/orm/overview/databases).

## Setup

Create a database connection file:

```typescript title="src/prisma.ts"
import { PrismaClient } from "@prisma/client";

export const prisma = new PrismaClient();
```

## Hot Updater Configuration

Create the Hot Updater instance:

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { prismaAdapter } from "@hot-updater/server/adapters/prisma";
import { s3Storage } from "@hot-updater/aws";
import { prisma } from "./prisma";

const insightsDatabaseNamespace =
  process.env.HOT_UPDATER_INSIGHTS_DATABASE_NAMESPACE;
if (!insightsDatabaseNamespace) {
  throw new Error("HOT_UPDATER_INSIGHTS_DATABASE_NAMESPACE is required");
}

export const hotUpdater = createHotUpdater({
  database: prismaAdapter({
    insightsDatabaseNamespace,
    prisma,
    provider: "sqlite",
  }),
  clientAccess: { type: "api-key" },
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

Generate one lowercase UUID and store it as
`HOT_UPDATER_INSIGHTS_DATABASE_NAMESPACE` in the server and migration
environment:

```bash
node -e 'console.log(crypto.randomUUID())'
```

Keep this value unchanged for the lifetime of the database. It identifies the
Insights data source, so provisioning and every server deployment must use the
same value.

## Schema Generation

Generate the Prisma schema for Hot Updater tables.

```bash
npx hot-updater db generate src/hotUpdater.ts --yes
```

This command creates `prisma/schema.prisma` when it is missing or merges the
Hot Updater models into the existing schema. Keep the generated models instead
of replacing them with a handwritten schema.

<Callout>
  Need to generate SQL without config? See [SQL
  Export](/docs/custom/database/sql-export) for standalone SQL generation with
  the `--sql` flag.
</Callout>

Regenerate Prisma Client and apply the merged schema:

```bash
npx prisma generate
npx prisma db push
npx hot-updater db migrate src/hotUpdater.ts --yes
```

Run the Hot Updater migration after Prisma applies the generated schema and
before the server starts. This explicit provisioning step installs the
provider-specific Insights layout and validates its database namespace. In
production, run it after `prisma migrate deploy`; in development, run it after
`prisma db push`. When updating an existing database, stop and drain every Hot
Updater event writer before provisioning, then start only servers using the new
schema after provisioning completes. Mixed-version rolling writes are not
supported during this offline cutover.

## Query Semantics

Prisma uses backend collations and pattern engines for string filters. The
adapter therefore rejects explicit insensitive comparisons and pattern values
containing backend metacharacters before querying Prisma. Explicit sensitive
mode is available only for PostgreSQL, CockroachDB, and MongoDB; other
providers reject it instead of silently using their default collation.

## CLI Configuration

Configure your CLI to use this self-hosted server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match one entry in the server's
  `createHotUpdater({storage})` array. Both use `s3Storage` here.
  Mount `handlers.admin` only behind fail-closed framework authentication at
  `/hot-updater/admin/*`. The CLI header above assumes the Bearer middleware from the Quick
  Start.
</Callout>

## API Endpoints

The configuration above enables the update-check routes:

| Method | Endpoint                                                                                        | Description                            |
| ------ | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| GET    | `/hot-updater/version`                                                                          | Get the server version                 |
| GET    | `/hot-updater/release-catalogs/app-version/:platform/:channelKey/:appVersion`                   | Resolve an app-version Release Catalog |
| GET    | `/hot-updater/release-catalogs/fingerprint/:platform/:channelKey/:fingerprintHash`              | Resolve a fingerprint Release Catalog  |
| GET    | `/hot-updater/artifacts/:targetBundleId/from/:currentBundleId`                                  | Resolve an artifact                    |

`handlers.admin` owns the Bundle, Channel, Release, Release Catalog, and
database-commit admin routes under `/hot-updater/admin/*`. See [CLI Configuration](/docs/custom/cli-configuration#api-endpoints) for their complete
request and response contract. These admin routes do not authenticate themselves; keep the fail-closed
framework middleware described above.
