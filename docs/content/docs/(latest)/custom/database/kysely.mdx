## Installation

Install Kysely and SQLite driver.

```package-install
npm install @hot-updater/server @hot-updater/cloudflare hono kysely better-sqlite3
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater @types/better-sqlite3
```

For other databases, see [Kysely's dialect documentation](https://kysely.dev/docs/dialects).

## Setup

Create a database connection file:

```typescript title="src/kysely.ts"
import { Kysely, SqliteDialect } from "kysely";
import Database from "better-sqlite3";

export const db = new Kysely({
  dialect: new SqliteDialect({
    database: new Database("./data/database.db"),
  }),
});
```

## Hot Updater Configuration

Create the Hot Updater instance:

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { kyselyAdapter } from "@hot-updater/server/adapters/kysely";
import { r2Storage } from "@hot-updater/cloudflare";
import { db } from "./kysely";

export const hotUpdater = createHotUpdater({
  database: kyselyAdapter({ db, provider: "sqlite" }),
  storage: [
    r2Storage({
      accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
  basePath: "/hot-updater",
  features: {
    updateCheck: true,
    bundles: true,
  },
});
```

## Schema Management

Generate SQL migration files for Hot Updater tables:

```bash
mkdir -p data
npx hot-updater db generate src/hotUpdater.ts --yes
```

Apply migrations to the database:

```bash
npx hot-updater db migrate src/hotUpdater.ts --yes
```

<Callout>
**Generate vs Migrate**

- `generate` - Creates SQL migration files for manual review before applying to database
- `migrate` - Runs Kysely migrator to directly apply migrations to the database

</Callout>

<Callout>
  Need to generate SQL without config? See [SQL
  Export](/docs/custom/database/sql-export) for standalone SQL generation with
  the `--sql` flag.
</Callout>

## CLI Configuration

Configure your CLI to use this self-hosted server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { r2Storage } from "@hot-updater/cloudflare";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater",
    commonHeaders: {
      Authorization: `Bearer ${managementToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match one entry in the server's
  `createHotUpdater({storage})` array. Both use `r2Storage` here. Because
  `features.bundles` enables management routes, protect `/hot-updater/api/*`
  with fail-closed authentication before mounting the handler. The CLI header
  above assumes the Bearer middleware from the Quick Start.
</Callout>

## Enabled Routes

The configuration above enables the update-check and management groups:

| Method | Endpoint                                                                                        | Description                            |
| ------ | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| GET    | `/hot-updater/version`                                                                          | Get the server version                 |
| GET    | `/hot-updater/release-catalogs/app-version/:authorityId/:platform/:channelKey/:appVersion`      | Resolve an app-version Release Catalog |
| GET    | `/hot-updater/release-catalogs/fingerprint/:authorityId/:platform/:channelKey/:fingerprintHash` | Resolve a fingerprint Release Catalog  |
| GET    | `/hot-updater/artifacts/:targetBundleId/from/:currentBundleId`                                  | Resolve an artifact                    |

`features.bundles: true` also mounts the Bundle, Channel, Release, Release
Catalog, and database-commit management routes under `/hot-updater/api/*`.
See [CLI Configuration](../cli-configuration#api-endpoints) for their complete
request and response contract. These management routes do not authenticate
themselves; keep the fail-closed framework middleware described above.
