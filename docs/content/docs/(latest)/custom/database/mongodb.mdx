## Installation

Install the MongoDB native driver.

```package-install
npm install @hot-updater/server @hot-updater/aws mongodb
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater
```

## Setup

Create a database connection file:

```typescript title="src/mongodb.ts"
import { MongoClient } from "mongodb";

export const client = new MongoClient(process.env.MONGODB_URI!);

// Connect to MongoDB
await client.connect();
```

## Hot Updater Configuration

Create the Hot Updater instance:

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { mongoAdapter } from "@hot-updater/server/adapters/mongodb";
import { s3Storage } from "@hot-updater/aws";
import { client } from "./mongodb";

export const hotUpdater = createHotUpdater({
  database: mongoAdapter({ client, transactions: true }),
  clientAccess: { type: "api-key" },
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

Run MongoDB as a replica set or sharded cluster and set `transactions: true`.
v1 Release and Release Catalog changes must commit atomically. With transactions
disabled, commits with revision expectations or multiple changes are rejected,
so a standalone MongoDB server cannot support the normal v1 deployment workflow.
## Schema Generation

Run the database migration to create the MongoDB collection and indexes.

```bash
npx hot-updater db migrate src/hotUpdater.ts
```

This command targets `src/hotUpdater.ts` and creates all Hot Updater
collections and indexes required by the active database schema. It migrates the
core schema first, then provisions the native Insights source and projections
with bounded, resumable steps.

Stop and drain all Hot Updater event writers before running this command. Start
only servers using the new schema after it completes. Existing event history is
backfilled in place; the migration does not discard or rewrite those events.

## CLI Configuration

Configure your CLI to use this self-hosted server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match a plugin in your server's
  `createHotUpdater({storage})` array. Both use `s3Storage` in this example.
  Mount `handlers.admin` only behind fail-closed framework authentication at
  `/hot-updater/admin/*`. The CLI header above assumes the Bearer middleware from the Quick
  Start.
</Callout>

## API Endpoints

The configuration above enables the update-check routes:

| Method | Endpoint                                                                                        | Description                            |
| ------ | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| GET    | `/hot-updater/version`                                                                          | Get the server version                 |
| GET    | `/hot-updater/release-catalogs/app-version/:platform/:channelKey/:appVersion`                   | Resolve an app-version Release Catalog |
| GET    | `/hot-updater/release-catalogs/fingerprint/:platform/:channelKey/:fingerprintHash`              | Resolve a fingerprint Release Catalog  |
| GET    | `/hot-updater/artifacts/:targetBundleId/from/:currentBundleId`                                  | Resolve an artifact                    |

`handlers.admin` owns the Bundle, Channel, Release, Release Catalog, and
database-commit admin routes under `/hot-updater/admin/*`. See [CLI Configuration](/docs/custom/cli-configuration#api-endpoints) for their complete
request and response contract. These admin routes do not authenticate themselves; keep the fail-closed
framework middleware described above.
