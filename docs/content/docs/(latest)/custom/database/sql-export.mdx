## Overview

Export Hot Updater table schemas as plain SQL files without requiring a config file. Use this when you need standalone SQL for manual database setup.

<Callout>
For ORM-specific schema generation (Drizzle, Prisma, Kysely), see the respective adapter documentation pages.
</Callout>

## Interactive mode

Run the command and select your database:

```bash
npx hot-updater db generate --sql
```

You'll be prompted to select:
- PostgreSQL
- MySQL
- SQLite

These are the supported databases; MySQL must be 8.0 or later. CockroachDB
and SQL Server are not supported.

## Direct provider selection

Specify the database dialect directly:

```bash
# PostgreSQL
npx hot-updater db generate --sql postgresql

# MySQL
npx hot-updater db generate --sql mysql

# SQLite
npx hot-updater db generate --sql sqlite
```

## Output

The command generates one file, `hot-updater.sql`. It reads no server file,
so it is the SQL that `hot-updater db migrate` applies with the Kysely adapter
for a server without [third-party plugins](/docs/custom/server-plugins#create-the-plugins-tables):

- Hot Updater's tables and indexes in your dialect's syntax, with binary
  string collation and no database foreign keys
- The settings table and its schema settings rows, written last

Apply the whole file to a new, empty database. The server checks the settings
rows before its first read or write, and its handlers answer 503 until they
exist, so a partly applied file never serves traffic.

## Preview before saving

Without the `--yes` flag, you'll see a preview before the file is created:

```bash
npx hot-updater db generate --sql postgresql
```

The command will:
1. Generate SQL
2. Show a formatted preview
3. Warn if the file already exists
4. Prompt for confirmation

## Skip confirmation

Use `--yes` to skip confirmation and overwrite existing files. Without a
dialect, `--yes` generates PostgreSQL:

```bash
npx hot-updater db generate --sql postgresql --yes
```

<Callout type="warn">
If `hot-updater.sql` already exists, it will be overwritten. The command shows a warning before overwriting.
</Callout>
