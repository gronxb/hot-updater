## Overview

Export Hot Updater table schemas as plain SQL files for manual database setup. The command generates the SQL without a database connection, but it loads your server config to find its plugins.

<Callout>
For ORM-specific schema generation (Drizzle, Prisma, Kysely), see the respective adapter documentation pages.
</Callout>

## Interactive mode

Run the command and select your database:

```bash
npx hot-updater db generate --sql
```

You'll be prompted to select:
- PostgreSQL
- MySQL
- SQLite

These are the supported databases; MySQL must be 8.0.17 or later. CockroachDB
and SQL Server are not supported.

## Direct provider selection

Specify the database dialect directly:

```bash
# PostgreSQL
npx hot-updater db generate --sql postgresql

# MySQL
npx hot-updater db generate --sql mysql

# SQLite
npx hot-updater db generate --sql sqlite
```

## Plugins' tables

The SQL holds core's tables and those of the
[plugins](/docs/custom/server-plugins#create-the-plugins-tables) your server
runs, such as `insights()` and `apiKeys()`. The command finds the plugin list
as plugin commands do: in the server config you name, then in
`hotUpdater.plugins.ts`, then in a default server config such as
`src/hotUpdater.ts`:

```bash
npx hot-updater db generate src/hotUpdater.ts --sql postgresql
```

It names the file it read the plugins from. Without one, it says so and
generates core's tables only. The command imports that file as your server
does, so a config that opens a database when it is imported, such as a PGlite
client that creates its data directory, does so here too.

## Output

The command generates one file, `hot-updater.sql`: the SQL that
`hot-updater db migrate` applies with the Kysely adapter for the same plugins.

- The tables and indexes of core and the plugins in your dialect's syntax,
  with binary string collation and no database foreign keys
- The settings table and its schema settings rows, `schema.engine`,
  `schema.core`, and one per plugin, written last

Apply the whole file to a new, empty database. The server checks the settings
rows before its first read or write, and its handlers answer 503 until they
exist, so a partly applied file never serves traffic.

## Preview before saving

Without the `--yes` flag, you'll see a preview before the file is created:

```bash
npx hot-updater db generate --sql postgresql
```

The command will:
1. Generate SQL
2. Show a formatted preview
3. Warn if the file already exists
4. Prompt for confirmation

## Skip confirmation

Use `--yes` to skip confirmation and overwrite existing files. Without a
dialect, `--yes` generates PostgreSQL:

```bash
npx hot-updater db generate --sql postgresql --yes
```

<Callout type="warn">
If `hot-updater.sql` already exists, it will be overwritten. The command shows a warning before overwriting.
</Callout>
