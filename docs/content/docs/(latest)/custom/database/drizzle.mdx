## Installation

Install Drizzle ORM and SQLite driver.

```package-install
npm install @hot-updater/server @hot-updater/aws drizzle-orm better-sqlite3
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater drizzle-kit @types/better-sqlite3
```

For other databases, see [Drizzle's adapter documentation](https://orm.drizzle.team/docs/get-started).

## Setup

Create a database connection file:

```typescript title="src/drizzle.ts"
import { drizzle } from "drizzle-orm/better-sqlite3";
import Database from "better-sqlite3";
import * as schema from "../hot-updater-schema";

const sqlite = new Database("./data/database.db");
export const db = drizzle(sqlite, { schema });
```

## Hot Updater Configuration

Create the Hot Updater instance:

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { drizzleAdapter } from "@hot-updater/server/adapters/drizzle";
import { s3Storage } from "@hot-updater/aws";
import { db } from "./drizzle";

export const hotUpdater = createHotUpdater({
  database: drizzleAdapter({ db, provider: "sqlite" }),
  clientAccess: { type: "public" },
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

## Schema Generation

Generate the Drizzle schema for Hot Updater tables.

```bash
mkdir -p data
npx hot-updater db generate src/hotUpdater.ts --yes
```

This command writes `hot-updater-schema.ts` at the project root. The generator
can bootstrap the missing import shown above on its first run.

Point Drizzle Kit at the generated file and the same SQLite database:

```typescript title="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./hot-updater-schema.ts",
  out: "./drizzle",
  dialect: "sqlite",
  dbCredentials: {
    url: "./data/database.db",
  },
});
```

Apply the schema before starting the server:

```bash
npx drizzle-kit push
```

<Callout>
  Need to generate SQL without config? See [SQL
  Export](/docs/custom/database/sql-export) for standalone SQL generation with
  the `--sql` flag.
</Callout>

## CLI Configuration

Configure your CLI to use this self-hosted server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { s3Storage } from "@hot-updater/aws";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const adminToken = process.env.HOT_UPDATER_ADMIN_TOKEN;
if (!adminToken) {
  throw new Error("HOT_UPDATER_ADMIN_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage({
    region: "auto",
    endpoint: process.env.R2_ENDPOINT,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater/admin",
    commonHeaders: {
      Authorization: `Bearer ${adminToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  The CLI `storage` plugin must match a plugin in your server's
  `createHotUpdater({storage})` array. Both use `s3Storage` in this example.
  Mount `handlers.admin` only behind fail-closed framework authentication at
  `/hot-updater/admin/*`. The CLI header above assumes the Bearer middleware from the Quick
  Start.
</Callout>

## API Endpoints

The configuration above enables the update-check routes:

| Method | Endpoint                                                                                        | Description                            |
| ------ | ----------------------------------------------------------------------------------------------- | -------------------------------------- |
| GET    | `/hot-updater/version`                                                                          | Get the server version                 |
| GET    | `/hot-updater/release-catalogs/app-version/:authorityId/:platform/:channelKey/:appVersion`      | Resolve an app-version Release Catalog |
| GET    | `/hot-updater/release-catalogs/fingerprint/:authorityId/:platform/:channelKey/:fingerprintHash` | Resolve a fingerprint Release Catalog  |
| GET    | `/hot-updater/artifacts/:targetBundleId/from/:currentBundleId`                                  | Resolve an artifact                    |

`handlers.admin` owns the Bundle, Channel, Release, Release Catalog, and
database-commit admin routes under `/hot-updater/admin/*`. See [CLI Configuration](../cli-configuration#api-endpoints) for their complete
request and response contract. These admin routes do not authenticate themselves; keep the fail-closed
framework middleware described above.
