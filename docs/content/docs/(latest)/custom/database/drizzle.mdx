## Before you start

Use this recipe in the server project from the [custom-server quick start](/docs/custom/quick-start)
or your existing backend. Make the database and storage environment variables
available to the server and schema commands. The React Native project's deploy
configuration is a separate step.

`drizzleAdapter` supports PostgreSQL, MySQL 8.0 or later, and SQLite, through
these Drizzle drivers:

| Database   | Drivers                                                  |
| ---------- | -------------------------------------------------------- |
| PostgreSQL | node-postgres, postgres-js, PGlite, Neon over WebSockets |
| MySQL      | mysql2                                                   |
| SQLite     | libSQL, better-sqlite3, bun:sqlite                       |

Hot Updater runs every write in an interactive transaction. On first use, the
adapter checks that the driver can run one and throws
`DrizzleTransactionUnsupportedError` for a driver that cannot, such as Neon
over HTTP. CockroachDB and SQL Server are not supported.

## Installation

Install Drizzle ORM and SQLite driver.

```package-install
npm install @hot-updater/server @hot-updater/aws drizzle-orm better-sqlite3
```

```package-install
npm install --save-dev hot-updater drizzle-kit @types/better-sqlite3
```

For other databases, see [Drizzle's adapter documentation](https://orm.drizzle.team/docs/get-started).

## Setup

Create a database connection file:

```typescript title="src/drizzle.ts"
import { drizzle } from "drizzle-orm/better-sqlite3";
import Database from "better-sqlite3";

const sqlite = new Database("./data/database.db");
export const db = drizzle(sqlite);
```

Hot Updater reads and writes through SQL, so the Drizzle instance does not
need Hot Updater's schema.

## Hot Updater configuration

Create the Hot Updater instance:

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { drizzleAdapter } from "@hot-updater/server/adapters/drizzle"; // [!code ++]
import { apiKeys } from "@hot-updater/server/plugins/api-keys";
import { insights } from "@hot-updater/server/plugins/insights";
import { s3Storage } from "@hot-updater/aws";
import { db } from "./drizzle";

export const hotUpdater = createHotUpdater({
  database: drizzleAdapter({ db, provider: "sqlite" }), // [!code ++]
  plugins: [insights(), apiKeys()],
  storage: [
    s3Storage({
      region: "auto",
      endpoint: process.env.R2_ENDPOINT,
      credentials: {
        accessKeyId: process.env.R2_ACCESS_KEY_ID!,
        secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
      },
      bucketName: process.env.R2_BUCKET_NAME!,
      downloadUrlSigningKey: process.env.HOT_UPDATER_STORAGE_DOWNLOAD_URL_KEY!,
    }),
  ],
});
```

`drizzleAdapter` takes `db`, a Drizzle database or a function that returns
one on first use, and `provider`: `"postgresql"`, `"mysql"` or `"sqlite"`,
matching the driver. Its `schema` option is accepted and ignored. It returns
an engine database with the schema generator and migrator that
`hot-updater db` runs. On
better-sqlite3 and bun:sqlite, which run synchronously, the adapter runs one
statement at a time and begins each transaction with `BEGIN IMMEDIATE`.
`insights()` records app events, and `apiKeys()` protects the client routes
with the `x-api-key` header.

## Schema generation

Generate the Drizzle schema for Hot Updater tables.

```bash
mkdir -p data
npx hot-updater db generate src/hotUpdater.ts --yes
```

This command writes `hot-updater-schema.ts` at the project root: every table,
key and index, with each column typed exactly as Hot Updater's SQL schema
declares it, and no foreign keys. The tables include those of the server's
[third-party plugins](/docs/custom/server-plugins#create-the-plugins-tables).

Point Drizzle Kit at the generated file and the same SQLite database. If your
config already lists schema files, add `./hot-updater-schema.ts` to its
`schema` array:

```typescript title="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./hot-updater-schema.ts", // [!code ++]
  out: "./drizzle",
  dialect: "sqlite",
  dbCredentials: {
    url: "./data/database.db",
  },
});
```

Apply the schema, then write the schema settings, before starting the server:

```bash
npx drizzle-kit push
npx hot-updater db migrate src/hotUpdater.ts --yes
```

Drizzle Kit creates the tables. `db migrate` then writes only the settings
rows. It asks you to apply the tables first when they are missing, and it
refuses a database created by an older Hot Updater schema instead of
converting it. The server checks the settings rows before its first read or
write; until they exist, it throws `HotUpdaterSchemaMigrationRequiredError`
and its handlers answer 503. A running server checks again on its next
request. Run all three commands again after upgrading Hot Updater.

<Callout>
  Need to generate SQL without config? See [SQL
  Export](/docs/custom/database/sql-export) for standalone SQL generation with
  the `--sql` flag.
</Callout>

## CLI configuration

After the schema is applied, [create the client API key](/docs/custom/api-key-authentication#bootstrap-a-self-hosted-client)
using this same direct server configuration. Then
[connect the React Native project's CLI](/docs/custom/cli-configuration) to the
protected admin mount. Its storage configuration must match a server entry.

## API endpoints

The adapter persists data; your framework mounts the HTTP handlers. Continue
with the [Hono](/docs/custom/frameworks/hono), [Express](/docs/custom/frameworks/express)
or [Elysia](/docs/custom/frameworks/elysia) recipe. See the
[handler boundaries](/docs/custom/overview#runtime-policy) and
[repository contract](/docs/database-plugins/standalone#server-contract) for
client and admin access.

Finish with [Set up your app](/docs/get-started/app-setup) and
[Test an OTA update](/docs/get-started/test-ota).
