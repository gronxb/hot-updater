## Installation

```package-install
npm install @hot-updater/expo --save-dev
```

## Configuration

```typescript
interface ExpoPluginConfig {
  outDir?: string;      // Output directory (default: "dist")
  sourcemap?: boolean;  // Generate sourcemaps (default: false)
  resetCache?: boolean; // Reset Metro cache before bundling (default: true)
}
```

## Usage

```typescript title="hot-updater.config.ts"
import { expo } from '@hot-updater/expo'; // [!code ++]
import { defineConfig } from 'hot-updater';

export default defineConfig({
  build: expo({ // [!code ++]
    sourcemap: false // [!code ++]
  }), // [!code ++]
  // ... other config
});
```

## Expo configuration

The `@hot-updater/expo` package also provides the Expo config plugin. Add it to
your `app.json` file:

```jsonc title="app.json"
{
  "expo": {
    "plugins": [
      [ // [!code ++]
        "@hot-updater/expo", // [!code ++]
        { // [!code ++]
          "channel": "production" // [!code ++]
        } // [!code ++]
      ] // [!code ++]
    ]
  }
}
```

The app config plugin accepts these options:

| Option | Purpose |
| --- | --- |
| `channel` | Native update channel. Defaults to `production`. |
| `publicKeyPath` | Optional path to the signing public key, relative to the Expo project root. Required when bundle signing is enabled. |

For signed updates, add `publicKeyPath: "./keys/public-key.pem"` to this app
plugin's options. It requires an RSA SPKI PEM public key of at least 2048 bits.
Prebuild reads only this public file, embeds it in both native apps, and
includes it in their fingerprints. It does not need the private key or KMS
credentials. Configure the signer separately in `hot-updater.config.ts`.

See [Expo and EAS signing setup](/docs/guides/bundle-signing#expo-and-eas-build)
for exporting the public file and releasing the matching native app.

Run prebuild to apply the changes:

```package-install
npx expo prebuild
```

## Expo DOM Components (`use dom`)

Expo DOM components are designed for EAS Update. Hot Updater uses `overrideUri` internally (via Babel plugin) to redirect DOM components to the correct bundle path.

### Babel plugin

Add the Babel plugin when you use Expo DOM components, including on Expo SDK 55+:

```package-install
npx expo customize babel.config.js
```

```js title="babel.config.js"
module.exports = function (api) {
  api.cache(true);

  return {
    presets: ['babel-preset-expo'],
    plugins: [
      '@hot-updater/expo/babel-plugin', // [!code ++]
    ],
  };
};
```

### Persist changes

Use patch-package, yarn patch, or pnpm patch to persist these changes across installs.

Using patch-package:

```package-install
npm install patch-package --save-dev
```

```bash
npx patch-package expo
```

Add a postinstall script:

```jsonc title="package.json"
{
  "scripts": {
    "postinstall": "patch-package" // [!code ++]
  }
}
```

Using pnpm patch:

```bash
pnpm patch expo
# Make the changes above, then:
pnpm patch-commit <path-shown-in-output>
```

Using yarn patch:

```bash
yarn patch expo
# Make the changes above, then follow yarn's instructions
```

The Babel plugin handles `overrideUri` for all DOM components without further code changes.

## Key features

- Uses Expo's `expo export:embed` command
- Auto-detects Hermes from app.json configuration
- Supports both managed and bare Expo workflows
- Compatible with Expo prebuild for native builds
- Automatically configures bundler based on Expo settings
