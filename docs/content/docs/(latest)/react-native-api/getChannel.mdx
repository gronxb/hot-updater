By default, if no channel is specified, the app is assigned to the `production` channel.

For build-time setup, refer to
[Default Channel Setup](/docs/guides/channel-management). For runtime switching,
see [Runtime Channel Switch](/docs/guides/runtime-channel-switch).

## Usage

You can use `HotUpdater.getChannel()` to dynamically check which channel the app is currently using.

### Example

```tsx
import { HotUpdater } from "@hot-updater/react-native";
import { Text, View } from "react-native";

export default function App() {
  const channel = HotUpdater.getChannel();

  return (
    <View>
      <Text>Current Channel: {channel}</Text>
    </View>
  );
}
```

## Behavior

- If no runtime channel switch is active, `HotUpdater.getChannel()` returns the build-time channel.
- If a bundle from another channel has been applied at runtime, `HotUpdater.getChannel()` returns that switched channel.
- If no channel is configured, the default is `production`.
- The build-time default channel is written into native project files by
  [`hot-updater channel set`](/docs/guides/channel-management).
- Use [`HotUpdater.getDefaultChannel()`](/docs/react-native-api/getDefaultChannel) when you need the embedded default channel regardless of runtime channel switch state.
- You can restore the original channel with [`HotUpdater.resetChannel()`](/docs/react-native-api/resetChannel).

## Runtime Example

After configuring [`HotUpdater.init`](/docs/react-native-api/init), check and
apply a transition to another channel as part of your
[custom update flow](/docs/guides/custom-update):

```tsx
const updateInfo = await HotUpdater.checkForUpdate({
  updateStrategy: "appVersion",
  channel: "beta",
});

if (updateInfo) {
  const didUpdate = await updateInfo.updateBundle();
  if (didUpdate) {
    await HotUpdater.reload();
  }
}
```
