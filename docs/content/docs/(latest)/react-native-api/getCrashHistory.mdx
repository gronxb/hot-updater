## Usage

Use `hotUpdater.getCrashHistory()` in a support log or debug screen to inspect
artifacts that crashed and triggered automatic rollback.

```tsx
import { hotUpdater } from "./hotUpdater";

const crashedArtifacts = hotUpdater.getCrashHistory();
console.log("Rejected artifact IDs:", crashedArtifacts);
```

## Return value

```ts
getCrashHistory(): string[]
```

Each value matches the Console's Advanced **Artifact ID**. It is not the update
ID returned by [`getBundleId()`](/docs/react-native-api/getBundleId). An empty
array means the device has no recorded crashed artifacts.

The getter is synchronous and reads local history without making a network
request. Recorded artifacts are rejected if the device attempts to install
them again. [`clearCrashHistory()`](/docs/react-native-api/clearCrashHistory)
clears that rejection history for a controlled retry.

The list also holds an artifact whose launch ended before the first render,
until a later session retries it once. See
[automatic rollback](/docs/concepts/automatic-rollback#what-counts-as-a-failed-launch).

It also holds up to 10 artifacts whose download failed verification in the
last 24 hours: a file or manifest whose hash or signature fails, or that can't
be decoded. The device doesn't download such an artifact again during those 24
hours. After that, it can be selected again, since a proxy or a cut-off
download can make good files fail. Network and HTTP errors are retried as
usual. These artifacts never count as crashes, and installing another native
build clears them.

Native bundle loading starts crash detection. Configure
[`init`](/docs/react-native-api/init) to observe the completed launch through
`onNotifyAppReady` and client plugins. See
[automatic rollback](/docs/concepts/automatic-rollback) for the recovery
lifecycle.
