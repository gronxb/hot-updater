Use the pre-filled `updateBundle()` helper returned by `checkForUpdate()`. It
resolves the protocol v1 manifest artifact, stages the selected transition, and
does not reload the currently running React Native runtime.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "<your-update-server-url>",
  requestHeaders: { "x-api-key": "<client-api-key>" },
  onError: (error) => console.error("Hot Updater:", error),
});

async function stageAppUpdate() {
  const updateInfo = await HotUpdater.checkForUpdate({
    updateStrategy: "appVersion",
  });

  if (!updateInfo) return;

  const didUpdate = await updateInfo.updateBundle();
  if (didUpdate && updateInfo.shouldForceUpdate) {
    await HotUpdater.reload();
  }
}
```

## Direct parameters

Most apps should not construct these parameters. The selected update helper
supplies them after resolving the artifact endpoint.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `bundleId` | `string` | Yes | Target artifact ID. |
| `status` | `"UPDATE" \| "ROLLBACK"` | Yes | Transition direction. |
| `manifestUrl` | `string` | Yes | Target manifest URL. |
| `manifestFileHash` | `string` | Yes | SHA256 hash or `sig:<base64_signature>` for the manifest. |
| `assets` | `Record<string, ArtifactAsset>` | Yes | Original descriptor for every target file, with optional Hermes patches. |
| `channel` | `string` | No | Channel committed with the staged selection. |
| `selection` | `object \| null` | No | Release Catalog selection receipt. |

The runtime downloads and verifies the manifest, then resolves each target path
in this order: current OTA file, matching built-in file, optional Hermes patch,
and complete original file. A patch failure falls back to the original file.
The staged directory is committed atomically only after every target hash is
verified.

`updateBundle` never reloads the app by itself. Call `HotUpdater.reload()` to
start the staged transition immediately. The automatic `HotUpdater.wrap` flow
handles force updates separately.

For built-in or embedded Catalog transitions, use the helper returned by
`checkForUpdate()`; those transitions do not require a fabricated manifest
request.
