## Usage

Use `updateBundle` to stage the selected transition, downloading and verifying
a bundle when needed. Normally, call the pre-filled helper returned by
`checkForUpdate()`. The function does not reload the React Native runtime
currently in use.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "<your-update-server-url>",
  requestHeaders: {
    "x-api-key": "<client-api-key>",
  },
  onError: (error) => console.error("Hot Updater:", error),
});

async function stageAppUpdate() {
  try {
    const updateInfo = await HotUpdater.checkForUpdate({
      updateStrategy: "appVersion", // or "fingerprint"
    });

    if (!updateInfo) {
      return;
    }

    // Recommended: let the helper resolve the artifact and stage the selection.
    const didUpdate = await updateInfo.updateBundle();

    if (!didUpdate) {
      console.warn("Update transition was not staged");
      return;
    }

    console.log("Bundle transition staged successfully");

    if (updateInfo.shouldForceUpdate) {
      await HotUpdater.reload();
    }
  } catch (error) {
    console.error("Failed to stage update:", error);
  }
}
```

## Parameters

The `updateBundle` function accepts the following parameters:

| Parameter  | Type                     | Required | Description                                       |
| ---------- | ------------------------ | -------- | ------------------------------------------------- |
| `bundleId` | `string`                 | ✅       | Unique identifier of the update bundle.           |
| `fileUrl`  | `string \| null`         | ✅       | Bundle archive URL, or `null` to reset to the built-in bundle. |
| `fileHash` | `string \| null`         | ✅       | SHA256 hash or `sig:<base64_signature>` for downloads; `null` for a built-in reset. |
| `status`   | `"UPDATE" \| "ROLLBACK"` | ✅       | Update transition to apply.                       |

Passing `fileUrl: null` resets to the built-in bundle; it does not roll back to
the OTA bundle named by `bundleId`. For a catalog-selected rollback, call the
returned `updateInfo.updateBundle()` helper so the selected release and artifact
are preserved.

### Behavior

- Downloads the specified bundle when `fileUrl` is not `null`.
- A download with a missing or empty `fileHash` is rejected.
- Without a configured signing public key, verifies a hexadecimal SHA256 hash
  and rejects signed artifacts. With a configured public key, requires a `sig:`
  RSA-SHA256 signature and rejects unsigned artifacts. A failed verification
  aborts the update and deletes the download. See
  [bundle signing](/docs/guides/bundle-signing) for key configuration.
- A `null` URL resets the native bundle selection to the built-in bundle and
  runs downloaded-bundle cleanup. The nullable properties must still be present
  in the object.
- Stages the selected bundle transition for the next React Native runtime start
  without replacing the code already running.
- Never reloads the app by itself. Call `HotUpdater.reload()` explicitly to
  start the staged transition immediately; the automatic `HotUpdater.wrap` flow
  handles force updates separately.
- An in-progress download is not guaranteed to finish after the app is
  force-quit.

### Security Recommendation

Use `updateInfo.updateBundle()` to resolve the artifact and pass its verification
hash to the native updater. The `fileUrl` and `fileHash` fields returned by
`checkForUpdate()` are `null` and must not be copied into a direct call.
A plain SHA256 hash checks integrity but does not authenticate the publisher;
a `sig:` value also verifies publisher authenticity with the configured public key.

#### Recommended Approach

Use `updateInfo.updateBundle()` whenever possible. The helper resolves the
artifact when needed and preserves the complete update context selected by
`checkForUpdate()` without manual copying.

```tsx
const updateInfo = await HotUpdater.checkForUpdate({
  updateStrategy: "appVersion",
});

if (updateInfo) {
  await updateInfo.updateBundle();
}
```
