## Usage

`HotUpdater.checkForUpdate()` uses the `baseURL` or custom `resolver` already
configured by [`HotUpdater.wrap()`](/docs/react-native-api/wrap) or
[`HotUpdater.init()`](/docs/react-native-api/init). The update source cannot be
overridden per check.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "<your-update-server-url>",
  authorityId: "<your-authority-id>",
});

async function checkForAppUpdate() {
  const updateInfo = await HotUpdater.checkForUpdate({
    updateStrategy: "appVersion",
    channel: "production",
    requestHeaders: {
      Authorization: "Bearer <your-access-token>",
    },
  });

  if (!updateInfo) {
    console.log("App is up to date");
    return;
  }

  const didUpdate = await updateInfo.updateBundle();
  if (didUpdate && updateInfo.shouldForceUpdate) {
    await HotUpdater.reload();
  }
}
```

Use the returned `updateInfo.updateBundle()` function for the selected
transition. It carries the Release Catalog receipt, channel switch, artifact
resolution, hashes, manifest diff, and rollback values required by that exact
check.

## Options

`checkForUpdate` accepts `CheckForUpdateOptions`:

| Option           | Type                            | Required | Description                                                                                |
| ---------------- | ------------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `updateStrategy` | `"appVersion" \| "fingerprint"` | Yes      | Strategy used for this check. It may override the strategy configured by `wrap`.           |
| `channel`        | `string`                        | No       | Channel to check. A new runtime channel is persisted only after `updateBundle()` succeeds. |
| `requestHeaders` | `Record<string, string>`        | No       | Headers merged over the headers configured by `wrap` or `init`.                            |
| `requestTimeout` | `number`                        | No       | Request timeout in milliseconds. Defaults to `5000`.                                       |
| `onError`        | `(error: Error) => void`        | No       | Per-check error callback. It overrides the configured callback for this check.             |

After a runtime channel switch has been applied, checking a different explicit
channel requires [`HotUpdater.resetChannel()`](/docs/react-native-api/resetChannel)
first.

## Return value

The function returns `Promise<CheckForUpdateResult | null>`. `null` means no
applicable transition was returned. Handled validation or transport failures
also invoke `onError` and return `null`. An available result contains the
following fields:

| Field                | Type                                                | Description                                                                                              |
| -------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `id`                 | `string`                                            | Target Bundle ID.                                                                                        |
| `status`             | `"UPDATE" \| "ROLLBACK"`                            | Direction of the Bundle transition.                                                                      |
| `shouldForceUpdate`  | `boolean`                                           | Whether the app should reload as soon as the transition is applied.                                      |
| `message`            | `string \| null`                                    | Optional message associated with the Release.                                                            |
| `fileUrl`            | `string \| null`                                    | Archive URL when it is already resolved. It can be `null` for rollback and catalog-selected transitions. |
| `fileHash`           | `string \| null`                                    | Archive hash or embedded signature when it is already resolved.                                          |
| `rolloutCohortCount` | `number \| null \| undefined`                       | Numeric rollout size when supplied by policy.                                                            |
| `targetCohorts`      | `string[] \| null \| undefined`                     | Additional rollout cohorts when supplied by policy.                                                      |
| `manifestUrl`        | `string \| null \| undefined`                       | Optional manifest artifact URL.                                                                          |
| `manifestFileHash`   | `string \| null \| undefined`                       | Optional manifest hash or embedded signature.                                                            |
| `changedAssets`      | `Record<string, ChangedAsset> \| null \| undefined` | Manifest-relative assets to download, reuse, or patch.                                                   |
| `releaseId`          | `string \| null \| undefined`                       | Selected Release ID. Latest only.                                                                        |
| `transitionKind`     | `ReleaseTransitionKind \| undefined`                | `"INSTALL"`, `"ADOPT_RELEASE"`, `"USE_EMBEDDED"`, or `"USE_BUILTIN"`. Latest only.                       |
| `updateBundle`       | `() => Promise<boolean>`                            | Applies this exact transition with all required values pre-filled.                                       |

`fileUrl` and `fileHash` are intentionally not enough to reconstruct every
latest transition. For example, an `INSTALL` selected from a Release Catalog
resolves its artifact inside `updateInfo.updateBundle()`, while
`ADOPT_RELEASE`, `USE_EMBEDDED`, and `USE_BUILTIN` may only commit selection
state. Prefer the callable result over manually forwarding fields to
`HotUpdater.updateBundle()`.

## How it works

The default resolver fetches a shared Release Catalog, evaluates it on the
device, and resolves the selected artifact when it is needed:

- App version catalog: `GET {baseURL}/release-catalogs/app-version/:authorityId/:platform/:channelKey/:appVersion`
- Fingerprint catalog: `GET {baseURL}/release-catalogs/fingerprint/:authorityId/:platform/:channelKey/:fingerprintHash`
- Artifact resolution: `GET {baseURL}/artifacts/:targetBundleId/from/:currentBundleId`

`:channelKey` is the base64url-encoded channel name. `authorityId` defaults to
`default` unless it is configured with `baseURL` or provided by a custom
resolver.
