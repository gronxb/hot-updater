## Prerequisites

Before you begin, make sure the following are ready:

- **Node.js**: Version 20.19 or later is required; Node 22 is recommended.
- **Supabase CLI**: Install it via `npx supabase`.
- **Supabase Account**: Sign up at [Supabase](https://supabase.com) if you don't have one.

Docker or OrbStack is needed only when you choose to run Supabase locally; the
managed remote init flow does not require a local container runtime.

## Step 1: Install Required Packages

Run the following command to install dependencies:

```package-install
npm install hot-updater --save-dev
```

## Step 2: Configure Supabase

Run the initialization script to start the interactive setup process. Use the following command with your preferred package manager:

```package-install
npx -y supabase login
npx hot-updater init
```

<Accordions type="single">
  <Accordion title="Interactive Setup Steps">

1. **Select a Build Plugin**: Choose a build plugin for your project (e.g., Bare (React Native CLI) for React Native).
2. **Select a Provider**: Select Supabase as the provider for handling updates.

During the setup, you will be prompted to:

1. **Select a Supabase Organization**: Select an existing organization. If none exists, create one in the Supabase Dashboard before running init.
2. **Create or Select a Project**: Choose an existing project or create a new one within the selected organization.
3. **Configure Storage**: Select a bucket or create a new private bucket. Init asks before converting a selected public bucket to private.
4. **Database Migration**: Apply the generated migrations to the selected project.
5. **Deploy Edge Function**: Deploy a Supabase Edge Function called `update-server`.

  </Accordion>
</Accordions>

Once setup is complete, `.env.hotupdater` may include the following values.
Project and function selections are persisted for deterministic reruns.
Personal access tokens and database passwords are included only when needed and
when you consent to persistence; project-creation inputs appear only when a
project is created.

```
HOT_UPDATER_SUPABASE_PROJECT_ID=your-project-id
HOT_UPDATER_SUPABASE_FUNCTION_NAME=update-server
HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY=your-service-role-or-secret-key
HOT_UPDATER_SUPABASE_BUCKET_NAME=your-bucket-name
HOT_UPDATER_SUPABASE_URL=https://your-project-id.supabase.co
# Conditional credentials/create-only values may include:
SUPABASE_ACCESS_TOKEN=your-personal-access-token
HOT_UPDATER_SUPABASE_DB_PASSWORD=your-database-password
HOT_UPDATER_SUPABASE_PROJECT_NAME=your-new-project-name
HOT_UPDATER_SUPABASE_ORGANIZATION_SLUG=your-organization-slug
HOT_UPDATER_SUPABASE_REGION=your-region
```

<Callout type="warn">

If you're **not** using the `react-native-dotenv` solution, provider credentials from `.env.hotupdater` will not be included in your app bundle. However, if you're still concerned,

please refer to the article below for more details:
[Security](/docs/policy/security#plugin-token-protection)

</Callout>

## Step 3: Generated Configurations

During the initialization process, the following file is automatically generated:

- `hot-updater.config.ts`: This file contains the configuration settings for integrating Supabase with your project.

```ts title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { supabaseDatabase, supabaseStorage } from "@hot-updater/supabase";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

export default defineConfig({
  authorityId: "your-project-id",
  build: bare({ enableHermes: true }),
  updateStrategy: "appVersion",
  storage: supabaseStorage({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey: process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
    bucketName: process.env.HOT_UPDATER_SUPABASE_BUCKET_NAME!,
  }),
  database: supabaseDatabase({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey: process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
  }),
});
```

Keep the generated `authorityId` unchanged. Managed Supabase uses the project
reference as the Release Catalog authority.

The generated Supabase migrations enable Row Level Security on Hot Updater
tables and keep direct table/function access limited to the service role used by
the CLI and deployed Edge Function.

### Upgrade and rollback

Managed Supabase does not upgrade a v0 schema in place. Init checks for the v1
Release Catalog schema before changing bucket privacy, applying migrations, or
deploying the Edge Function. A schema with v0 Bundles but no Release Catalogs
is rejected without mutation. Create a new Supabase project for v1 and ship its
Edge Function endpoint in a new native build. Keep the v0 project available
for installed v0 binaries that still need OTA service.

### Release catalog cache

Supabase officially uses the direct Edge Function URL in `origin-only` mode.
`hot-updater init` generates that URL in the React Native configuration, and
`hot-updater doctor --server-base-url <direct-edge-url>` reports the mode as a
healthy informational status.

The request still benefits from the Release Catalog architecture: the Edge
Function serves an already compiled catalog, coalesces concurrent cold reads,
and performs one exact catalog-row read on an in-process cache miss instead of
running per-install rollout decisions. However, Supabase does not document a
reusable response cache in front of Function execution, so every device check
still invokes the Edge Function. Supabase origin-only measurements must report
Edge Function invocations and Postgres reads separately and must not be
presented as shared-CDN hit metrics.

## Step 4: Add HotUpdater to Your Project

The HotUpdater component wraps your application, enabling seamless delivery of updates and fallback UI during updates. Follow these steps to integrate it into your App.tsx:

```tsx title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";
import { Text, View } from "react-native";

function App() {
  return (
    <View>
      <Text>Hello World</Text>
    </View>
  );
}

export default HotUpdater.wrap({
  baseURL: "https://<project-ref>.supabase.co/functions/v1/<function-name>", // [!code ++]
  authorityId: "your-project-id", // [!code ++]
  updateStrategy: "appVersion", // or "fingerprint" // [!code ++]
  requestHeaders: {
    // if you want to use the request headers, you can add them here
  },
  fallbackComponent: ({ progress, status }) => (
    <View
      style={{
        flex: 1,
        padding: 20,
        borderRadius: 10,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "rgba(0, 0, 0, 0.5)",
      }}
    >
      {/* You can put a splash image here. */}

      <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
        {status === "UPDATING" ? "Updating..." : "Checking for Update..."}
      </Text>
      {progress > 0 ? (
        <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
          {Math.round(progress * 100)}%
        </Text>
      ) : null}
    </View>
  ),
})(App);
```

<Callout type="info">
The managed Supabase runtime exposes public update checks, Analytics event
ingestion, and `/version`. Internally, it enables
`features: { updateCheck: true, bundles: false, analytics: true }`.
Analytics query routes stay protected, and bundle management routes are not
mounted on the public Edge Function URL.
</Callout>

## Step 5: If You Use Expo, Add the Config Plugin

Add the plugin to your `app.json` file as shown below:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "@hot-updater/react-native",
        {
          "channel": "production"
        }
      ]
    ]
  }
}
```

```package-install
npx expo prebuild
```

<Callout>
  This process automatically generates the code that needs to be added in Step
  6. Skip this step if you are using bare or Rock.
</Callout>

<Callout type="info">
  If you use Expo DOM components (`use dom`), see the [Expo DOM Components (`use
  dom`)](/docs/build-plugins/expo#expo-dom-components-use-dom) section for the
  additional Babel plugin setup.
</Callout>

## Step 6: Add Native Code

For Bare and Rock projects, follow the version-specific Android and iOS
instructions in [Native Code Setup](/docs/get-started/basic-usage#native-code-setup). The canonical guide separates
current React Native template generations and preserves Metro in debug builds.
Expo projects that ran `expo prebuild` with the config plugin do not need manual
native edits.

## Verifying the Setup

1. Check your Supabase dashboard for the newly created bucket and edge function.
2. Test the HotUpdater integration in your React Native app.

You're all set! 🎉 Start using hot-updater with Supabase for seamless updates in your React Native app.

This document simplifies the initialization process, making it easy for developers to get started with minimal friction.
