## Prerequisites

Before you begin, make sure the following are ready:

- **Node.js**: Version 20.19 or later is required; Node 22 is recommended.
- **Cloudflare Account**: Sign up at [Cloudflare](https://cloudflare.com) if you don't have one.
- **Cloudflare D1 API Token**: Create an API Token at https://dash.cloudflare.com/{your-account-id}/api-tokens with **D1 Edit** permission.

## Step 1: Install Required Packages

Run the following command to install dependencies:

```package-install
npm install hot-updater --save-dev
```

## Step 2: Configure Cloudflare

Run the initialization script to start the interactive setup process. Use the following command with your preferred package manager:

```package-install
npx hot-updater init
```

<Accordions type="single">
  <Accordion title="Interactive Setup Steps">

1. **Select a Build Plugin**: Choose a build plugin for your project (e.g., Bare (React Native CLI) for React Native).
2. **Select a Provider**: Select Cloudflare as the provider for handling updates.

During the setup, you will be prompted to:

1. **Login to Cloudflare**: Sign in to your Cloudflare account with wrangler
2. **Enter D1 API Token**: Input your API token with D1 Edit permission.
3. **Select R2 Bucket**: Choose an existing R2 bucket or create a new one
4. **Choose R2 Privacy**: Decide whether the managed R2 domain is private (the default) or public
5. **Set Up R2 API Credentials**: Enter existing Access Key ID and Secret Access Key values
6. **Select D1 Database**: Choose an existing D1 database or create a new one
7. **Run D1 Migration**: Execute database migrations for D1
8. **Deploy Worker**: Deploy the Cloudflare Worker for update management

  </Accordion>
</Accordions>

Once setup is complete, `.env.hotupdater` may include the following values.
Resource names, IDs, and R2 privacy are always persisted for deterministic
reruns. API and R2 credentials are persisted only when you consent.

```
HOT_UPDATER_CLOUDFLARE_ACCOUNT_ID=your-account-id
HOT_UPDATER_CLOUDFLARE_R2_BUCKET_NAME=your-r2-bucket-name
HOT_UPDATER_CLOUDFLARE_R2_PRIVATE=true
HOT_UPDATER_CLOUDFLARE_D1_DATABASE_ID=your-d1-database-id
HOT_UPDATER_CLOUDFLARE_D1_DATABASE_NAME=your-d1-database-name
HOT_UPDATER_CLOUDFLARE_WORKER_NAME=your-worker-name
# Included only when credential persistence is approved:
HOT_UPDATER_CLOUDFLARE_API_TOKEN=your-api-token
HOT_UPDATER_CLOUDFLARE_R2_ACCESS_KEY_ID=your-r2-access-key-id
HOT_UPDATER_CLOUDFLARE_R2_SECRET_ACCESS_KEY=your-r2-secret-access-key
```

<Callout type="warn">

If you're **not** using the `react-native-dotenv` solution, provider credentials from `.env.hotupdater` will not be included in your app bundle. However, if you're still concerned,

please refer to the article below for more details:
[Security](/docs/policy/security#plugin-token-protection)

</Callout>

## Step 3: Generated Configurations

During the initialization process, the following file is automatically generated:

- `hot-updater.config.ts`: This file contains the configuration settings for integrating Cloudflare with your project.

```ts title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { d1Database, r2Storage } from "@hot-updater/cloudflare";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

export default defineConfig({
  authorityId: "your-d1-database-id",
  build: bare({ enableHermes: true }),
  updateStrategy: "appVersion",
  storage: r2Storage({
    bucketName: process.env.HOT_UPDATER_CLOUDFLARE_R2_BUCKET_NAME!,
    accountId: process.env.HOT_UPDATER_CLOUDFLARE_ACCOUNT_ID!,
    credentials: {
      accessKeyId: process.env.HOT_UPDATER_CLOUDFLARE_R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.HOT_UPDATER_CLOUDFLARE_R2_SECRET_ACCESS_KEY!,
    },
  }),
  database: d1Database({
    databaseId: process.env.HOT_UPDATER_CLOUDFLARE_D1_DATABASE_ID!,
    accountId: process.env.HOT_UPDATER_CLOUDFLARE_ACCOUNT_ID!,
    cloudflareApiToken: process.env.HOT_UPDATER_CLOUDFLARE_API_TOKEN!,
  }),
});
```

Keep the generated `authorityId` unchanged. Managed Cloudflare uses the D1
database ID as the Release Catalog authority. The persisted
`HOT_UPDATER_CLOUDFLARE_R2_PRIVATE` value replays the privacy choice on later
non-interactive init runs.

### Upgrade and rollback

Managed Cloudflare does not upgrade a v0 D1 database in place. Init checks for
the v1 Release Catalog schema before applying migrations or deploying the
Worker. When it detects v0 Bundle policy, it stops without changing D1. Create
a new D1 database, R2 bucket, and Worker for v1, then ship the new endpoint in a
new native build. Keep the v0 Worker and database available for installed v0
binaries that still need OTA service.

### Release catalog cache

The generated Worker configuration uses Wrangler `4.69.0` or newer, a current
compatibility date, and:

```json
{
  "cache": { "enabled": true }
}
```

This is Cloudflare's cache in front of Worker execution, not
`caches.default` inside the Worker. Successful catalog responses use a
five-second shared TTL and vary by `x-api-key` and content encoding. Confirm
`CF-Cache-Status: HIT` when validating a warm request; response headers alone
do not prove that Worker and D1 execution were skipped.

## Step 4: Add HotUpdater to Your Project

The HotUpdater component wraps your application, enabling seamless delivery of updates and fallback UI during updates. Follow these steps to integrate it into your App.tsx:

```tsx title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";
import { Text, View } from "react-native";

function App() {
  return (
    <View>
      <Text>Hello World</Text>
    </View>
  );
}

export default HotUpdater.wrap({
  baseURL: "https://<your-worker-name>.<your-subdomain>.workers.dev", // [!code ++]
  authorityId: "your-d1-database-id", // [!code ++]
  updateStrategy: "appVersion", // or "fingerprint" // [!code ++]
  requestHeaders: {
    // if you want to use the request headers, you can add them here
  },
  fallbackComponent: ({ progress, status }) => (
    <View
      style={{
        flex: 1,
        padding: 20,
        borderRadius: 10,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "rgba(0, 0, 0, 0.5)",
      }}
    >
      {/* You can put a splash image here. */}

      <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
        {status === "UPDATING" ? "Updating..." : "Checking for Update..."}
      </Text>
      {progress > 0 ? (
        <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
          {Math.round(progress * 100)}%
        </Text>
      ) : null}
    </View>
  ),
})(App);
```

<Callout type="info">
The managed Cloudflare runtime exposes public update checks, Analytics event
ingestion, and `/version`. Internally, it enables
`features: { updateCheck: true, bundles: false, analytics: true }`.
Analytics query routes stay protected, and bundle management routes are not
mounted on the public worker URL.
</Callout>

## Step 5: If You Use Expo, Add the Config Plugin

Add the plugin to your `app.json` file as shown below:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "@hot-updater/react-native",
        {
          "channel": "production"
        }
      ]
    ]
  }
}
```

```package-install
npx expo prebuild
```

<Callout>
  This process automatically generates the code that needs to be added in Step
  6. Skip this step if you are using bare or Rock.
</Callout>

<Callout type="info">
  If you use Expo DOM components (`use dom`), see the [Expo DOM Components (`use
  dom`)](/docs/build-plugins/expo#expo-dom-components-use-dom) section for the
  additional Babel plugin setup.
</Callout>

## Step 6: Add Native Code

For Bare and Rock projects, follow the version-specific Android and iOS
instructions in [Native Code Setup](/docs/get-started/basic-usage#native-code-setup). The canonical guide separates
current React Native template generations and preserves Metro in debug builds.
Expo projects that ran `expo prebuild` with the config plugin do not need manual
native edits.

## Verifying the Setup

1. Check your Cloudflare dashboard for the newly created bucket, D1 database, and worker.
2. Test the HotUpdater integration in your React Native app.

You're all set! 🎉 Start using hot-updater with Cloudflare for seamless updates in your React Native app.

This document simplifies the initialization process, making it easy for developers to get started with minimal friction.
