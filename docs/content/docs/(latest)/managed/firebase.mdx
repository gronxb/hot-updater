## Prerequisites

Before you begin, make sure the following are ready:

- **Node.js**: Version 20.19 or later is required; Node 22 is recommended.
- **Firebase Project**: Create a new project at [Firebase](https://firebase.google.com) if you don’t have one.
- **Google Cloud CLI**: Install `gcloud` and authenticate the account that owns the Firebase project.
- **Firebase Storage**: Enable Storage so the project has its canonical default `.firebasestorage.app` or `.appspot.com` bucket.
- **Firestore**: Create a new firestore database at [Firebase](https://firebase.google.com) if you don’t have one.

## Step 1: Install Required Packages

Run the following command to install dependencies:

```package-install
npm install hot-updater --save-dev
npm install @hot-updater/react-native
```

## Step 2: Configure Firebase

Run the initialization script to start the interactive setup process. Use the following command with your preferred package manager:

```package-install
npx hot-updater init
```

<Accordions type="single">
  <Accordion title="Interactive Setup Steps">

1. **Select a Build Plugin**: Choose a build plugin for your project (e.g., Bare (React Native CLI) for React Native).
2. **Select a Provider**: Select Firebase as the provider for handling updates.

During the setup, you will be prompted to:

1. **Create or Select a Firebase Project**: Choose an existing project or create a new one.
2. **Verify Storage**: Init locates the selected project's canonical default bucket and stops if Storage has not been enabled.
3. **Deploy Firestore Indexes**: Deploy the indexes used to store and query updates.
4. **Provision API Key**: Create the first client API key or reuse the saved key.
5. **Deploy Functions**: Deploy a Firebase Function v2 called `hot-updater`.
6. **Add IAM Policy**: Add a new IAM policy to the service account of the function.

  </Accordion>
</Accordions>

Once setup is complete, `.env.hotupdater` may include the following values. The
project, region, and canonical bucket are persisted for deterministic reruns.
The service-account path is included only when configured and approved for
persistence.

```
HOT_UPDATER_FIREBASE_PROJECT_ID=your-project-id
HOT_UPDATER_FIREBASE_REGION=your-functions-region
HOT_UPDATER_FIREBASE_STORAGE_BUCKET=your-bucket-name
HOT_UPDATER_API_KEY=your-api-key
# Project Settings > Service Accounts > New Private Key > Download JSON
GOOGLE_APPLICATION_CREDENTIALS=your-credentials.json
```

Managed init reuses `HOT_UPDATER_API_KEY` when supplied or creates an API key,
registers it in Firestore, and persists the plaintext value locally. Send this
API key in the app's `x-api-key` request header. Do not run
`hot-updater api-key create` for a managed installation.

<Callout type="warn">

Provider credentials from `.env.hotupdater` are not included in your app bundle
unless you explicitly configure that behavior. The API key is the exception:
add `HOT_UPDATER_API_KEY` to your React Native build-time configuration as
shown below, but never add the Firebase service-account credential.

For more details, see:
[Security](/docs/policy/security#plugin-token-protection)

</Callout>

## Optional: Bundle Signing

Managed Firebase init does not create or enable a signing key. After
provisioning the OTA infrastructure, configure the official
[Google Cloud KMS signer](/docs/guides/bundle-signing#firebase-projects-google-cloud-kms),
embed its public key in a native release, and only then deploy signed bundles.
Signing credentials belong in the deploy environment, never in the React
Native app.

## Step 3: Add HotUpdater to Your Project

Configure the endpoint and API key once, then check when your app is ready.
Replace the API-key placeholder with your existing React Native build-time
configuration value. Do not paste the plaintext key into App.tsx and commit it.

```tsx title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";
import { useEffect } from "react";
import { Text, View } from "react-native";

HotUpdater.init({
  baseURL: "https://<project-id>.web.app", // [!code ++]
  requestHeaders: {
    "x-api-key": "<HOT_UPDATER_API_KEY from .env.hotupdater>", // [!code ++]
  },
});

function App() {
  useEffect(() => {
    void HotUpdater.checkForUpdate({ updateStrategy: "appVersion" })
      .then(async (updateInfo) => {
        if (!updateInfo) return;
        await updateInfo.updateBundle();
        if (updateInfo.shouldForceUpdate) await HotUpdater.reload();
      })
      .catch(console.error);
  }, []);

  return (
    <View>
      <Text>Hello World</Text>
    </View>
  );
}

export default App;
```

<Callout type="info">
  The managed Firebase runtime exposes `/version` publicly. OTA update checks
  and Analytics ingestion require `x-api-key: $HOT_UPDATER_API_KEY`. Internally,
  it enables Analytics and mounts only `handlers.client`. Admin routes,
  including Analytics queries, are not mounted on the public Hosting URL.
</Callout>

## Generated Configuration and Operations

During the initialization process, the following file is automatically generated:

- `hot-updater.config.ts`: This file contains the configuration settings for integrating Firebase with your project.
- `.env.hotupdater`: **IMPORTANT**:
  Make sure to set the `GOOGLE_APPLICATION_CREDENTIALS` environment variable to the path of your downloaded Firebase credentials JSON file.
  This is critical for Firebase authentication to work properly.
  For more details, see: https://firebase.google.com/docs/admin/setup?hl=en#initialize_the_sdk_in_non-google_environments

```bash title=".env.hotupdater"
HOT_UPDATER_FIREBASE_PROJECT_ID=your-project-id
HOT_UPDATER_FIREBASE_REGION=your-functions-region
HOT_UPDATER_FIREBASE_STORAGE_BUCKET=your-bucket-name
HOT_UPDATER_API_KEY=your-api-key
# Project Settings > Service Accounts > New Private Key > Download JSON
GOOGLE_APPLICATION_CREDENTIALS=your-credentials.json
```

```ts title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { firebaseStorage, firebaseDatabase } from "@hot-updater/firebase";
import { applicationDefault } from "firebase-admin/app";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

// https://firebase.google.com/docs/admin/setup?hl=en#initialize_the_sdk_in_non-google_environments
// Check your .env.hotupdater file and add the credentials
// Set the GOOGLE_APPLICATION_CREDENTIALS environment variable to your credentials file path
// Example: GOOGLE_APPLICATION_CREDENTIALS=./firebase-adminsdk-credentials.json
const credential = applicationDefault();

export default defineConfig({
  authorityId: "your-project-id",
  build: bare({
    enableHermes: true,
  }),
  updateStrategy: "appVersion",
  storage: firebaseStorage({
    projectId: process.env.HOT_UPDATER_FIREBASE_PROJECT_ID!,
    storageBucket: process.env.HOT_UPDATER_FIREBASE_STORAGE_BUCKET!,
    credential,
  }),
  database: firebaseDatabase({
    projectId: process.env.HOT_UPDATER_FIREBASE_PROJECT_ID!,
    credential,
  }),
});
```

Keep the generated `authorityId` unchanged. Managed Firebase uses the Firebase
project ID as the Release Catalog authority.

### Upgrade and rollback

Managed Firebase does not upgrade v0 Firestore data in place. Init inspects the
adapter marker and Hot Updater collections before deploying. A v0 marker or an
unversioned database containing Hot Updater data is rejected without mutation.
Use a new Firebase project for v1 and ship its Hosting endpoint in a new native
build. Keep the v0 project available for installed v0 binaries that still need
OTA service.

### Release catalog cache

Init deploys Firebase Hosting rewrites for `/version`, `/release-catalogs/**`,
`/artifacts/**`, and `/events`
in front of the `hot-updater` Function. Use the Hosting domain as the base URL
so successful catalog responses can be served by Firebase's
global CDN without invoking the Function or reading Firestore. The response's
five-second `s-maxage` and `Vary: Accept-Encoding, x-api-key` define freshness
and authentication partitioning. Errors are `private, no-store`.

Do not use the direct Cloud Functions URL when validating the shared-cache
profile; it proves Function correctness but bypasses Firebase Hosting.

## Step 4: If You Use Expo, Add the Config Plugin

Add the plugin to your `app.json` file as shown below:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "@hot-updater/expo",
        {
          "channel": "production"
        }
      ]
    ]
  }
}
```

```package-install
npx expo prebuild
```

  6. Skip this step if you are using bare or Rock.

import android.app.Application;
import com.facebook.react.PackageList;
import com.facebook.react.ReactApplication;

public class MainApplication extends Application implements ReactApplication {

      new DefaultReactNativeHost(this) {

          return BuildConfig.DEBUG;
        }

        @Override
        protected List<ReactPackage> getPackages() {
          @SuppressWarnings("UnnecessaryLocalVariable")
          List<ReactPackage> packages = new PackageList(this).getPackages();
          // Packages that cannot be autolinked yet can be added manually here, for example:
          return packages;
        }

        @Override
        protected String getJSMainModuleName() {
          return "index";
        }

        @Override // [!code ++]
        protected String getJSBundleFile() {  // [!code ++]

                ? null  // [!code ++]

        @Override
        protected boolean isNewArchEnabled() {
          return BuildConfig.IS_NEW_ARCHITECTURE_ENABLED;
        }

        @Override
        protected Boolean isHermesEnabled() {
          return BuildConfig.IS_HERMES_ENABLED;
        }
      };

  @Override
  public ReactNativeHost getReactNativeHost() {
    return mReactNativeHost;

  @Override

    super.onCreate();
    SoLoader.init(this, /* native exopackage */ false);

      DefaultNewArchitectureEntryPoint.load();
    }
    ReactNativeFlipper.initializeFlipper(this, getReactNativeHost().getReactInstanceManager());
  }
}

1. Check your Firebase dashboard for the newly created firebase function.
