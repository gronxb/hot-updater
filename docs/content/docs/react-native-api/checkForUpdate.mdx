## Usage

Configure Hot Updater once with `HotUpdater.wrap()` or `HotUpdater.init()`, then
pass an update strategy for each check. The check reuses the configured
`baseURL` or `resolver`.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "<your-update-server-url>",
});

async function checkForAppUpdate() {
  const updateInfo = await HotUpdater.checkForUpdate({
    updateStrategy: "appVersion",
    requestHeaders: {
      Authorization: "Bearer <your-access-token>",
    },
  });

  if (!updateInfo) {
    return;
  }

  const didDownload = await updateInfo.updateBundle();
  if (didDownload && updateInfo.shouldForceUpdate) {
    await HotUpdater.reload();
  }
}
```

Calling `checkForUpdate()` before `wrap()` or `init()` throws because no update
source has been configured.

## `CheckForUpdateOptions`

`HotUpdater.checkForUpdate()` accepts these options:

| Property         | Type                            | Required | Description                                                                          |
| ---------------- | ------------------------------- | -------- | ------------------------------------------------------------------------------------ |
| `updateStrategy` | `"appVersion" \| "fingerprint"` | Yes      | Strategy used for this check; it can override the strategy configured by `wrap()`    |
| `channel`        | `string`                        | No       | Channel to check. A runtime switch is persisted only after `updateBundle()` succeeds |
| `requestHeaders` | `Record<string, string>`        | No       | Headers merged over the headers configured by `wrap()` or `init()`                   |
| `onError`        | `(error: Error) => void`        | No       | Handler for an error from this check; it overrides the configured handler            |
| `requestTimeout` | `number`                        | No       | Request timeout in milliseconds; defaults to the configured value or 5000            |

If a runtime channel override is already active, checking a different explicit
channel throws. Call `HotUpdater.resetChannel()` first.

## `CheckForUpdateResult`

The function resolves to `CheckForUpdateResult | null`. `null` means there is
no applicable update, the server returned `UP_TO_DATE`, or the check could not
produce an update. An available result has the following fields:

| Property             | Type                                   | Required | Description                                                                                                                   |
| -------------------- | -------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `id`                 | `string`                               | Yes      | Bundle ID returned by the update server                                                                                       |
| `shouldForceUpdate`  | `boolean`                              | Yes      | Whether the app should reload immediately after download                                                                      |
| `message`            | `string \| null`                       | Yes      | Optional message associated with the update                                                                                   |
| `status`             | `"ROLLBACK" \| "UPDATE"`               | Yes      | Operation the client should apply                                                                                             |
| `fileUrl`            | `string \| null`                       | Yes      | Archive URL, or `null` for a rollback without an archive                                                                      |
| `fileHash`           | `string \| null`                       | Yes      | Archive hash or `sig:<base64_signature>` value used for verification                                                          |
| `rolloutCohortCount` | `number \| null`                       | No       | Numeric rollout size from 0 through 1000                                                                                      |
| `targetCohorts`      | `string[] \| null`                     | No       | Compatibility field inherited from the core update type; standard servers use it internally and omit it from client responses |
| `manifestUrl`        | `string \| null`                       | No       | Manifest URL for a manifest-driven update                                                                                     |
| `manifestFileHash`   | `string \| null`                       | No       | Manifest hash or signature used for verification                                                                              |
| `changedAssets`      | `Record<string, ChangedAsset> \| null` | No       | Changed-file descriptors used to download or patch a manifest diff                                                            |
| `updateBundle`       | `() => Promise<boolean>`               | Yes      | Downloads or applies this result with all required values pre-filled                                                          |

The `updateBundle` function is added by the React Native client; it is not a
JSON field returned by the server. Prefer it over manually copying result fields
into `HotUpdater.updateBundle()` because it also preserves runtime-channel and
manifest-diff context.

## Channel Override

Pass `channel` to check another channel. The override is not persisted by the
check itself; it becomes active only after the returned update is successfully
applied.

```tsx
const updateInfo = await HotUpdater.checkForUpdate({
  channel: "beta",
  updateStrategy: "fingerprint",
});

if (updateInfo) {
  await updateInfo.updateBundle();
}
```

## Default Resolver Requests

With `baseURL`, the default resolver requests one of these paths and appends
the device cohort:

- `GET {baseURL}/app-version/:platform/:appVersion/:channel/:minBundleId/:bundleId/:cohort`
- `GET {baseURL}/fingerprint/:platform/:fingerprintHash/:channel/:minBundleId/:bundleId/:cohort`

A custom `resolver` receives the same runtime values through its
`checkUpdate()` parameters and can use a different transport.
