## Recommended Usage

Prefer the `updateBundle()` helper returned by
[`HotUpdater.checkForUpdate()`](/docs/react-native-api/checkForUpdate). It
pre-fills the required archive, verification, manifest-diff, rollback, and
runtime-channel values from that specific check.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

const updateInfo = await HotUpdater.checkForUpdate({
  updateStrategy: "appVersion",
});

if (updateInfo) {
  const didApply = await updateInfo.updateBundle();
  if (didApply && updateInfo.shouldForceUpdate) {
    await HotUpdater.reload();
  }
}
```

## Direct Usage

Use `HotUpdater.updateBundle(params)` only when you already have a complete
current update object. All four required properties must be present, including
nullable `fileUrl` and `fileHash` values.

```tsx
const updateInfo = await HotUpdater.checkForUpdate({
  updateStrategy: "appVersion",
});

if (updateInfo) {
  await HotUpdater.updateBundle({
    bundleId: updateInfo.id,
    fileUrl: updateInfo.fileUrl,
    fileHash: updateInfo.fileHash,
    status: updateInfo.status,
    manifestUrl: updateInfo.manifestUrl ?? null,
    manifestFileHash: updateInfo.manifestFileHash ?? null,
    changedAssets: updateInfo.changedAssets ?? null,
  });
}
```

When checking a different runtime channel, use the result helper instead. The
helper retains the target channel that is not otherwise part of the public
update response.

## `UpdateParams`

| Property                         | Type                     | Required | Description                                                                                     |
| -------------------------------- | ------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `bundleId`                       | `string`                 | Yes      | Bundle ID to install or roll back to                                                            |
| `fileUrl`                        | `string \| null`         | Yes      | Archive URL; use `null` when the operation has no archive                                       |
| `fileHash`                       | `string \| null`         | Yes      | Archive hash or signature; use `null` only when the operation has no archive verification value |
| `status`                         | `"ROLLBACK" \| "UPDATE"` | Yes      | Update operation to apply                                                                       |
| `channel`                        | `string`                 | No       | Runtime channel to persist after a successful installation                                      |
| `manifestUrl`                    | `string \| null`         | No       | Manifest URL for a manifest-driven installation                                                 |
| `manifestFileHash`               | `string \| null`         | No       | Hash or signature for the manifest file                                                         |
| `changedAssets`                  | `object \| null`         | No       | Changed-file descriptors for a manifest diff                                                    |
| `shouldSkipCurrentBundleIdCheck` | `boolean`                | No       | Allows a first runtime-channel switch to install an older bundle ID; normally leave this unset  |

The promise resolves to `true` when native installation succeeds and `false`
when native reports an unsuccessful operation. Download, validation, and
storage failures reject with a Hot Updater error.

## Verification

For archive updates, `fileHash` can contain either a SHA-256 hash or a
`sig:<base64_signature>` value. Do not discard a non-null value returned by the
server: native uses it to reject corrupted or untrusted downloads. Manifest
updates similarly use `manifestFileHash` and the hashes inside
`changedAssets`.
