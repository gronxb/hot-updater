## Prerequisites

Before you begin, make sure the following are ready:

- **Node.js**: Version 22 is recommended (20.19 or later is required).
- **AWS Account**: Sign up at [AWS](https://aws.amazon.com) if you don't have one.
- **AWS CLI**: Install the AWS CLI and sign in or configure a profile.

## Required AWS Permissions

Hot Updater requires specific AWS IAM permissions for setup and ongoing usage:

### 1. Initialization (One-Time Setup)

Used for `hot-updater init`:

- `AmazonS3FullAccess`: Create and read S3 buckets.
- `AWSLambda_FullAccess`: Create and update Lambda functions.
- `CloudFrontFullAccess`: Manage CloudFront distributions.
- `IAMFullAccess`: Create IAM roles for Lambda@Edge.
- `AmazonSSMFullAccess`: Access SSM parameters used to store CloudFront key pairs.

### 2. Ongoing Usage

Used for `hot-updater deploy` and `hot-updater console`:

- `AmazonS3FullAccess`: Manage bundles and metadata in the S3 bucket.
- `cloudfront:CreateInvalidation`: Invalidate CloudFront cache after deployments.

For ongoing usage, create separate deploy credentials or a deploy principal
with limited permissions. Here's a minimal policy example for CloudFront
invalidation:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["cloudfront:CreateInvalidation"],
      "Resource": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DISTRIBUTION_ID>"
    }
  ]
}
```

If this permission is missing, you may encounter the following error:

```
AccessDenied: User: arn:aws:sts::***:assumed-role/***/*** is not authorized to perform: cloudfront:CreateInvalidation on resource: arn:aws:cloudfront::***:distribution/*** because no identity-based policy allows the cloudfront:CreateInvalidation action
```

## Step 1: Install Required Packages

Run the following command to install dependencies:

```package-install
npm install hot-updater --save-dev
```

## Step 2: Configure AWS

Run the initialization script to start the interactive setup process. Use the following command with your preferred package manager:

```package-install
npx hot-updater init
```

<Accordions type="single">
  <Accordion title="Interactive Setup Steps">

1. **Select a Build Plugin**: Choose a build plugin for your project (e.g., Bare (React Native CLI) for React Native).
2. **Select a Provider**: Select AWS + Lambda@Edge as the provider for handling updates.
   During the setup, you will be prompted to:
3. **Choose AWS Login Method**: Select current AWS CLI/default session, a
   shared AWS profile, account access keys, or an AWS SSO profile.
4. **Enter AWS Configuration**: Provide the profile name for shared-profile or
   SSO mode, or credentials only for account/access-key mode.
5. **Select Region**: Choose an AWS region for your S3 bucket
6. **Select S3 Bucket**: Choose an existing bucket or create a new one
7. **Create IAM Role**: Create or select an IAM role for Lambda@Edge
8. **Deploy Lambda Function**: Deploy the Lambda@Edge function to handle updates
9. **Create/Update CloudFront Distribution**: Create or update a CloudFront distribution

  </Accordion>
</Accordions>

Once setup completes, `.env.hotupdater` records the selected auth mode and
the deterministic state needed to update the same infrastructure. It may
include:

```bash
HOT_UPDATER_AWS_AUTH_MODE=local-session
HOT_UPDATER_S3_BUCKET_NAME=your-s3-bucket-name
HOT_UPDATER_S3_REGION=your-region
HOT_UPDATER_AWS_LAMBDA_NAME=hot-updater-edge
HOT_UPDATER_CLOUDFRONT_DISTRIBUTION_ID=your-distribution-id
```

If you choose a shared profile or SSO, the replay state also includes the
profile:

```bash
HOT_UPDATER_AWS_PROFILE=your-profile-name
```

If you choose the current AWS CLI/default session mode, no credential env
variables are needed. The generated config uses the AWS SDK default provider
chain directly.

If you choose access keys, init asks whether it may persist them. These values
are present only when you approve that prompt:

```bash
# The generated key may be over-privileged or temporary depending on how you authenticated during init.
HOT_UPDATER_S3_ACCESS_KEY_ID=your-access-key-id
HOT_UPDATER_S3_SECRET_ACCESS_KEY=your-secret-access-key
```

After you approve a pending S3 migration, init may also record
`HOT_UPDATER_AWS_MIGRATION_APPROVED=true`. If you decline credential
persistence, provide the credentials again when a later infrastructure update
needs them.

<Callout type="warn">

If you're **not** using the `react-native-dotenv` solution, the tokens from your `.env.hotupdater` file will not be included in your app bundle and are therefore not exposed to risks. However, if you're still concerned,

please refer to the article below for more details:
[Security](/docs/policy/security#plugin-token-protection)

</Callout>

## Step 3: Generated Configurations

During the initialization process, the following file is automatically generated:

- `hot-updater.config.ts`: This file contains the configuration settings for integrating AWS with your project.

If you choose **current AWS CLI/default session**, the generated config uses the
AWS SDK default provider chain instead of embedding access keys:

```ts title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { fromNodeProviderChain } from "@aws-sdk/credential-providers";
import { s3Storage, s3Database } from "@hot-updater/aws";
import { defineConfig } from "hot-updater";
import { config } from "dotenv";

config({ path: ".env.hotupdater" });

const commonOptions = {
  bucketName: process.env.HOT_UPDATER_S3_BUCKET_NAME!,
  region: process.env.HOT_UPDATER_S3_REGION!,
  credentials: fromNodeProviderChain(),
};

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: s3Storage(commonOptions),
  database: s3Database({
    ...commonOptions,
    // prettier-ignore
    cloudfrontDistributionId: process.env.HOT_UPDATER_CLOUDFRONT_DISTRIBUTION_ID!,
  }),
  updateStrategy: "appVersion",
});
```

If you choose **shared AWS profile**, `fromNodeProviderChain()` is replaced with
`fromIni({ profile: process.env.HOT_UPDATER_AWS_PROFILE! })`. SSO is
also profile/config mode and uses
`fromSSO({ profile: process.env.HOT_UPDATER_AWS_PROFILE! })`. Only
account/access-key mode writes an inline `accessKeyId` and
`secretAccessKey` credential object.

## Step 4: Replace Account Access Keys (Optional)

By this point, `.env.hotupdater` has already been created by
`hot-updater init`.

This step applies only if you selected **account/access key** during
`init`. Current-session, shared-profile, and SSO modes use their
generated credential providers and do not need replacement access-key
variables.

The setup key may have excessive permissions because init provisions
infrastructure.

Replace it with credentials scoped for ongoing deployment, including the
required `AmazonS3FullAccess` and CloudFront invalidation permission.

```bash title=".env.hotupdater"
HOT_UPDATER_S3_ACCESS_KEY_ID=your-access-key-id
HOT_UPDATER_S3_SECRET_ACCESS_KEY=your-secret-access-key
```

## Step 5: Add HotUpdater to Your Project

The HotUpdater component wraps your application, enabling seamless delivery of updates and fallback UI during updates. Follow these steps to integrate it into your App.tsx:

```tsx title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";
import { Text, View } from "react-native";

function App() {
  return (
    <View>
      <Text>Hello World</Text>
    </View>
  );
}

export default HotUpdater.wrap({
  baseURL: "https://<your-cloudfront-distribution-url>/api/check-update", // [!code ++]
  updateStrategy: "appVersion", // or "fingerprint" // [!code ++]
  requestHeaders: {
    // if you want to use the request headers, you can add them here
  },
  fallbackComponent: ({ progress, status }) => (
    <View
      style={{
        flex: 1,
        padding: 20,
        borderRadius: 10,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "rgba(0, 0, 0, 0.5)",
      }}
    >
      {/* You can put a splash image here. */}

      <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
        {status === "UPDATING" ? "Updating..." : "Checking for Update..."}
      </Text>
      {progress > 0 ? (
        <Text style={{ color: "white", fontSize: 20, fontWeight: "bold" }}>
          {Math.round(progress * 100)}%
        </Text>
      ) : null}
    </View>
  ),
})(App);
```

<Callout type="info">
The managed AWS runtime exposes the public update-check endpoints and `/version`. Internally, it is equivalent to `createHotUpdater({ routes: { updateCheck: true, bundles: false } })`, so bundle management endpoints are not mounted on the public function URL.
</Callout>

## Step 6: If You Use Expo, Add the Config Plugin

Add the plugin to your `app.json` file as shown below:

```json title="app.json"
{
  "expo": {
    "plugins": [
      [
        "@hot-updater/react-native",
        {
          "channel": "production"
        }
      ]
    ]
  }
}
```

```package-install
npx expo prebuild
```

## Step 7: Add Native Code

Follow the canonical [Native Code Setup](/docs/get-started/basic-usage#native-code-setup)
for your React Native version and language. That page tracks the current
Android and iOS template boundaries; the AWS provider does not require a
provider-specific native integration.

## Verifying the Setup

1. Check your AWS dashboard for the newly created bucket, Lambda@Edge function, and CloudFront distribution.
2. Test the HotUpdater integration in your React Native app.

You're all set! 🎉 Start using hot-updater with AWS for seamless updates in your React Native app.

This document simplifies the initialization process, making it easy for developers to get started with minimal friction.
