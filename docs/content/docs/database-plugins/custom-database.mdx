## Installation

```package-install
npm install @hot-updater/plugin-core
```

## Overview

Build a custom database plugin to integrate any database provider. This guide shows how to use `createDatabasePlugin` to build and configure your own database plugin.

## Creating a Database Plugin

Use `createDatabasePlugin` to build custom database plugins:

```typescript
import { createDatabasePlugin } from "@hot-updater/plugin-core";

export const myDatabase = createDatabasePlugin<MyConfig>({
  name: "myDatabase", // Plugin identifier
  factory: (config) => ({
    // Return these required methods:
    getBundleById: async (bundleId) => {
      /* ... */
    },
    getBundles: async (options) => ({ data: [], pagination: {} }),
    getChannels: async () => [],
    commitBundle: async ({ changedSets }) => {
      /* ... */
    },
    onUnmount: async () => {
      /* optional cleanup */
    },
  }),
});
```

### Factory Function Return Type

Your factory function must return an object with these methods:

```typescript
{
  // Fetch single bundle by ID
  getBundleById: (bundleId: string) => Promise<Bundle | null>;

  // Optional but recommended: direct update-check fast path
  getUpdateInfo?: (args: GetBundlesArgs) => Promise<UpdateInfo | null>;

  // Set this only when getBundles implements cursor boundaries itself
  supportsCursorPagination?: boolean;

  // Fetch paginated bundles with the complete DatabaseBundleQueryOptions
  getBundles: (
    options: DatabaseBundleQueryOptions & { offset?: number },
  ) => Promise<Paginated<Bundle[]>>;

  // Get all available channels
  getChannels: () => Promise<string[]>;

  // Commit all pending changes (batch operation)
  commitBundle: (params: {
    changedSets: {
      operation: "insert" | "update" | "delete";
      data: Bundle;
    }[];
  }) => Promise<void>;

  // Optional: cleanup resources on unmount
  onUnmount?: () => Promise<void>;
}
```

Implement `getUpdateInfo` whenever your backend can answer update checks
without scanning the full management list. This is especially important for
blob/object-storage plugins, where the hot path should read only the manifest
objects needed for the request.

**Note**: The factory does NOT need to implement `updateBundle`, `appendBundle`, or `deleteBundle` - these are auto-generated by `createDatabasePlugin` and tracked internally.

## Implementation Example

Here's a complete custom database plugin using a REST API:

```typescript title="customDatabase.ts"
import {
  type Bundle,
  type Paginated,
  createDatabasePlugin,
} from "@hot-updater/plugin-core";

export interface CustomDatabaseConfig {
  baseUrl: string;
  apiKey: string;
}

const appendValues = (
  params: URLSearchParams,
  key: string,
  values: string[] | undefined,
) => {
  for (const value of values ?? []) {
    params.append(key, value);
  }
};

const setNullable = (
  params: URLSearchParams,
  key: string,
  value: string | null | undefined,
) => {
  if (value !== undefined) {
    params.set(key, value === null ? "null" : value);
  }
};

export const customDatabase = createDatabasePlugin<CustomDatabaseConfig>({
  name: "customDatabase",
  factory: (config) => {
    const headers = {
      "Content-Type": "application/json",
      Authorization: `Bearer ${config.apiKey}`,
    };

    return {
      supportsCursorPagination: true,

      async getBundleById(bundleId) {
        const response = await fetch(`${config.baseUrl}/bundles/${bundleId}`, {
          headers,
        });

        if (!response.ok) {
          if (response.status === 404) return null;
          throw new Error(`Failed to fetch bundle: ${response.statusText}`);
        }

        return response.json();
      },

      async getBundles(options): Promise<Paginated<Bundle[]>> {
        const params = new URLSearchParams({
          limit: String(options.limit),
        });

        if (options.page !== undefined) {
          params.set("page", String(options.page));
        }
        if (options.cursor?.after) {
          params.set("after", options.cursor.after);
        }
        if (options.cursor?.before) {
          params.set("before", options.cursor.before);
        }

        if (options.where?.channel) {
          params.set("channel", options.where.channel);
        }
        if (options.where?.platform) {
          params.set("platform", options.where.platform);
        }
        if (options.where?.enabled !== undefined) {
          params.set("enabled", String(options.where.enabled));
        }

        const id = options.where?.id;
        if (id?.eq !== undefined) params.set("idEq", id.eq);
        if (id?.gt !== undefined) params.set("idGt", id.gt);
        if (id?.gte !== undefined) params.set("idGte", id.gte);
        if (id?.lt !== undefined) params.set("idLt", id.lt);
        if (id?.lte !== undefined) params.set("idLte", id.lte);
        appendValues(params, "idIn", id?.in);

        setNullable(
          params,
          "targetAppVersion",
          options.where?.targetAppVersion,
        );
        appendValues(
          params,
          "targetAppVersionIn",
          options.where?.targetAppVersionIn,
        );
        if (options.where?.targetAppVersionNotNull !== undefined) {
          params.set(
            "targetAppVersionNotNull",
            String(options.where.targetAppVersionNotNull),
          );
        }
        setNullable(params, "fingerprintHash", options.where?.fingerprintHash);

        if (options.orderBy) {
          params.set("orderBy", options.orderBy.field);
          params.set("orderDirection", options.orderBy.direction);
        }

        const response = await fetch(`${config.baseUrl}/bundles?${params}`, {
          headers,
        });

        if (!response.ok) {
          throw new Error(`Failed to fetch bundles: ${response.statusText}`);
        }

        const result = await response.json();
        return {
          data: result.data,
          pagination: result.pagination,
        };
      },

      async getChannels() {
        const response = await fetch(`${config.baseUrl}/channels`, {
          headers,
        });

        if (!response.ok) {
          throw new Error(`Failed to fetch channels: ${response.statusText}`);
        }

        return response.json();
      },

      async commitBundle({ changedSets }) {
        // Process all changes in batch
        for (const change of changedSets) {
          if (change.operation === "insert" || change.operation === "update") {
            await fetch(`${config.baseUrl}/bundles`, {
              method: "POST",
              headers,
              body: JSON.stringify(change.data),
            });
          } else if (change.operation === "delete") {
            await fetch(`${config.baseUrl}/bundles/${change.data.id}`, {
              method: "DELETE",
              headers,
            });
          }
        }
      },

      async onUnmount() {
        // Optional: cleanup resources, close connections, etc.
        console.log("Database plugin unmounted");
      },
    };
  },
});
```

This example opts into native cursor pagination, so its REST backend must
honor `after`, `before`, `orderBy`, every filter above,
and return matching cursor metadata. Do not set
`supportsCursorPagination: true` if the backend ignores those fields.
Without that flag, `createDatabasePlugin` supplies offset/ID/order
fallback queries to `getBundles`; an implementation using that mode
must honor the internal `offset` value instead.

## Helper Utilities

The `@hot-updater/plugin-core` package provides helper functions:

### calculatePagination

Generates pagination metadata after your implementation resolves a cursor into
an internal start index:

```typescript
import { calculatePagination } from "@hot-updater/plugin-core";

const startIndex = resolvedCursorStartIndex;
const pagination = calculatePagination(totalCount, {
  limit: 10,
  offset: startIndex,
});
// Result: { total, hasNextPage, hasPreviousPage, currentPage, totalPages }
```

## CLI Configuration

Use the plugin as the database field in `hot-updater.config.ts`. This is
a field excerpt; a complete config must also provide build, storage, and update
strategy fields:

```typescript title="hot-updater.config.ts (excerpt)"
import { customDatabase } from "./customDatabase";

const database = customDatabase({
  baseUrl: process.env.DATABASE_BASE_URL!,
  apiKey: process.env.DATABASE_API_KEY!,
});
```

## Custom Server Usage

Use your plugin with `createHotUpdater` for self-hosted servers:

```typescript
import { createHotUpdater } from "@hot-updater/server";
import { customDatabase } from "./customDatabase";

const hotUpdater = createHotUpdater({
  database: customDatabase({
    baseUrl: process.env.DATABASE_BASE_URL!,
    apiKey: process.env.DATABASE_API_KEY!,
  }),
  // ... other options
});
```

## Best Practices

### Security

- Never hardcode credentials in plugin code
- Use environment variables for sensitive data
- Implement proper authentication headers
- Validate input data before storing

### Performance

- Prefer `getUpdateInfo` for the update-check hot path so runtime requests do
  not fall back to wide `getBundles` scans
- Implement efficient filtering in `getBundles`
- Use database indexes for common queries
- Batch operations in `commitBundle` when possible
- Cache channel lists if they don't change frequently
- Add deterministic I/O or query-counter tests that fail if update checks or
  cursor-backed management reads regress into broad scans

### Error Handling

- Return `null` from `getBundleById` when not found (don't throw)
- Throw descriptive errors for other failures
- Handle network errors gracefully
- Validate bundle data structure
