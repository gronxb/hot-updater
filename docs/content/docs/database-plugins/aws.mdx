## Installation

```package-install
npm install @hot-updater/aws --save-dev
```

## Create the table

For managed AWS installations, `npx hot-updater init` selects DynamoDB by
default and creates or validates this table automatically.

For custom installations, create one on-demand table manually with the
overloaded index used for update checks and patch relations:

```bash
aws dynamodb create-table \
  --table-name hot-updater \
  --billing-mode PAY_PER_REQUEST \
  --attribute-definitions \
    AttributeName=pk,AttributeType=S \
    AttributeName=sk,AttributeType=S \
    AttributeName=gsi1pk,AttributeType=S \
    AttributeName=gsi1sk,AttributeType=S \
  --key-schema \
    AttributeName=pk,KeyType=HASH \
    AttributeName=sk,KeyType=RANGE \
  --global-secondary-indexes '[
    {
      "IndexName": "hot-updater-update-index",
      "KeySchema": [
        { "AttributeName": "gsi1pk", "KeyType": "HASH" },
        { "AttributeName": "gsi1sk", "KeyType": "RANGE" }
      ],
      "Projection": { "ProjectionType": "ALL" }
    }
  ]'
```

Analytics uses the same table for append-only events. Before enabling the
`analytics()` server plugin, write its schema marker:

```bash
aws dynamodb put-item \
  --table-name hot-updater \
  --item '{"pk":{"S":"_hot-updater"},"sk":{"S":"schema.analytics"},"value":{"S":"2"}}' \
  --condition-expression 'attribute_not_exists(pk)'
```

Managed AWS init creates or validates this marker automatically.
The successful readiness check is cached for the lifetime of the provider, so
event writes and paginated Analytics reads do not add one schema `GetItem` per
operation.

## Configuration

```typescript
interface DynamoDBDatabaseConfig {
  tableName: string;
  region?: string;
  endpoint?: string;
  credentials?: {
    accessKeyId: string;
    secretAccessKey: string;
  };
}
```

If `credentials` is omitted, the AWS SDK default credential chain is used. This
lets you rely on local AWS CLI sessions, `AWS_PROFILE`, shared config files, or
other standard AWS credential sources.

## Usage

```typescript
import { dynamodbDatabase } from "@hot-updater/aws";
import { defineConfig } from "hot-updater";

export default defineConfig({
  database: dynamodbDatabase({
    tableName: "hot-updater",
    region: "us-east-1",
    credentials: {
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    },
  }),
});
```

## Complete Example

Combined storage and database:

```typescript
import { dynamodbDatabase, s3Storage } from "@hot-updater/aws";
import { defineConfig } from "hot-updater";

const credentials = {
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
};

export default defineConfig({
  storage: s3Storage({
    region: "us-east-1",
    credentials,
    bucketName: "my-bundles-bucket",
  }),
  database: dynamodbDatabase({
    tableName: "hot-updater",
    region: "us-east-1",
    credentials,
  }),
});
```

## Custom Server Usage

Use `dynamodbDatabase` with `createHotUpdater` for self-hosted servers:

```typescript
import { dynamodbDatabase } from "@hot-updater/aws";
import { createHotUpdater } from "@hot-updater/server";

const hotUpdater = createHotUpdater({
  database: dynamodbDatabase({
    tableName: process.env.AWS_DYNAMODB_TABLE_NAME!,
    region: process.env.AWS_REGION!,
    credentials: {
      accessKeyId: process.env.AWS_ACCESS_KEY_ID!,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY!,
    },
  }),
});
```

The Lambda or server role needs read access for update checks. Analytics also
needs `GetItem` for the schema marker and `Query`/`PutItem` for the
`analytics#bundle_events` partition. CLI and Console writers need permission to
put, update, and delete metadata items.

## Migrating from S3 metadata

`s3Database` remains available for existing installations but is deprecated.
Continue using `s3Storage` for bundle archives and other large artifacts.

The providers do not share state. Back up the metadata bucket and copy existing
bundle and patch rows before changing the configured database. Do not run S3
and DynamoDB metadata writers concurrently during a migration.

`hot-updater init` keeps `S3 metadata (Deprecated)` selectable for existing
installations. Replaying an older AWS init environment without an explicit
database choice preserves S3 metadata instead of silently switching databases.
