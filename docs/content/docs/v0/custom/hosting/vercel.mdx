## Prerequisites

- Vercel account at [vercel.com](https://vercel.com)
- A PostgreSQL integration from the [Vercel Marketplace](https://vercel.com/docs/postgres), such as Neon
- Cloud storage (S3, R2, Supabase, Firebase, or custom)

## Installation

Install required dependencies.

```package-install
npm install @hot-updater/server hono
```

Install your chosen storage plugin separately (e.g., `@hot-updater/aws`, `@hot-updater/supabase`, `@hot-updater/firebase`).
Create `src/storage.ts` and export a configured runtime-capable plugin as
`storagePlugin`. This hosting guide intentionally leaves that provider choice
to the matching [Storage Plugin](../../storage-plugins/custom-storage) guide.
Configure that plugin's required credentials and settings in every Vercel
environment that serves updates.

Install Drizzle ORM with PostgreSQL driver.

```package-install
npm install drizzle-orm pg
```

```package-install
npm install --save-dev @hot-updater/bare @hot-updater/standalone hot-updater drizzle-kit @types/pg dotenv
```

## Database Setup

Vercel Postgres is discontinued. For a new project, install a current Postgres
integration from the Marketplace and connect it to the Vercel project. This
example uses Neon, whose integration provides `DATABASE_URL` to the connected
environments. Configure an unpooled `DATABASE_URL_UNPOOLED` value as well when
you want Drizzle Kit to use a direct connection for migrations.

Create the database connection file. The runtime uses the Marketplace-provided
`DATABASE_URL`.

```typescript title="src/drizzle.ts"
import { drizzle } from "drizzle-orm/node-postgres";
import { Pool } from "pg";
import * as schema from "../hot-updater-schema";

const pool = new Pool({
  connectionString: process.env.DATABASE_URL!,
});

export const db = drizzle({ client: pool, schema });
```

## Hot Updater Configuration

Create the Hot Updater instance.

```typescript title="src/hotUpdater.ts"
import { createHotUpdater } from "@hot-updater/server";
import { drizzleAdapter } from "@hot-updater/server/adapters/drizzle";
import { db } from "./drizzle";
import { storagePlugin } from "./storage";

export const hotUpdater = createHotUpdater({
  database: drizzleAdapter({ db, provider: "postgresql" }),
  storages: [storagePlugin],
  basePath: "/hot-updater",
  routes: {
    updateCheck: true,
    bundles: true,
  },
});
```

## Serverless Function

Create Vercel serverless function with Hono.

```typescript title="src/index.ts"
import { Hono } from "hono";
import { bearerAuth } from "hono/bearer-auth";
import { hotUpdater } from "./hotUpdater";

const app = new Hono();

const authToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!authToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

app.use("/hot-updater/api/*", bearerAuth({ token: authToken }));
app.mount("/hot-updater", hotUpdater.handler);

export default app;
```

<Callout type="warn">
  With Hono `mount()`, update-check routes such as `/hot-updater/app-version/*`
  and `/hot-updater/fingerprint/*` are usually exposed for React Native clients,
  but that is a deployment choice. `/hot-updater/version` is always mounted for
  diagnostics. Always protect `/hot-updater/api/*` when `routes.bundles: true`.
</Callout>

## Schema and Migration

Generate the Drizzle schema for Hot Updater tables.

```bash
npx hot-updater db generate src/hotUpdater.ts --yes
```

The command writes `hot-updater-schema.ts` at the project root. Configure
Drizzle Kit to load Vercel's local environment and prefer a direct migration
connection when one is available:

```typescript title="drizzle.config.ts"
import { config } from "dotenv";
import { defineConfig } from "drizzle-kit";

config({ path: ".env.local" });

const migrationUrl =
  process.env.DATABASE_URL_UNPOOLED ?? process.env.DATABASE_URL;

if (!migrationUrl) {
  throw new Error("DATABASE_URL_UNPOOLED or DATABASE_URL is required");
}

export default defineConfig({
  schema: "./hot-updater-schema.ts",
  out: "./drizzle",
  dialect: "postgresql",
  dbCredentials: {
    url: migrationUrl,
  },
});
```

Pull the development environment and apply the schema before deployment:

```bash
npx vercel env pull .env.local
npx drizzle-kit push
```

For production, run the same schema step from a controlled release job against
the production database before shifting traffic.

## Development

Run the development server locally.

```bash
npx vercel env pull .env.local
npx vercel dev
```

Server runs at `http://localhost:3000`.

## Deploy

Deploy to Vercel.

```bash
npx vercel deploy --prod
```

Your Hot Updater server will be available at `https://your-project.vercel.app/hot-updater`.

## CLI Configuration

Configure your CLI to use this deployed server.

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";
import { cliStorage } from "./hot-updater-storage";

const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: cliStorage,
  database: standaloneRepository({
    baseUrl: "https://your-project.vercel.app/hot-updater",
    commonHeaders: {
      Authorization: `Bearer ${managementToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
  `./hot-updater-storage` is your React Native project's provider configuration.
  Its exported `cliStorage` must use the same URI scheme and backing store as
  the server's `storagePlugin`. Configure `HOT_UPDATER_AUTH_TOKEN` in every
  Vercel environment and in the CLI environment.
</Callout>
