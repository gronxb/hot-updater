## Usage

When an update comes from
[`HotUpdater.checkForUpdate()`](/docs/v0/react-native-api/checkForUpdate), call
the `updateBundle()` function on that result. It keeps the channel switch,
hashes, manifest diff, and rollback values from the check together.

```tsx
import { HotUpdater } from "@hot-updater/react-native";

HotUpdater.init({
  baseURL: "<your-update-server-url>",
});

async function applyAppUpdate() {
  const updateInfo = await HotUpdater.checkForUpdate({
    updateStrategy: "appVersion",
  });

  if (!updateInfo) {
    return;
  }

  const didUpdate = await updateInfo.updateBundle();
  if (didUpdate && updateInfo.shouldForceUpdate) {
    await HotUpdater.reload();
  }
}
```

Call `HotUpdater.updateBundle(params)` directly only when you already have a
complete `UpdateParams` object from another trusted update flow:

```tsx
const didUpdate = await HotUpdater.updateBundle({
  bundleId: "01952bbd-e7b2-7931-aee8-2e2187caa0ce",
  fileUrl: "https://updates.example.com/bundles/app.tar.br",
  fileHash: "b8f6c4d7...",
  status: "UPDATE",
});
```

`HotUpdater.wrap()` or `HotUpdater.init()` must configure the client before
either update API is called.

## Parameters

The object overload accepts `UpdateParams`. Required nullable properties must
be present even when their value is `null`.

| Property                         | Type                     | Required | Description                                                                                                                      |
| -------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `bundleId`                       | `string`                 | Yes      | Target Bundle ID.                                                                                                                |
| `fileUrl`                        | `string \| null`         | Yes      | Archive URL, or `null` for a rollback/manifest-only transition.                                                                  |
| `fileHash`                       | `string \| null`         | Yes      | Archive SHA-256 hash or `sig:<base64-signature>`; `null` means no archive hash is available.                                     |
| `status`                         | `"UPDATE" \| "ROLLBACK"` | Yes      | Direction of the transition.                                                                                                     |
| `channel`                        | `string`                 | No       | Runtime channel to persist after a successful install.                                                                           |
| `manifestUrl`                    | `string \| null`         | No       | Signed or hashed manifest artifact URL.                                                                                          |
| `manifestFileHash`               | `string \| null`         | No       | Manifest hash or embedded signature.                                                                                             |
| `changedAssets`                  | `UnsafeObject \| null`   | No       | Manifest-relative file and patch descriptors used for a diff install.                                                            |
| `shouldSkipCurrentBundleIdCheck` | `boolean`                | No       | Allows an explicitly authorized channel transition that is not newer than the active Bundle. Leave unset in normal direct calls. |

For a rollback to the built-in bundle, pass the nullable properties explicitly:

```tsx
await HotUpdater.updateBundle({
  bundleId: "00000000-0000-0000-0000-000000000000",
  fileUrl: null,
  fileHash: null,
  status: "ROLLBACK",
});
```

## Verification and reload behavior

- A plain hexadecimal `fileHash` verifies the archive SHA-256 value.
- A value beginning with `sig:` invokes native signature verification.
- `fileHash: null` is valid for transitions with no archive, but direct archive
  installs should supply the hash/signature returned by a trusted server.
- A successful call stages the selected Bundle. Call
  [`HotUpdater.reload()`](/docs/v0/react-native-api/reload) to execute it
  immediately; automatic `wrap` flows handle force-update reloads themselves.
