## Plugin Token Protection

Developers may worry that sensitive tokens defined in the `hot-updater.config.ts` file might be bundled into the app and exposed in production.

Using environment variables is simply for populating the token value in the `hot-updater.config.ts` file. This is, in fact, unrelated to React Native.

```ts title="hot-updater.config.ts"
import { existsSync } from "node:fs";
import { bare } from "@hot-updater/bare";
import { supabaseDatabase, supabaseStorage } from "@hot-updater/supabase";
import { defineConfig } from "hot-updater";

if (existsSync(".env.hotupdater")) {
  process.loadEnvFile(".env.hotupdater");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: supabaseStorage({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey:
      process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
    bucketName: process.env.HOT_UPDATER_SUPABASE_BUCKET_NAME!,
  }),
  database: supabaseDatabase({
    supabaseUrl: process.env.HOT_UPDATER_SUPABASE_URL!,
    supabaseServiceRoleKey:
      process.env.HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY!,
  }),
  updateStrategy: "appVersion",
});

```

## Clarification

The `hot-updater.config.ts` file is not included in the app’s build. Instead, it serves as a configuration layer specifically for communicating with the `hot-updater` CLI. As a result, sensitive tokens defined in this file are not part of the distributed application code.

What is actually included in the app’s build is as follows:
```ts
import { HotUpdater } from "@hot-updater/react-native";

export default HotUpdater.wrap({
  baseURL: "https://<your-update-server-url>",
  updateStrategy: "appVersion", // or "fingerprint",
});
```

Here, the source URL is included in the app code, but sensitive environment variables, such as `HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY` tokens, are not bundled.

## Potential Token Exposure

<Callout type="warn">
Anything included in the app bundle can be read by app users. Never include
provider credentials such as `HOT_UPDATER_SUPABASE_SERVICE_ROLE_KEY` or
`HOT_UPDATER_CLOUDFLARE_API_TOKEN` in app source or build configuration.
</Callout>

Configure public app values explicitly, such as the update server URL shown
above. Do not import `.env.hotupdater` or `hot-updater.config.ts` into the app.
Keep provider credentials in the local CLI, CI, or server environment.

## Best Practices

1. Include only values intended for public access in the app configuration.
2. Keep credential files out of version control and distributed app bundles.
3. Store server secrets in the deployment environment and use them only on the server.
