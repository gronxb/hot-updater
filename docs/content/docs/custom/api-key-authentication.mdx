---
title: "Better Auth API Keys"
description: Require a Better Auth API key on every Hot Updater route.
icon: KeyRound
---

Use Better Auth's API-key plugin to turn a valid `x-api-key` header into a
Better Auth session. `@hot-updater/better-auth` then authenticates that session
and protects every HTTP route emitted by `createHotUpdater`.

## Install

```package-install
better-auth @better-auth/api-key @hot-updater/better-auth
```

## Configure Better Auth

Add `apiKey()` to the same Better Auth instance that owns your authentication
database. `enableSessionForAPIKeys: true` is required because
`betterAuthPlugin` authenticates through `auth.api.getSession`.

```typescript title="src/auth.ts"
import { apiKey } from "@better-auth/api-key";
import { betterAuth } from "better-auth";

export const auth = betterAuth({
  database: authDatabase,
  plugins: [
    apiKey({
      enableSessionForAPIKeys: true,
    }),
  ],
});
```

The API-key table belongs to Better Auth. Enabling the Hot Updater plugin does
not add that table to the Hot Updater schema. With Better Auth's built-in
Kysely adapter, apply its migration separately:

```bash
npx auth@latest migrate --config ./src/auth.ts
```

For Prisma, Drizzle, or another ORM adapter, generate the Better Auth schema
and apply it with that ORM's migration workflow:

```bash
npx auth@latest generate --config ./src/auth.ts
```

## Protect the Hot Updater server

Pass the configured Better Auth instance to `betterAuthPlugin`. The Hot Updater
plugin does not configure or verify API keys itself.

```typescript title="src/hotUpdater.ts"
import { betterAuthPlugin } from "@hot-updater/better-auth";
import { createHotUpdater } from "@hot-updater/server";

import { auth } from "./auth";

export const hotUpdater = createHotUpdater({
  database: hotUpdaterDatabase,
  storages,
  routes: {
    bundles: true,
    updateCheck: true,
  },
  plugins: [betterAuthPlugin({ auth })],
});
```

This configuration requires an authenticated Better Auth session on every
route mounted by `createHotUpdater`, including `/version`, update checks,
bundle management, and any installed feature routes. A valid API key satisfies
that requirement because Better Auth exposes it as a session. Cookie-backed
Better Auth sessions continue to work through the same path.

The policy applies only to routes emitted by this `createHotUpdater` instance.
Framework-owned endpoints such as `/ping`, and signed bundle download URLs
served by storage or a CDN, remain outside its scope.

## Create and distribute a key

Create the key from a trusted server-side bootstrap path. For a user-owned key,
use an existing Better Auth user's ID.

```typescript title="scripts/create-hot-updater-key.ts"
import { auth } from "../src/auth";

const credential = await auth.api.createApiKey({
  body: {
    name: "mobile-client",
    userId: existingBetterAuthUser.id,
  },
});

await secretStore.write("HOT_UPDATER_API_KEY", credential.key);
```

Better Auth reads API keys from `x-api-key` by default. Send the key from every
Hot Updater consumer. The standalone CLI plugins share headers through their
repository configuration:

```typescript title="hot-updater.config.ts"
import { defineConfig } from "@hot-updater/core";
import {
  standaloneAnalytics,
  standaloneRepository,
} from "@hot-updater/standalone";

import { env } from "./env";

const repositoryConfig = {
  baseUrl: env.HOT_UPDATER_URL,
  commonHeaders: {
    "x-api-key": env.HOT_UPDATER_API_KEY,
  },
};

export default defineConfig({
  database: standaloneRepository(repositoryConfig),
  console: {
    analytics: standaloneAnalytics(repositoryConfig),
  },
});
```

React Native update checks use `requestHeaders`:

```typescript title="App.tsx"
import { HotUpdater } from "@hot-updater/react-native";

import { env } from "./env";

export default HotUpdater.wrap({
  baseURL: "https://updates.example.com",
  requestHeaders: {
    "x-api-key": env.HOT_UPDATER_API_KEY,
  },
})(App);
```

<Callout type="warn">
  A key embedded in a React Native bundle can be extracted. Treat this as a
  client access gate, not as end-user identity or strong administrator
  authentication. Apply rate limits, expiration, rotation, and revocation, and
  do not rely on an embedded key alone to protect sensitive management
  operations. The example sends one key to every protected route, so add a
  separate gateway policy if management APIs need stronger isolation.
</Callout>
