## Overview

Your CLI configuration (`hot-updater.config.ts`) connects your React Native project to your self-hosted Hot Updater server. This file defines how bundles are built, stored, and tracked.

## Basic Configuration

Create a `hot-updater.config.ts` file in your React Native project root:

```typescript title="hot-updater.config.ts"
import { bare } from "@hot-updater/bare";
import { r2Storage } from "@hot-updater/cloudflare";
import { standaloneRepository } from "@hot-updater/standalone";
import { defineConfig } from "hot-updater";

const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

export default defineConfig({
  build: bare({ enableHermes: true }),
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
    credentials: {
      accessKeyId: process.env.R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
    },
    bucketName: process.env.R2_BUCKET_NAME!,
  }),
  database: standaloneRepository({
    baseUrl: "http://localhost:3000/hot-updater",
    commonHeaders: {
      Authorization: `Bearer ${managementToken}`,
    },
  }),
  updateStrategy: "appVersion",
});
```

<Callout type="warn">
**Critical: Storage Plugin Must Match**

The `storage` plugin in your CLI config must match the `storages` in your server's `createHotUpdater` configuration.

**CLI uses `r2Storage` → Server must use `r2Storage`**

Both sides need the same plugin type and configuration to encode/decode storage URIs correctly.

</Callout>

## Standalone Repository Configuration

The `standaloneRepository` plugin connects your CLI to your self-hosted server:

```typescript
interface StandaloneRepositoryConfig {
  baseUrl: string; // Your server URL
  commonHeaders?: Record<string, string>; // Optional headers (e.g., authentication)
  routes?: Routes; // Optional custom route configuration
}
```

### With Authentication

```typescript
const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

database: standaloneRepository({
  baseUrl: process.env.HOT_UPDATER_SERVER_URL!,
  commonHeaders: {
    Authorization: `Bearer ${managementToken}`,
  },
});
```

### With Custom Routes

```typescript
const managementToken = process.env.HOT_UPDATER_AUTH_TOKEN;
if (!managementToken) {
  throw new Error("HOT_UPDATER_AUTH_TOKEN is required");
}

database: standaloneRepository({
  baseUrl: "https://api.example.com",
  commonHeaders: {
    Authorization: `Bearer ${managementToken}`,
  },
  routes: {
    create: () => ({
      path: "/v1/hot-updater/api/bundles",
      headers: { "X-Custom-Header": "value" },
    }),
    update: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
      headers: { "X-Custom-Header": "value" },
    }),
    list: () => ({
      path: "/v1/hot-updater/api/bundles",
    }),
    channels: () => ({
      path: "/v1/hot-updater/api/bundles/channels",
    }),
    retrieve: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
    delete: (bundleId) => ({
      path: `/v1/hot-updater/api/bundles/${bundleId}`,
    }),
  },
});
```

## API Endpoints

With `routes: { updateCheck: true, bundles: true }`,
`@hot-updater/server` mounts the legacy management contract used by
`standaloneRepository`. All six routes can be remapped with the `routes`
option shown above:

| Method | Default endpoint                    | Purpose            |
| ------ | ----------------------------------- | ------------------ |
| POST   | `/hot-updater/api/bundles`          | Create Bundles     |
| PATCH  | `/hot-updater/api/bundles/:id`      | Update a Bundle    |
| GET    | `/hot-updater/api/bundles`          | List Bundles       |
| GET    | `/hot-updater/api/bundles/:id`      | Retrieve a Bundle  |
| DELETE | `/hot-updater/api/bundles/:id`      | Delete a Bundle    |
| GET    | `/hot-updater/api/bundles/channels` | List Channel names |

The Bundle-list request supports `channel`, `platform`, `enabled`, the
`idEq`/`idGt`/`idGte`/`idLt`/`idLte`/`idIn` filters,
`targetAppVersion`/`targetAppVersionIn`/`targetAppVersionNotNull`,
`fingerprintHash`, and `limit`/`page`/`after`/`before`. Undefined
filters are omitted; nullable filters use the literal `null`, booleans use
`true` or `false`, and array filters use repeated query keys rather than
comma-separated values.

For the complete Bundle shape, pagination response, query defaults, and
encoding rules, use the canonical
[Standalone Database server contract](../database-plugins/standalone#server-contract).
The management routes do not authenticate themselves. Protect
`/hot-updater/api/*` with fail-closed authentication before mounting the
handler.
