## Installation

```package-install
npm install @hot-updater/supabase --save-dev
```

## Storage v2

### Node and CLI

```ts
import { env, secret } from "@hot-updater/core/config";
import { supabaseStorage } from "@hot-updater/supabase/storage/node";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: supabaseStorage({
    supabaseUrl: env("SUPABASE_URL"),
    supabaseServiceRoleKey: secret("SUPABASE_SERVICE_ROLE_KEY"),
    bucketName: env("SUPABASE_BUCKET"),
    basePath: "bundles",
    delivery: "signed",
  }),
});
```

`supabaseStorage(config)` returns the direct plugin object. The Node entry
accepts only `target: "node"`.

### Edge and worker runtimes

```ts
import { env, secret } from "@hot-updater/core/config";
import {
  createEdgeStorageContext,
  supabaseStorage,
} from "@hot-updater/supabase/storage/edge";
import { createHotUpdater } from "@hot-updater/server";

type EdgeContext = Readonly<{
  environment: Readonly<Record<string, string | undefined>>;
}>;

export const hotUpdater = createHotUpdater<EdgeContext>({
  database,
  storages: [
    supabaseStorage({
      supabaseUrl: env("SUPABASE_URL"),
      supabaseServiceRoleKey: secret("SUPABASE_SERVICE_ROLE_KEY"),
      bucketName: env("SUPABASE_BUCKET"),
      delivery: "signed",
      signedUrlExpiresIn: 3600,
    }),
  ],
  storageContext: ({ context }) =>
    createEdgeStorageContext({
      target: "edge",
      environment: context?.environment ?? {},
    }),
});
```

The Edge entry accepts `target: "worker"` and `target: "edge"`.

## Configuration

Use either `supabaseServiceRoleKey` or `supabaseAnonKey`. Server-side artifact
writes normally require the service-role key. `delivery` is `"signed"` by
default; `"public"` returns the bucket's public URL.

Literal configuration may reuse its client. Tagged configuration is resolved
against each operation context and creates a request-specific client.

## Capabilities

Both target entries support exact `put`, `head`, `get`, and `delete`,
create-only writes, inclusive ranges, and `issueDownload`. `list` is not
exposed. The persisted URI protocol remains `supabase-storage://`.

## Storage v1 during migration

The root import remains available during the current deprecation window:

```ts
import { supabaseStorage } from "@hot-updater/supabase";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: supabaseStorage({
    supabaseUrl: "https://project.supabase.co",
    supabaseServiceRoleKey: "your-service-role-key",
    bucketName: "hot-updater-bundles",
  }),
});
```

This root import is the v1 universal-profile provider. New integrations should
use the explicit Storage v2 target entry. Upgrade consumers and provider
packages together; existing `supabase-storage://` URIs remain valid. To roll
back, pin the complete pre-v2 package set.
