## Installation

```package-install
npm install @hot-updater/firebase firebase-admin --save-dev
```

## Storage v2

### Node and CLI

```ts
import { env } from "@hot-updater/core/config";
import { firebaseStorage } from "@hot-updater/firebase/storage/node";
import { defineConfig } from "hot-updater";
import { applicationDefault } from "firebase-admin/app";

export default defineConfig({
  storage: firebaseStorage({
    projectId: env("FIREBASE_PROJECT_ID"),
    storageBucket: env("FIREBASE_STORAGE_BUCKET"),
    credential: applicationDefault(),
    basePath: "bundles",
  }),
});
```

`firebaseStorage(config)` returns the direct plugin object. The Node entry
accepts only `target: "node"`.

### Firebase Functions

```ts
import { env } from "@hot-updater/core/config";
import {
  createFunctionsStorageContext,
  firebaseStorage,
} from "@hot-updater/firebase/storage/functions";
import { createHotUpdater } from "@hot-updater/server";
import { applicationDefault } from "firebase-admin/app";

type FunctionsContext = Readonly<{
  environment: Readonly<Record<string, string | undefined>>;
  bindings: Readonly<Record<string, unknown>>;
}>;

export const hotUpdater = createHotUpdater<FunctionsContext>({
  database,
  storages: [
    firebaseStorage({
      projectId: env("FIREBASE_PROJECT_ID"),
      storageBucket: env("FIREBASE_STORAGE_BUCKET"),
      credential: applicationDefault(),
    }),
  ],
  storageContext: ({ context }) =>
    createFunctionsStorageContext({
      environment: context?.environment ?? {},
      bindings: context?.bindings ?? {},
    }),
});
```

The Functions entry accepts only `target: "functions"`.

Set local Admin credentials through the standard environment:

```bash title=".env.hotupdater"
GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json
FIREBASE_PROJECT_ID=your-project-id
FIREBASE_STORAGE_BUCKET=your-bucket-name
```

## Capabilities and lifecycle

Both target entries support exact `put`, `head`, `get`, and `delete`,
create-only writes, inclusive ranges, and `issueDownload`. `list` is not
exposed.

Literal configuration owns one provider client until `onUnmount`.
Configuration containing tagged references resolves and closes an
operation-owned client for each request. Returned streams retain their client
until close, cancellation, or error.

The persisted URI protocol remains `gs://`.

## Storage v1 during migration

The root import remains available during the current deprecation window:

```ts
import { firebaseStorage } from "@hot-updater/firebase";
import { defineConfig } from "hot-updater";
import { applicationDefault } from "firebase-admin/app";

export default defineConfig({
  storage: firebaseStorage({
    projectId: "your-project-id",
    storageBucket: "your-bucket-name",
    credential: applicationDefault(),
  }),
});
```

This root import is the v1 universal-profile provider. New integrations should
use the explicit Storage v2 target entry. Upgrade consumers and provider
packages together; existing `gs://` URIs remain valid. To roll back, pin the
complete pre-v2 package set.
