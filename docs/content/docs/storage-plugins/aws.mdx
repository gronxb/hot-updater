## Installation

```package-install
npm install @hot-updater/aws --save-dev
```

## Storage v2

Import the concrete target entry. `s3Storage(config)` returns the plugin object
directly.

### Node and CLI

```ts
import { env, secret } from "@hot-updater/core/config";
import { s3Storage } from "@hot-updater/aws/storage/node";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: s3Storage({
    region: env("AWS_REGION"),
    bucketName: env("AWS_S3_BUNDLES_BUCKET"),
    credentials: {
      accessKeyId: secret("AWS_ACCESS_KEY_ID"),
      secretAccessKey: secret("AWS_SECRET_ACCESS_KEY"),
    },
    delivery: { type: "presigned", expiresInSeconds: 3600 },
  }),
});
```

If `credentials` is omitted, the AWS SDK default credential chain is used.
S3-compatible services can set `endpoint` and `forcePathStyle`.

### AWS Lambda

```ts
import { env, secret } from "@hot-updater/core/config";
import {
  createLambdaStorageContext,
  s3Storage,
} from "@hot-updater/aws/storage/lambda";
import { createHotUpdater } from "@hot-updater/server";

type LambdaContext = Readonly<{
  environment: Readonly<Record<string, string | undefined>>;
  bindings: Readonly<Record<string, unknown>>;
}>;

export const hotUpdater = createHotUpdater<LambdaContext>({
  database,
  storages: [
    s3Storage({
      region: env("AWS_REGION"),
      bucketName: env("AWS_S3_BUNDLES_BUCKET"),
      credentials: {
        accessKeyId: secret("AWS_ACCESS_KEY_ID"),
        secretAccessKey: secret("AWS_SECRET_ACCESS_KEY"),
      },
      delivery: { type: "presigned" },
    }),
  ],
  storageContext: ({ context }) =>
    createLambdaStorageContext({
      environment: context?.environment ?? {},
      bindings: context?.bindings ?? {},
    }),
});
```

The Node entry accepts only `target: "node"`; the Lambda entry accepts only
`target: "functions"`.

## Configuration

`S3StorageConfig` accepts `bucketName`, `basePath`, `region`, `endpoint`,
`credentials`, `forcePathStyle`, checksum options, retry attempts, and an
optional delivery policy. String and credential fields can use immutable
`env()` or `secret()` references.

The delivery policy is either presigned S3 URLs or CloudFront:

```ts
import { env, secret } from "@hot-updater/core/config";
import { s3Storage } from "@hot-updater/aws/storage/node";

const storage = s3Storage({
  bucketName: env("AWS_S3_BUNDLES_BUCKET"),
  delivery: {
    type: "cloudfront",
    publicBaseUrl: env("CLOUDFRONT_URL"),
    keyPairId: secret("CLOUDFRONT_KEY_PAIR_ID"),
    privateKey: secret("CLOUDFRONT_PRIVATE_KEY"),
  },
});
```

## Capabilities and lifecycle

Both v2 entries support exact `put`, `head`, `get`, and `delete`, create-only
writes, and inclusive ranges. `issueDownload` is exposed when `delivery` is
configured; `list` is not exposed. The plugin owns its S3 clients and releases
them on `onUnmount`; a returned body stream retains its client lease until
close, cancellation, or error.

The persisted URI protocol remains `s3://`.

## Storage v1 during migration

The root import remains available during the current deprecation window:

```ts
import { s3Storage } from "@hot-updater/aws";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: s3Storage({
    region: "us-east-1",
    bucketName: "my-hot-updater-bucket",
  }),
});
```

This is the v1 universal-profile provider. New integrations should use the
explicit Storage v2 target entry. Migrate core, CLI/server consumers, and the
provider package together; stored `s3://` URIs do not need rewriting. To roll
back, pin the complete pre-v2 package set.
