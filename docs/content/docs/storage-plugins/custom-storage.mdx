## Installation

```package-install
npm install @hot-updater/plugin-core @hot-updater/core
```

Install the conformance suite in the package that tests the provider:

```package-install
npm install @hot-updater/test-utils vitest --save-dev
```

## Storage v2 at a glance

A Storage v2 provider accepts its configuration and returns one immutable
plugin object:

```ts
export const myStorage = (config: MyStorageConfig) =>
  createStoragePlugin({
    name: "myStorage",
    protocol: "acme",
    plugin: () => createImplementation(config),
  });
```

Configure that object directly:

```ts
export default defineConfig({
  storage: myStorage({
    bucketName: env("ACME_BUCKET"),
    apiKey: secret("ACME_API_KEY"),
  }),
});
```

`createStoragePlugin` calls `plugin()` while constructing the object. The
returned value is not another factory. Runtime selection also does not belong
inside `createStoragePlugin`; publish a concrete entry for each supported
target and let that entry close over its target-specific implementation.

## Author a provider

The required primitives are `put`, `head`, `get`, and exact-object `delete`.
`issueDownload` and `list` are optional capabilities.

```ts title="myStorage.ts"
import {
  createStoragePlugin,
  StoragePluginError,
  type StorageOperationContext,
  type StoragePluginImplementation,
} from "@hot-updater/plugin-core/storage";
import {
  resolveConfigReference,
  type ConfigReference,
} from "@hot-updater/core/config";

type MyStorageConfig = Readonly<{
  bucketName: string | ConfigReference;
  apiKey: string | ConfigReference;
}>;

type MyStorageClient = Readonly<{
  put(
    key: string,
    body: Uint8Array | ReadableStream<Uint8Array>,
    contentLength: number,
  ): Promise<void>;
  head(key: string): Promise<Readonly<{ contentLength: number }> | null>;
  get(key: string): Promise<Readonly<{
    body: ReadableStream<Uint8Array>;
    contentLength: number;
  }> | null>;
  delete(key: string): Promise<boolean>;
  close(): Promise<void>;
}>;

declare const createClient: (
  apiKey: string,
  context: StorageOperationContext,
) => MyStorageClient;

const objectKey = (storageUri: string, bucketName: string): string => {
  const url = new URL(storageUri);
  if (url.protocol !== "acme:" || url.hostname !== bucketName) {
    throw new StoragePluginError(
      "invalid-uri",
      "The storage URI does not belong to this bucket.",
    );
  }
  return decodeURIComponent(url.pathname.slice(1));
};

const createImplementation = (
  config: MyStorageConfig,
): StoragePluginImplementation => {
  const clients = new Set<MyStorageClient>();
  const acquire = (context: StorageOperationContext) => {
    const apiKey = resolveConfigReference(config.apiKey, context);
    const client = createClient(apiKey, context);
    clients.add(client);
    return client;
  };
  const bucket = (context: StorageOperationContext) =>
    resolveConfigReference(config.bucketName, context);

  return {
    async put(input) {
      const client = acquire(input.context);
      const bucketName = bucket(input.context);
      const key = input.key.replace(/^\/+/u, "");
      await client.put(key, input.body, input.contentLength);
      return {
        kind: "stored",
        storageUri: `acme://${bucketName}/${encodeURIComponent(key)}`,
      };
    },
    async head(input) {
      const client = acquire(input.context);
      const result = await client.head(
        objectKey(input.storageUri, bucket(input.context)),
      );
      return result === null
        ? { kind: "not-found" }
        : {
            kind: "found",
            storageUri: input.storageUri,
            metadata: { contentLength: result.contentLength },
          };
    },
    async get(input) {
      const client = acquire(input.context);
      const result = await client.get(
        objectKey(input.storageUri, bucket(input.context)),
      );
      return result === null
        ? { kind: "not-found" }
        : {
            kind: "found",
            storageUri: input.storageUri,
            body: result.body,
            metadata: { contentLength: result.contentLength },
          };
    },
    async delete(input) {
      const client = acquire(input.context);
      const deleted = await client.delete(
        objectKey(input.storageUri, bucket(input.context)),
      );
      return { kind: deleted ? "deleted" : "not-found" };
    },
    async onUnmount() {
      await Promise.all([...clients].map((client) => client.close()));
    },
  };
};

export const myStorage = (config: MyStorageConfig) =>
  createStoragePlugin({
    name: "myStorage",
    protocol: "acme",
    plugin: () => createImplementation(config),
  });
```

The core boundary validates operation inputs and provider results, preserves an
existing `StoragePluginError`, maps aborts, and freezes the public object.
Providers still own namespace checks, SDK error mapping, and resource cleanup.

## Tagged configuration and operation contexts

Use immutable tagged references when a value must be resolved where an
operation runs:

```ts
import { binding, env, secret } from "@hot-updater/core/config";

const nodePlugin = myStorage({
  bucketName: env("ACME_BUCKET"),
  apiKey: secret("ACME_API_KEY"),
});

const workerPlugin = workerStorage({
  bucket: binding("BUNDLES"),
  bucketName: env("ACME_BUCKET"),
});
```

`env(name)`, `secret(name)`, and `binding(name)` produce frozen data, not live
credentials. A provider resolves them against the `StorageOperationContext`
received by each operation. `binding` is rejected on the `node` target.
Missing values and target mismatches are deterministic errors.

Literal configuration may own and reuse a client. Configuration containing a
tagged reference must be resolved per operation and must not reuse one
request's resolved client in another request.

Create a context with the target helper exported beside the provider:

```ts
import { createNodeStorageContext } from "@hot-updater/plugin-core/storage/node";

const context = createNodeStorageContext({
  environment: {
    ACME_BUCKET: process.env.ACME_BUCKET,
    ACME_API_KEY: process.env.ACME_API_KEY,
  },
});
```

Official providers also export `createLambdaStorageContext`,
`createWorkerStorageContext`, `createFunctionsStorageContext`, or
`createEdgeStorageContext` from their matching target entries.

## Server usage

Pass v2 objects directly to `createHotUpdater`. A server must provide a
`storageContext` resolver when storage operations need request environment or
bindings:

```ts
import { env, secret } from "@hot-updater/core/config";
import { createHotUpdater } from "@hot-updater/server";
import {
  createEdgeStorageContext,
  supabaseStorage,
} from "@hot-updater/supabase/storage/edge";

type RuntimeContext = Readonly<{
  environment: Readonly<Record<string, string | undefined>>;
}>;

export const hotUpdater = createHotUpdater<RuntimeContext>({
  database,
  storages: [
    supabaseStorage({
      supabaseUrl: env("SUPABASE_URL"),
      supabaseServiceRoleKey: secret("SUPABASE_SERVICE_ROLE_KEY"),
      bucketName: env("SUPABASE_BUCKET"),
    }),
  ],
  storageContext: ({ context }) =>
    createEdgeStorageContext({
      target: "edge",
      environment: context?.environment ?? {},
    }),
});
```

The resolver runs at the server boundary for handler and API invocations. It
must return a fresh context with the target accepted by the imported provider
entry. Hot Updater snapshots that context before invoking storage.

## Ownership and disposal

The provider owns resources created by its implementation. Release them from
`onUnmount`; the v2 wrapper makes repeated unmount calls share one cleanup.
Streams returned by `get` must retain any client lease until the stream closes,
is cancelled, or errors.

`loadConfig()` returns a `ConfigResponse` that owns configured storage:

```ts
const config = await loadConfig(options);
const storage = await config.storage(context);

try {
  await storage.profiles.node.upload("bundles/id", archivePath);
} finally {
  await config.disposeStorage();
}
```

`config.storage(context)` returns a borrowed Node compatibility facade. It does
not expose `onUnmount`; callers must not close it. The owning
`ConfigResponse.disposeStorage()` is idempotent and rejects later attempts to
borrow storage.

## Results, errors, and capabilities

Required operations return tagged outcomes:

- `put`: `stored` or `already-exists`
- `head` and `get`: `found` or `not-found`
- `delete`: `deleted` or `not-found`
- `issueDownload`: `issued`
- `list`: an object list and optional cursor

Use `StoragePluginError` with one of the public codes:
`invalid-input`, `invalid-uri`, `unsupported`, `unauthorized`, `forbidden`,
`rate-limited`, `aborted`, `timeout`, `integrity`, or `provider`.

Omit an optional method when it is unsupported. Normalized consumers report
the exact `unsupported` error when they require an omitted capability. If a
required primitive cannot serve a particular request, keep the method and
reject that request with `StoragePluginError("unsupported", ...)`.

All first-party Storage v2 target entries support exact `put`, `head`, `get`,
and `delete`, create-only writes, and inclusive byte ranges. Their
`issueDownload` capability is documented on each provider page. Prefix delete
is not part of v2.

## Conformance suite

Register the public suite against a fresh plugin for every test:

```ts title="myStorage.spec.ts"
import { createNodeStorageContext } from "@hot-updater/plugin-core/storage/node";
import { setupStoragePluginTestSuite } from "@hot-updater/test-utils";

setupStoragePluginTestSuite({
  name: "myStorage",
  context: createNodeStorageContext({ environment: {} }),
  createPlugin: () =>
    myStorage({
      bucketName: "test-bucket",
      apiKey: "test-key",
    }),
});
```

The suite covers byte and stream round trips, historical URIs, concurrent
contexts, bounded backpressure, create-only behavior, ranges and metadata,
not-found outcomes, exact idempotent delete, cancellation, URI validation,
optional capabilities, and idempotent unmount.

## Migration and compatibility

| Situation                                 | Supported behavior                              | Action                                                                                                                     |
| ----------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| v1 provider factory with a new consumer   | Supported during the current deprecation window | Keep the configured v1 factory only while migrating; no removal release is committed yet.                                  |
| v2 direct object with a new consumer      | Canonical                                       | Pass `provider(config)` directly to `storage` or `storages`.                                                               |
| v2 object wrapped in another function     | Rejected with `v2-factory`                      | Remove the extra function.                                                                                                 |
| Existing persisted provider URIs          | Preserved                                       | Keep the provider protocol and exact object-key interpretation stable.                                                     |
| Target-specific runtime                   | Supported only through its matching export      | Import the explicit `/storage/node`, `/storage/worker`, `/storage/functions`, `/storage/lambda`, or `/storage/edge` entry. |
| Unsupported target or optional capability | Rejected deterministically                      | Select a supported target entry or omit the feature that needs the capability.                                             |
| Rollback                                  | Package-set rollback only                       | Pin the same pre-v2 versions of core, consumers, and every provider; do not rewrite stored URIs.                           |

The v1 and v2 contracts can coexist in the new consumer during the deprecation
window, but one configured storage value must use one contract. Upgrade core,
the consumer, and official providers together.

This Storage v2 release does not include a Nitro-based Console template,
Console deployment, or deploy-anywhere support. Those are separate future
work.
