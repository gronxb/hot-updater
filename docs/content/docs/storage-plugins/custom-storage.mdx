## Installation

```package-install
npm install @hot-updater/plugin-core --save-dev
```

## Contract

`createStoragePlugin` defines one flat, runtime-independent contract. The core
interface does not know about local file paths, Node.js, Workers, provider SDKs,
bindings, credentials, or request context. A provider captures those details
when it creates the plugin.

```typescript
import { createStoragePlugin } from "@hot-updater/plugin-core";

export const customStorage = createStoragePlugin({
  name: "customStorage",
  protocol: "custom",

  async put({ key, body, contentType }) {
    const objectKey = key;
    await client.put(objectKey, body, { contentType });
    return { storageUri: `custom://bucket/${objectKey}` };
  },

  async get({ storageUri }) {
    const object = await client.get(parseStorageUri(storageUri));
    return {
      response:
        object === null
          ? null
          : new Response(object.body, {
              headers: { "content-type": object.contentType },
            }),
    };
  },

  async getDownloadUrl({ storageUri }) {
    return { url: await client.createDownloadUrl(storageUri) };
  },

  async exists({ storageUri }) {
    return { exists: await client.exists(parseStorageUri(storageUri)) };
  },

  async delete({ storageUri }) {
    await client.delete(parseStorageUri(storageUri));
    return { storageUri };
  },
});
```

The full interface is:

```typescript
interface StoragePlugin {
  readonly name: string;
  readonly protocol: string;

  readonly put?: (input: {
    readonly key: string;
    readonly body: Uint8Array;
    readonly contentType: string;
  }) => Promise<{ readonly storageUri: string }>;

  readonly get?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly response: Response | null }>;

  readonly getDownloadUrl?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly url: string }>;

  readonly exists?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly exists: boolean }>;

  readonly delete?: (input: {
    readonly storageUri: string;
  }) => Promise<{ readonly storageUri: string }>;
}
```

Operations are optional because a runtime-specific implementation may support
only the capabilities its consumer needs. Hot Updater validates required
operations at each boundary and reports the missing operation by name.
Every operation receives one input object and returns one result object so new
fields can be added without introducing positional parameters or changing the
result shape.

| Consumer | Required operations |
| --- | --- |
| `hot-updater deploy` | `put`, `get`, `exists`, `delete` |
| `hot-updater patch` and promote-copy | `get`, `put`, `delete` |
| Console server mutations | `get`, `put`, `delete` |
| `createHotUpdater({ storage })` update responses | `getDownloadUrl` |
| `createHotUpdater({ storage })` download handling | `get` |

`delete` always deletes exactly one object. Prefix or bucket cleanup is an
administrative provider operation and is intentionally outside this contract.

## Configuration and runtime implementations

Pass plugin objects directly; there is no plugin factory thunk or runtime
profile:

```typescript
// hot-updater.config.ts: deploy-time provider client
import { r2Storage } from "@hot-updater/cloudflare";

export default defineConfig({
  storage: r2Storage({
    accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
    bucketName: process.env.CLOUDFLARE_R2_BUCKET_NAME!,
    credentials: {
      accessKeyId: process.env.CLOUDFLARE_R2_ACCESS_KEY_ID!,
      secretAccessKey: process.env.CLOUDFLARE_R2_SECRET_ACCESS_KEY!,
    },
  }),
});
```

The same public name can be exported from a runtime subpath with a different
implementation. For example, the Cloudflare Worker version captures an R2
binding instead of Node.js credentials:

```typescript
import { createHotUpdater } from "@hot-updater/server";
import { d1Database, r2Storage } from "@hot-updater/cloudflare/worker";
import { env } from "cloudflare:workers";

const hotUpdater = createHotUpdater({
  database: d1Database(env.DB),
  storage: [
    r2Storage({
      bucket: env.BUCKET,
      bucketName: env.BUCKET_NAME,
      downloadUrlSigningKey: env.STORAGE_DOWNLOAD_URL_SIGNING_KEY,
    }),
  ],
});
```

`getDownloadUrl` is the storage plugin's public URL boundary. A provider can
return its CDN URL, a provider-signed URL, or a signed URL handled by the same
server. The contract exposes only the resulting URL; the delivery mechanism is
an implementation detail. For example, AWS passes
`cloudFrontDownloadUrl(...)` to `s3Storage`, while a private R2 Worker returns a
signed handler-relative URL.

## File-system consumers

The core contract carries bytes and Web responses, not paths. CLI code is
responsible for reading a local file before `put` and materializing a `Response`
returned by `get`. Provider plugins should not add file-system operations back
to the public contract.
