## Installation

```package-install
npm install @hot-updater/cloudflare --save-dev
```

## Storage v2

Use the entry that matches the runtime. Both functions return a direct plugin
object.

### Node and CLI

```ts
import { env, secret } from "@hot-updater/core/config";
import { r2Storage } from "@hot-updater/cloudflare/storage/node";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: r2Storage({
    accountId: env("CLOUDFLARE_ACCOUNT_ID"),
    bucketName: env("R2_BUCKET"),
    credentials: {
      accessKeyId: secret("R2_ACCESS_KEY_ID"),
      secretAccessKey: secret("R2_SECRET_ACCESS_KEY"),
    },
    publicBaseUrl: env("R2_PUBLIC_BASE_URL"),
  }),
});
```

The Node entry uses R2's S3-compatible API and accepts only `target: "node"`.

### Cloudflare Worker

```ts
import { binding, env, secret } from "@hot-updater/core/config";
import {
  createWorkerStorageContext,
  r2Storage,
} from "@hot-updater/cloudflare/storage/worker";
import { createHotUpdater } from "@hot-updater/server";

type WorkerBindings = Readonly<{
  BUNDLES: R2Bucket;
}>;

type WorkerContext = Readonly<{
  environment: Readonly<Record<string, string | undefined>>;
  bindings: WorkerBindings;
}>;

declare const runtimeBindings: WorkerBindings;

export const hotUpdater = createHotUpdater<WorkerContext>({
  database,
  storages: [
    r2Storage({
      bucket: binding("BUNDLES"),
      bucketName: env("R2_BUCKET"),
      publicBaseUrl: env("R2_PUBLIC_BASE_URL"),
      jwtSecret: secret("R2_DOWNLOAD_JWT_SECRET"),
    }),
  ],
  storageContext: ({ context }) =>
    createWorkerStorageContext({
      environment: context?.environment ?? {},
      bindings: context?.bindings ?? runtimeBindings,
    }),
});
```

The Worker entry accepts only `target: "worker"`. A tagged bucket reference is
resolved from the operation context on every request.

## Capabilities and lifecycle

Both target entries support exact `put`, `head`, `get`, and `delete`,
create-only writes, and inclusive ranges. The Node entry exposes
`issueDownload`; the Worker entry exposes it when `publicBaseUrl` is
configured. `list` is not exposed.

The Node plugin owns its S3 clients and keeps a lease through returned streams.
The Worker binding is borrowed and is never closed by the plugin.

The persisted URI protocol remains `r2://`.

## Storage v1 during migration

The root import is the v1 universal-profile provider and remains available
during the current deprecation window:

```ts
import { r2Storage } from "@hot-updater/cloudflare";
import { defineConfig } from "hot-updater";

export default defineConfig({
  storage: r2Storage({
    accountId: "your-account-id",
    bucketName: "my-r2-bucket",
    credentials: {
      accessKeyId: "your-r2-access-key-id",
      secretAccessKey: "your-r2-secret-access-key",
    },
  }),
});
```

Existing Wrangler-based v1 configuration is deprecated within that window.
New integrations should use a Storage v2 target entry. Migrate the package set
together; stored `r2://` URIs remain valid. To roll back, pin the complete
pre-v2 package set.
