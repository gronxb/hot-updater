## Background HTTP capability diagnostic

receive `that.lynx.fetch` as a lexical `fetch` parameter. The native C++
`AddModuleWrapForJsContent` argument list also includes `fetch` in
`core/runtime/js/bindings/js_app.cc:84`. The release `lynx_core.js` assigns
`AbortController` to its actual global object, and `lynx.fetch` invokes
`NativeModules.LynxFetchModule.fetch`. These source contracts do not establish
that each host registered a functioning network service.

The public SDK HTTP client uses lexical `fetch` and `AbortController`.
Consequently, the earlier SDK1 `globalThis.fetch` diagnostic alone is insufficient
to determine compatibility. New `http` fixtures report lexical `fetch`,

perform a real fetch with an AbortController signal to
`http://127.0.0.1:18791/health`, bounded to five seconds. The returned HTTP status
and body, or actual failure, remain visible in the final UI and console output.
No globals, HTTP implementation or native response are substituted.
