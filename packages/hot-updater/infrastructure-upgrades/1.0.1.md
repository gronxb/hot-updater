# 1.0.1

## Compatibility

This upgrade keeps the v1 data model and client protocol. Follow the 1.0.0
cutover first for v0 infrastructure. Existing v1 AWS tables require metadata
index projections; Firebase installations require the new composite indexes.
Roll out the matching database plugins and server together. Older Standalone
servers do not provide `/bundles/:id/patch-children` and must be upgraded before
using Console child counts. A custom repository may implement
`bundlePatches.findByBaseBundleIds`; absence produces an explicit error and never
triggers a bundle-history scan.

## Steps

1. Extract the target server scaffold and preserve local configuration and secrets.
2. Prepare the provider indexes below before routing requests to the new runtime.
3. Deploy the runtime and verify filtered pagination, missing IDs, bundle patch
   hydration, child counts, release edits and Insights.

No request path automatically scans metadata to backfill an absent index or
count projection. Such requests fail with an upgrade/repair error. Channel/API
key lists, exact aggregate counts, scoped relation reads and explicit migration
jobs may read their requested complete result set; there is no hidden history
limit or partial-success response.

## Cloudflare

Apply the appended `0002_remove_unused_fingerprint_index.sql` migration to remove

unchanged. Existing D1 primary keys, scope and patch base/owner indexes support
the queries. Redeploy the extracted Worker to add the Standalone reverse patch
endpoint. No table or schema-version change is required.

## Supabase

Apply `20260922000000_remove_unused_fingerprint_index.sql` to remove
`hot_updater_v1_releases_fingerprint_hash_idx`. Existing scope and patch indexes
remain in use. Redeploy the extracted server for the new admin endpoint. No table
or schema-version change is required.

## AWS

No table or GSI replacement is required. Keep the existing patch-owner GSI.
The runtime maintains primary-table projections for bundle platform, patch base,
and release bundle/channel/platform/enabled/app-version filters in the same
transaction as canonical metadata. Projection writes count toward DynamoDB's
100-action transaction limit; split independent bulk operations if necessary.

For an existing v1 table, stop all metadata writers, including older CLI and
server processes. Run the following once from the app with its established
private AWS credentials and the target `@hot-updater/aws` package installed:

```js
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient } from "@aws-sdk/lib-dynamodb";
import { migrateDynamoDBMetadataIndexes } from "@hot-updater/aws/iac";

const client = DynamoDBDocumentClient.from(new DynamoDBClient({}));
await migrateDynamoDBMetadataIndexes({
  client,
  tableName: process.env.HOT_UPDATER_DYNAMODB_TABLE_NAME,
});
```

Use the already configured table name and region; do not copy credentials into
source or chat. This explicit maintenance job visits every canonical metadata
page, writes projections, repairs bundle/patch totals, then writes the
`_hot-updater / metadata-indexes` version-1 marker. It does not visit Insights
history or S3 objects. If it fails, keep writers stopped and retry; the marker
is never written before completion. A new empty table initializes automatically.
Never manually mark an existing populated table as upgraded. Resume writes only
with the target plugin/server; older writers do not maintain these projections.

## Firebase

Merge the scaffold's `firestore.indexes.json` with the deployed configuration,
preserving unrelated indexes. Deploy with `firebase deploy --only
firestore:indexes` and wait until all indexes are ready before deploying the
Function. The template includes platform/id bundle indexes, owner/base patch
indexes, both cursor directions for supported Release filter combinations,
scope/id reads and API-key list ordering. No document backfill or adapter-marker
change is required. Unsupported predicates fail instead of loading a collection.

## Verification

- Fetch a missing bundle, catalog and API-key hash; check that unrelated metadata
  collections/partitions are not read.
- List a filtered bundle page and a Release page in both cursor directions.
  On AWS, inspect key conditions to confirm the appropriate metadata projection.
- Hydrate a page with more than 30 patch owners on Firebase; verify no owners are
  lost and that the SDK's disjunction limit does not trigger a history scan.
- Replace patches, check child counts, then delete their base and verify cascades.
- Update an existing Release and verify its catalog and filtered list agree.
- Verify Insights aggregates and event pagination independently. Overview queries
  do not reconstruct metrics from raw event history or impose a 50,000-event cap.

Standalone clients require the updated server; SQL/ORM adapters need no new
table or schema-version migration. Prisma and MongoDB retain sorting and
pagination in the backend, and MongoDB uses native predicates for indexed
finite-ID queries.

For existing native PostgreSQL and ORM installations, remove only the retired
`releases_fingerprint_hash_idx`: fingerprint Release lookup now uses `scope_key`.
Generated Prisma/Drizzle schemas and fresh schemas omit it. Apply the generated
ORM index migration, or use the appropriate statement below through the existing
database connection. The schema marker remains `1.0.0`; `db migrate` treats an
existing v1 schema as current, so it does not perform this optional index cleanup.

```sql
-- PostgreSQL / SQLite
DROP INDEX IF EXISTS releases_fingerprint_hash_idx;
-- MySQL
DROP INDEX releases_fingerprint_hash_idx ON releases;
-- CockroachDB
DROP INDEX IF EXISTS releases@releases_fingerprint_hash_idx;
```

For MongoDB, check `db.releases.getIndexes()` and drop the named index with
`db.releases.dropIndex("releases_fingerprint_hash_idx")` if present. Retain the
scope, patch owner/base, installation history, latest-event and overview indexes;
they still serve runtime queries. Retain the Firestore Release filter/cursor
composites as well: range pagination must not depend on equality-index merging.
