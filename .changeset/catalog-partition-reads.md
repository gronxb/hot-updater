feat(server): read partitioned release catalogs through the head and one covering partition. Nothing writes partitions yet, and nothing turns partitioning on: until a later 1.2.0 change does, every scope stays compact and reads exactly as before, with no read of `release_catalog_partitions` and no MongoDB snapshot.

- **The row says its layout.** A scope's `release_catalogs` row is either today's compact catalog or a head naming its live epoch. Readers branch on that row and never read a setting.
- **The update check.** For a head, the server reads the row covering the device's version: one descending limit-1 read of `release_catalog_partitions`. It accepts the row only from the head's epoch, at or below its generation, and covering the version. On MongoDB the head is read again with the row in one snapshot, and the answer comes from that snapshot's row, whatever its layout. A gap row answers 200 with the head's generation and empty lists. A missing, newer or corrupt row is read again three times, then answered 503 `private, no-store` with `CATALOG_SNAPSHOT_CONFLICT`. It is never the no-catalog 404, and never an empty catalog.
- **The memo.** The 5-second per-scope memo is still the only cache. It holds a miss, a compact row, or a head with the rows verified under it, in 128 slots that count rows. Row loads are keyed by head identity, so a row never attaches to a head that expired or was replaced while it loaded. A scope with no catalog is now remembered for the same 5 seconds, the way a CDN already keeps its 404. A miss takes a free slot or replaces the oldest miss, and never evicts a cached catalog. A failed read is not cached.
- **Public rows stay compact.** `getReleaseCatalogRow`, `listReleaseCatalogs`, `CoreReads`, the admin `GET /release-catalogs` routes and `standaloneCore` return a partitioned scope assembled into today's compact payload, with the head's `catalog_id`, generation and `catalog_hash`. The hash is never computed again. Patch bases read only the rows their range covers. Each page and each patch-base union comes from one snapshot on MongoDB, or from rows checked against the head's generation with no hole elsewhere. `ready()` reads one raw catalog row and never assembles one.
- **plugin-core.** `Engine.core` gains `snapshot(read)` and `snapshots`, `SnapshotDatabase` and `SnapshotReads`: core's reads through the adapter's `readSnapshot`, or direct reads where the adapter has none. The tiling kit gains `parseReleaseCatalogPartition`, which parses a stored row once into its span and answers.
- **test-utils.** `createReleaseCatalogPartitionFixture` converts a compact scope in place, keeping every identity column, and writes heads, rows and compact rows the way a partitioning writer would. The read-budget suite pins the partitioned check, patch bases and assembled row on every backend, with the extra snapshot read where the adapter has `readSnapshot`. `startHttpTestServer` returns its `baseUrl`. The oracle's `probeAppVersions`, `deviceStates`, `cohortClasses` and `decideReleaseCatalog` are exported.
