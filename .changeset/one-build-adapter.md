New `@hot-updater/one` package for [One](https://onestack.dev) apps:
- `one()` build adapter: bundles with `react-native bundle`, which One routes through its own bundler, always compiles with Hermes, and writes to `node_modules/.hot-updater/build` so One's files in `dist/` stay out of the update. Before native builds it runs `one prebuild`, and it reads the config plugin's `publicKeyPath` from `vite.config.ts` for signing and fingerprints.
- `@hot-updater/one` config plugin for `native.app.plugins`, for One versions that run config plugins in `one prebuild`. It applies the same native changes, channel, fingerprint and public key as the Expo plugin.

The Expo config plugin's source moved to a private workspace package that `@hot-updater/expo` and `@hot-updater/one` both bundle into their `app.plugin.js`. `@hot-updater/expo` usage does not change.

`init` and `init --build` offer One, and `doctor --fix`, `channel set`, `keys` and `fingerprint create` treat a One app's `ios/` and `android/` as generated by prebuild, like an Expo CNG project's.
