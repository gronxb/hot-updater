Sign in with your Apple Account to issue the App Store Connect API key. An iOS build that needs a key for `signing.ascApiKey` or `--upload testflight` and finds none asks for the Apple Account, its password (masked), and the two-factor code in Hot Updater's own prompts in a terminal, issues a team key named `hot-updater <date>` with the Admin role through asc, the open-source App Store Connect CLI, stores it through the config's `secrets` adapter, or in an owner-only file when the adapter can't store it, and continues; `hot-updater secrets issue asc-api-key [name]` does the same ahead of time, the only command that signs in before a build. It keeps a key the adapter or the environment already provides, printing where it is and its key ID; `--replace` issues a new key, stores it, and names the old key ID with where to revoke it in App Store Connect, never revoking it itself, since CI may still use it. `hot-updater secrets put` only imports a key you have (`--p8`, `--key-id`, `--issuer-id`) and points to `secrets issue` without them. Builds and `secrets issue` without a terminal or in CI never sign in: builds use the stored key and refuse with the `secrets issue` command when there is none. Only the issued key is kept: asc's session, config, and the `.p8` live in a temporary directory that is deleted, and a key the adapter surely did not store is revoked again.
