The Console manages the vault: a Vault page, shown when `console.config.ts` lists `vault()` over the database, adds, overwrites, and deletes secrets from their files and fields, and issues read tokens and lists and revokes vault tokens. Values are write-only: the page shows each secret's name, kind, version, update time, and non-secret metadata such as a key ID or a keystore's alias, and never a value. A new token shows once, with the `HOT_UPDATER_CONSOLE_URL` and `HOT_UPDATER_VAULT_TOKEN` lines CI sets. Without `HOT_UPDATER_VAULT_MASTER_KEY` the page shows the vault as locked instead of failing on save. `hotUpdater.api.vault.status()` reports whether the vault holds a usable master key: set, well formed, and the one the stored secrets were sealed with, which it checks by opening the first live secret's value (one page of secrets and one version, none without a key); `put({ expectedVersion })` and `remove({ expectedVersion })` check the version a caller saw in their transaction (0 for a new name) and throw `VaultConflictError` when it no longer holds, so concurrent adds, overwrites, and deletes never replace or remove a version the caller didn't see, or revive a removed secret; and `parseVaultSecretValue(kind, value)` and `vaultSecretMetadata(kind, value)` define each kind's value: `asc-api-key` `{ p8, keyId, issuerId }`, `android-keystore` `{ keystore, storePassword, keyAlias, keyPassword }`, `play-service-account` `{ serviceAccount }`, `bundle-signing-key` `{ privateKey }`, with files in base64, and environment variables by name for `deploy-credentials` and `generic`.
