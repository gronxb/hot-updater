Add a native Hot Updater API for brownfield apps, which start React Native from an existing native app and check for updates before it starts. It mirrors the JavaScript API: `HotUpdaterInstance(HotUpdaterOptions(...))` on iOS and `HotUpdater.init(context, HotUpdaterOptions(...))` on Android are the counterparts of `HotUpdater.init`, with `checkForUpdate(HotUpdaterCheckOptions(...))`, the update's `updateBundle(onProgress:)`, `resetChannel()`, and `getChannel()`, `getBundleId()`, and the other getters. A check's headers merge over the instance's and its timeout falls back to the instance's, as in JavaScript. Native `checkForUpdate` throws when the check fails, where JavaScript returns `null`; a failed request or response still reaches plugins as `onUpdateError`, and a check that cannot start, such as one with no app version or for another channel while the runtime channel is switched, only throws, as JavaScript only passes it to `onError`. `bundleURL()` (iOS) and `getJSBundleFile()` (Android) give the bundle React Native starts with: an update that `updateBundle` stages before it is read applies at this launch, and a later one at the next launch. A native download asks for the URLs of only the files it downloads (artifact protocol 2), with the check's headers and timeout, and falls back to protocol 1 on a server that predates it, as JavaScript does. On iOS, `HotUpdaterOptions(bundle:)` names the framework bundle that holds the embedded bundle and the `HOT_UPDATER_*` keys. On both platforms, `HotUpdaterOptions` take `channel`, `fingerprintHash`, and `publicKey`, which replace the embedded values. A channel reset, from JavaScript or native code, waits for a native check or download in progress, which would otherwise save its channel again. A native check settles what the previous launch left before it reads the selection, rolling back a bundle that crashed or never finished launching as the launch would, and keeps the launch's `RECOVERED` report. The brownfield guide now checks for updates before React Native starts. A native app updates one React Native bundle, whose instance uses the same server as its `HotUpdater.init`. The next `HotUpdater.init` reports the native checks' `onUpdateCheck`, `onBundleDownloaded`, `onUpdateError`, and `onHttpResponse` events to its plugins, before the launch's `onAppReady`, including an `UNCHANGED` check when nothing was found or the running bundle adopted a newer Release, as JavaScript's check reports it, with the time each happened as `occurredAt`; events of an earlier native build, such as before an app upgrade, are dropped, and Insights dates a replayed download or failure by that time.
