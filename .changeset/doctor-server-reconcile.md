`hot-updater doctor` names the command that upgrades a managed deployment's database and server together, and `--fix` no longer migrates a database ahead of the server that reads it. A server of an earlier release answers 503 once its database is migrated, and a server of the new release answers 503 until it is. When `.env.hotupdater` records the provider `hot-updater init` ran and the config still names that provider's database, `SCHEMA_MIGRATION_PENDING` and an outdated server both name `npx hot-updater init --provider <provider> --from-env-file .env.hotupdater`, which applies the migration and redeploys the Worker, Edge Function, Lambda@Edge function with its IAM policy, Cloud Function, Vercel Function, or Function App back to back. `--fix` skips that migration, saying why in `waitsForServer`, unless `--server-base-url` shows the server already at the required release; for a server of your own, it skips while `--server-base-url` shows that server at an earlier release. An outdated server of your own names `hot-updater db migrate` and `db generate`, and doctor prints the reason beside the commands. The 1.2.0 upgrade file and the managed guides describe the same order.
